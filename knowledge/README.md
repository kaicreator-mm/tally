# 已验证的修复

```
knowledge/
  a3f9c2e1.../
    fix.md          做了什么改动、为什么(人读)
    repro.sh        复现命令
    verified.json   验证时间、版本组合、四道闸记录、修复内容(机器读)
    STALE.md        老化标记(如果标过:可能过期,命中时降级成线索)
```

目录名是**精确指纹**。模糊指纹不在这里建目录 —— 它只用于召回线索,不关联修复。

## 存什么

`(指纹, 复现命令, 已验证修复 + 验证时的版本组合)`

入库路径只有一条:四道闸验证通过后由系统写入(git commit)。界面上没有编辑入口(铁律 2)。

## 不存什么

LLM 的分析过程 · 故障描述 · 复盘文章 · 没通过验证的结论

一个装满未验证结论的知识库,看起来和真经验一模一样,但你以后查到它会信它。而这是自用工具,没有客户会来纠正你。

## 老化

每条修复记着验证时的版本组合。查到时比对当前组合,对不上(或标了 `STALE.md`)→ 标 stale,降级成线索,不直接用。记录保留,不删。
