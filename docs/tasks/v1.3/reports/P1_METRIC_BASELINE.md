## 1. Scope and threshold policy

This baseline is generated by `internal/measurement/report.go` (`BuildBaselineReport`), a pure
read-side assembler over recorded measurement facts. P1 **records baseline distributions; it does
not evaluate product value or readiness** (Decision Lock 16; PRD §25.4 places readiness gates in
P2; §36.3 explicitly does not preset held-out/strong-evidence ratio thresholds or compare Tally to
a bare agent). Accordingly:

- The report contains **no readiness, value, or superiority thresholds** of any kind.
- The single constant `MinSufficientSamples = 2` is a **presentation-sufficiency rule only**
  (task AC4): a readout with fewer observed samples is marked `Sufficient=false` and must be
  presented as "insufficient" — never as `0`, never as "pass", and never used for comparison.
  It judges nothing about Tally's performance.

Vocabulary notes:

- The vocabularies for authoring mode, visibility, and independence requirement are byte-identical
  to the `internal/verification` domain enums; mapping from frozen contracts and verification
  reports into `TaskBaseline` is the caller's responsibility (`internal/measurement` stays a leaf
  package and does not import the verification stack).
- `error_weak` is an explicit extension bucket: PRD §38.5 does not list it, but §8.3.1 defines
  `error` as a weak baseline class, and dropping observed evidence classes from a distribution is
  less faithful than carrying an extra fact bucket.
- Information-level independence gaps are attributed per §8.5 (source and information independence
  must hold on the *same* evidence): if some applicable evidence is effectively
  source-independent but the acceptance is still uncovered, the gap is an information gap;
  otherwise it is a source gap.
- Missing data is never backfilled: an unobserved vocabulary entry appears with an explicit `0`
  count, and the section is marked insufficient (AC4).
