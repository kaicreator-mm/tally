# P0-13 — Project identity validation at failure/environment/deploy ingest boundaries

| Field | Value |
| --- | --- |
| Phase | `P0` |
| Kind | `integration` |
| Wave | `W03` |
| Complexity | `M` |
| Depends on | P0-08, P0-09 |

## Goal

Reject new machine facts for unknown project IDs using the derived project registry, without turning PostgreSQL into the author source.

## Source facts

- Current facts carry free-form project_id.
- exec/ingest are centralized machine-fact creation boundaries.

## PRD references

- §33.3 Derived Index
- INV-FACT-01

## Allowed paths

- `internal/ingest/ingest.go`
- `internal/ingest/ingest_integration_test.go`
- `internal/exec/exec.go`
- `internal/exec/exec_integration_test.go`

## Forbidden / ownership boundary

- `All paths not listed in Allowed paths`

Do not redesign adjacent modules. If a required edit is outside Allowed paths, return `BLOCKED` and name the exact path/interface needed.

## Acceptance criteria

1. Known project fact ingest still works.
2. Unknown project ingest is rejected before fact INSERT.
3. Registry failure is fail-closed for new facts.
4. No existing fact row is mutated.

## Required validation

- `go test ./internal/ingest/... ./internal/exec/...`
- `go test -tags=integration ./internal/ingest/... ./internal/exec/...`

Never claim a validation command passed unless it was actually executed. Environment/tooling absence must be reported as `NOT_RUN(<reason>)`.

## Implementation notes

- If exec.go conflict with P0-20 occurs, integrator merges P0-13 first and P0-20 resolves only handler registration.
