# K03 — 详细设计与代码实现（Detailed Design & Implementation）

> **内容阶段**：DETAILED_KNOWLEDGE_DESIGN / SOURCE_CANDIDATE / NOT_QUALIFIED。版本 [v2.1.2 #521](https://github.com/kaicreator-mm/tally/issues/521)，模块 [#524](https://github.com/kaicreator-mm/tally/issues/524)；[总索引](README.md)。**ADS 是真实 Agent 开发实验和规范来源，Tally 是选用这些知识的软件工程 Domain App**。本文是解释、方法与案例候选，不因写成文档而成为已批准的规则、真实测试结论或生产 Domain Package。

## 1. 能力目标、适用范围与非目标

把已确定的 L1 要求与 L2 接口变成能独立交付的具体代码：明确算法/数据结构、状态转移、错误语义、并发和代码维护质量，并在一个受控写集内完成实际实现与必要测试，而不是只写出“看似合理”的代码片段。

**典型触发**：已经有合法实现 Task/合同，涉及复杂状态、边界、异步、文件与持久化等变更；简单原子补丁可以直接用现有 Task Pack，无需额外设计文档。

**输出的工程价值**：减少错误实现、代码扩张和逻辑漏洞；使另一个 Reviewer 能从具体状态与测试直接核实设计是否落实。

**不包含**：不新造第四个 Task DAG，不建立独立的代码逆向分析专项，不强制每个函数都有设计文档。另外，本版本不设“代码库理解与逆向分析”和“安全与供应链”两个独立知识专项；实际任务中原本适用的源代码定位、权限、敏感信息与安全底线不因之被豁免。

## 2. 领域概念与边界

| 概念 | 精确定义及判断要点 | 常见误用 |
| --- | --- | --- |
| **Task-level Contract** | 从 L1/L2 得到的具体输入/输出、前置/后置、错误、允许代码范围 | 仅用 Issue 标题作为实现合同 |
| **Invariant / State Transition** | 改变状态时必须保持的约束和合法事件序列 | 只考虑成功路径，忽视部分失败 |
| **Algorithm / Complexity** | 为当前规模选择的数据结构及复杂度/内存/时间成本 | 将理论最优误认成总成本最低 |
| **Concurrency / Idempotency** | 处理并行、重复、迟到、超时或重试时保持语义正确 | 增加 retry 循环便自称可靠 |
| **Error Contract** | 可行动错误分类、因果信息、恢复/取消/重试能力 | 吞掉异常或只报“失败” |
| **Code Ownership / Write Set** | 当前 Task 合法可变更路径和共享文件边界 | 两个 Writer 修改同一生成物 |
| **Definition of Done** | 实际行为、构建/测试/集成和 Review 证据完整性 | 代码提交或 CI 绿灯等同交付完成 |
| **Source Currentness** | 实现/测试/Review 对应的准确版本和依赖状态 | 用旧的测试结果证明新 HEAD |

不同概念之间通过具体的来源/适用性/决策/消费者连接，不必为每一个词建立全新的数据库表。只有在真实 Tally 任务中被调用且能够改善工程判断时，才有必要形成可选的结构化资产。

## 3. 专业知识：方法、权衡与失败模式

### 3.1 从设计合同形成代码设计切片

先列必要模块接口、数据流、状态/错误约束与受影响的行为测试。代码细节应限制在当前 Task 负责的职责：函数边界、输入校验、返回类型、持久化/缓存更新、取消恢复等。共享模块接口若未冻结则由实际 L2/Task Owner 确定，不能由不同 Builder 私下改协议。

### 3.2 数据结构和算法以问题为导向

根据实际操作（按 ID 查找、区间查询、流式处理、顺序/批量插入）选 Map/Set/数组/树/索引或数据库约束。评价不仅看渐近复杂度，也看数据规模、内存、序列化、可读性和项目生态。一张小配置表不需要通用索引框架；大规模数据处理则不能忽略无界内存增长。

### 3.3 状态机与错误路径

用事件、前置状态、允许转移、拒绝原因及副作用形成状态表。对于每次操作明确提交点和结果：已成功、已失败、可能执行但未确认（UNKNOWN）。禁止在网络超时之后盲目重复不可幂等的支付/删除类操作，除非有已设计的幂等性或确认机制。

### 3.4 并发、超时与生命周期

明确哪些对象是共享可变状态、线程/异步任务可能如何交错、是否有锁/事务/CAS/队列顺序保证。取消信号需传播并回收资源；重试必须限定次数、间隔、类别与总截止时间；资源释放即使在异常时也发生。没有并发需求的模块不必引入通用调度器。

### 3.5 异常处理、日志与代码可维护性

日志要让使用者理解哪个操作、什么原因、下一步如何解决，同时避免无意义噪声和敏感数据泄露。错误应按业务拒绝、输入非法、临时外部错误、内部缺陷区分；代码注释解释不显然的设计原因、数据不变量和外部契约，而不是复述一行赋值。接口/错误消息应与实际首次启动配置策略一致。

### 3.6 实现质量与模块结构

优先保持高内聚和单一写入职责，不为两行重复代码就引入过度抽象，也不把所有逻辑塞进大型通用类。若项目多子模块，已有合法 monorepo 结构可保留模块所有权、统一工具链和共享包边界。新增 API/配置/测试必须遵循项目原本的兼容性与构建要求。

### 3.7 Builder 的证据与增量验证

先核实 Task 合法写集与来源版本，实施源码+必要测试；按实际技术栈选择语法/类型/format/build 检查及受影响行为测试。输出命令、退出码、目标 SHA 和失败日志；存在失败就修复或交付明确阻塞，而不能把没有执行的测试写成 PASS。Local/CI/Host/Release 资格分别保留。

## 4. 可复用 Decision Procedures（决策程序）

每个程序是能由 Agent 实行的**有界决策步骤**，不是另一个 Workflow Engine。任何输出必须保留实际证据与 UNKNOWN，不得自行授予 Product/L2 Freeze、Task Claim、Review 或 Release。

### DP-K03-01 · Task 详细设计生成

**输入：** Task 目标、L1/L2 pinned 源、目标接口、工作树及允许写集

**执行：**
1. 列出触发、输入输出、前置条件、边界和合法修改模块。
2. 为重要业务对象标注不变量、状态转换与重复/失败行为。
3. 挑选最简单能正确满足规模/契约的数据结构或算法，列替代方案缺点。
4. 将各类错误映射到可行动响应与必要日志，同时设计正确测试 Oracle。
5. 输出最小实现切片与集成 seam；与现有设计冲突时返回 L2 而不擅改。

**输出：** 实现设计小包：接口/状态/算法/错误/测试与写集

**停止与升级：** Task 授权或核心接口缺失则不开始非法写入；无需材料的简单任务允许 INLINE。

### DP-K03-02 · 异步/并发行为检查

**输入：** Task 中的异步执行/共享状态/外部调用与失败合同

**执行：**
1. 识别共享可变对象、可能重复的请求与不可逆副作用。
2. 写出正常、重复、超时、取消和部分失败转移表。
3. 依据事务/CAS/幂等/幂等键/重试限定选择最小机制。
4. 检查资源释放、最终状态回读和 UNKNOWN 证据。

**输出：** 并发与错误语义设计及对应负例

**停止与升级：** 没有实际风险则不加分布式锁和复杂重试；保证缺失时交还设计 Owner。

### DP-K03-03 · 实现和受影响测试

**输入：** 合法当前代码版本、详细设计、可执行环境和现有测试定位

**执行：**
1. 基于允许路径完成源码和契约/行为测试，避免修改无关文件。
2. 选择项目当前有效的语法/类型/构建/受影响测试命令，实际确认被执行的测试。
3. 根据首个失败原因做一次有界源码修复并重新运行受影响检查。
4. 将当前源/测试/日志绑定到 exact HEAD，形成候选而非提前声明正式 PASS。

**输出：** 源码候选、测试收据、公开接口变更说明与遗留 UNKNOWN

**停止与升级：** 改动需要超出写集或外部权限时停止越权并向原 owner 汇报。

## 5. Tally Workflow 消费契约

**消费阶段：** L3 Implementation Task DAG-I；使用 Tally 已有 Engineering Business、Task/Attempt 与 Agent/Host 事实源，新增的仅是领域知识与程序的调用关系。

| 环节 | 需要从上游获得 | 该模块实际提供 | 必须保留的判断 |
| --- | --- | --- | --- |
| 任务准入 | 当前合法 Task/写集/L2/来源 | 具体设计切片与局部测试计划 | 合法 Claim/FSW 仍由原有权威持有 |
| 实施 | 稳定接口与使用者 | 代码、错误处理、必要测试 | 不擅扩 Product/Architecture Scope |
| 验证 | 当前 workspace/命令和实际结果 | 语法/类型/构建/受影响行为收据 | 没有执行 = NOT_RUN |
| 集成交付 | 可审查 exact HEAD/真实项目入口 | 受控候选给 Review/Integration | Builder 声明不是 Release PASS |

**跨层交接/复用：** K04 负责 DAG-I 分解和共享写冲突，K05 提供规范测试设计与真实测试证据，K06 对失败进行根因修复，K07 的多 Agent 交接确保同一接口版本与 Review 来源。

## 6. Agent Skills 与任务输入输出

### SK-K03-01 · Detailed Design Slice

- **何时调用**：Task 存在多个重要实现决策或故障路径
- **最小输入**：准确需求、架构、源码/技术栈和明确写集
- **输出结构**：接口/算法/状态/异常/并发、局部正反测试与集成条件
- **自检**：可让另一 Builder 独立实现而不会对核心状态的 Owner 产生歧义
- **禁止的捷径**：对已冻结设计自行重新定义业务规则

### SK-K03-02 · Bounded Code Builder

- **何时调用**：Task 已具有合法执行上下文和所需环境
- **最小输入**：Task Pack、允许写集、真实基础版本与设计/测试
- **输出结构**：合法代码+测试、执行结果、SHA/命令/错误日志、尚未覆盖行为
- **自检**：语法/类型检查、受影响测试是真实执行且覆盖当前目标
- **禁止的捷径**：靠未运行测试、伪造 Test PASS 或隐藏失败完成任务

### SK-K03-03 · Error & Logging Designer

- **何时调用**：对外错误和故障诊断属于本 Task 的行为合同
- **最小输入**：用户角色、错误分类、运行类型与敏感数据约束
- **输出结构**：错误分类表、可操作消息、必要相关 ID 与日志级别
- **自检**：用户能判断下一步动作；同一异常不会泄露令牌或敏感内容
- **禁止的捷径**：把堆栈打印量当作诊断质量

## 7. 贯穿案例：正例、变体与反例

以下为**教学/设计情景**，不是宣称 ADS/Tally 已经执行或验证过的真实项目记录。实际资格认证必须替换为来源可核查的真实 Issue、源码版本、测试/Review/Host 收据。

**场景**：实现“批量处理工作项”，允许用户取消其中部分操作；同一请求可能因客户端超时被重试。

**正确处理路径：**
1. 根据批准合同确认每项工作可独立成功/失败，明确定义整个批次的部分成功表示与状态变更条件。
2. 选择批次大小限制、结果列表/错误格式与原子性边界，考虑一次性数据库事务与逐项更新的成本差异。
3. 为重复请求标出请求 ID 或可重试语义，防止重复造成额外副作用；明确 UNKNOWN 如何回读。
4. 在合法写集内实现状态检查、持久化、异常处理和资源释放，并记录可行动日志。
5. 编写成功、失败、取消、超时和重复请求测试，运行项目真实受影响命令并绑定当前 HEAD。

**成功的可观察标准：** 相同请求重复不会额外改变合法已处理业务状态；部分失败/超时有明确可观察语义；实际测试覆盖被执行的入口。

**错误处理路径与后果：** 使用全局可变数组表示批次进度，网络出错后无条件重做所有工作；错误仅输出“processing failed”；没有执行测试就声称完成。

**情景变体与边界：** 若业务要求整批原子性，必须调整状态/事务合同；如果已有接口不能表达部分成功，应由 L2 确认兼容性方案。

## 8. 反例库：哪些情况不能据此推断成功

1. **写代码替代设计**：重要状态与错误合同未清楚就直接开始多个 Agent 并发编码
2. **无限框架化**：简单同步逻辑导入抽象调度、重试、事件总线三套基础设施
3. **不可观测错误**：吞掉异常导致用户和维护者无法识别原因
4. **伪验证**：本地命令未实际运行、测试未发现或使用旧 SHA 便宣称完成
5. **跨写集修复**：发现上游接口不够就修改其他任务的冻结源码，无合法接纳

## 9. 训练题与验证矩阵（后续可转换为 Cases / Validation）

| 任务/情景 | Agent 期望判断 | 错误或危险结果 | 最小证据 |
| --- | --- | --- | --- |
| 简单一行空值修复 | INLINE 设计并运行相关回归 | 长篇新框架设计 | 真实 Task/受影响测试 |
| 重复请求导致多次写入 | 检查幂等键或状态前置条件 | 仅增加无限重试 | 重复调用负例 |
| 异步任务超时 | 区分失败与未知，保留回读 | 超时直接标成功 | Host/状态持久化证据 |
| 公开接口有新错误码 | 与 L2 合同及测试一致 | 任意变更旧行为 | 已确认接口版本 |
| 仅有 Builder 日志 | 报 SOURCE_CANDIDATE，等待权威验证 | 把本地 stdout 当 Task PASS | 命令/exit code/exact SHA |

**不完整证据的表示**：缺少用户业务决定、来源版本、真实调用结果或正式环境时，记录 `UNKNOWN / NOT_RUN / BLOCKED`，并写明下一项最小可验证事实。案例/模拟结果不能冒充真实 Agent 开发效果。
