## 9. 训练题与验证矩阵（后续可转换为 Cases / Validation）

| 任务/情景 | Agent 期望判断 | 错误或危险结果 | 最小证据 |
| --- | --- | --- | --- |
| 仅需一个简单同步读接口 | 保留已有模块结构，INLINE L2 | 因为有 L2 就强制多服务 | 现行 L1/已验证 L2 |
| 异步作业需要重启恢复 | 设计持久状态和明确写入 Owner | 仅用进程内 Map 宣称 durable | 具体恢复/失败要求 |
| 多个 Agent 并行 API/UI | 合同和异常码先明确 | 各自定义不同字段且无集成 seam | 冻结接口/Task 契约 |
| 队列 Demo 只测吞吐 | 限定结论适用面 | Demo PASS → 正式 Release PASS | 实验输入/指标/未测场景 |
| L2 与 Product 范围冲突 | 交 Product Authority 修订 | 擅自删除用户验收要求 | 来源版本和影响报告 |

**不完整证据的表示**：缺少用户业务决定、来源版本、真实调用结果或正式环境时，记录 `UNKNOWN / NOT_RUN / BLOCKED`，并写明下一项最小可验证事实。案例/模拟结果不能冒充真实 Agent 开发效果。

## 针对边界的对抗变体

- **NEG-K02-01**：在“异步导入队列”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K02-02**：在“离线桌面应用”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K02-03**：在“多个 Agent 共建公共 API”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。

## 最小实测计划（非已完成声明）

1. 固定当前 Task、可读来源、验证环境、质量基线与适用原有 Review/Validation 规则。
2. 执行直接 Agent 基线与选用此模块特定 Decision Procedure/Skill 的受控任务对照；避免在两组之间改变上下游 Product/L2 事实。
3. 让独立 Reviewer 按实际需求/设计/测试结果核实准确性、遗漏、回归、修复轮次和必要环境成本。
4. 报告已执行命令/Host/代码 SHA 与 `NOT_RUN/UNKNOWN`，保留负面结果，不能以知识问答分数代替真实开发结果。
5. 只有源主张、适用条件、独立验证和真实消费者都合格，才可能进入后续有权 Package 选用；本知识库仍 `NOT_QUALIFIED`。
