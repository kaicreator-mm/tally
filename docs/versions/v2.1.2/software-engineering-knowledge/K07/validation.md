## 9. 面向真实 Tally Consumer 的验证矩阵

以下均是后续可转换为 Validation 的**预设案例**，不是已跑通过的工具/Host 结果。

| 情景 | 正确行为 | 禁止结论 | 需要的实际证据 |
| --- | --- | --- | --- |
| 同机 IPC 结果成功返回 | 只认消息成功和工件引用 | 自动 Task PASS | IPC 消息/Task 事实对照 |
| Builder 和 Reviewer 同账号不同会话 | 核查实际工作/审查独立证据 | 仅凭账号相同拒绝或批准 | 两方审查来源和候选 SHA |
| 两个 Agent 写同一 generated file | 单 Writer/真实串行 | 无冲突直接并行 | 写集和实际文件控制 |
| HTTP 任务重复投递 | 幂等对账当前 Task/Attempt | 重复执行不可逆 Effect | 相关 ID、Host 状态回读 |
| 旧 HEAD 工件迟到 | 拒绝或重绑定并验证 | 用旧结果覆盖新任务 | source/attempt/current HEAD |

验收应绑定当前 Source/Task/Attempt、实际消费者和适用环境；真实测试未执行时必须保留 `NOT_RUN/UNKNOWN`。不要以知识目录完整、算法讲解正确或一次模型问答得分代替真实开发任务的质量。

## 实验如何证明“知识确实有用”

1. 固定任务目标、允许的源/Host、受影响质量标准与成功/失败 Oracle；记录投入/运行环境。
2. 只比较同等条件下的直接 Agent 与选用本模块相应知识/Skill 的 Agent，不能改动数据来源或给一组更多真实权限。
3. 根据实际结果比较用户接受、缺陷/回归、正确测试/故障定位、审查返工、修复尝试与成本；保留失败和负收益。
4. 没有真实执行收据时标 `NOT_RUN`，缺独立资格则标 `NOT_QUALIFIED`；不用小样本问答成绩代替真实源码/用户路径。
5. Tally 未来只有经过所需来源/权利/反例/消费者验证和原权威采纳，才能选用合格知识资产。
