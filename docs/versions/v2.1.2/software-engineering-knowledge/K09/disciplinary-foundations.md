## 学科机制、决策产物与错误泛化

每项知识都对当前真实软件工程任务的某个决策有用，包含受支持来源、适用范围与可证伪反例。来自外部标准/研究/企业实践的**知识方法不是现行 ADS 的新 MUST**；只有实际生效的 ADS 版本和合法项目规则承担强约束。

### F-K09-01 · 维护是软件生命周期的持续工程而非次要阶段

**学科观点与适用机制：** SWEBOK Maintenance 和 ISO/IEC/IEEE 12207:2026 将持续变更、运行支持、退役纳入生命周期。改 Bug、增加功能、重构内部结构、迁移数据以及停用旧版本具有不同权威和兼容性义务；不能把改变公开行为叫做纯重构。

**Agent 应产出的结果：** 先对变更类型与受支持用户/版本作事实识别，再确定需要当前 Product/L2/Task 的哪类修订。

**必须排除的假结论：** 删除旧接口只因‘架构更好’，之后用新测试替换旧业务要求。

**外部出处：** [A01](../external-source-catalog.md)、[A04](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K09-02 · 演进式数据库设计与兼容窗口

**学科观点与适用机制：** Martin Fowler Evolutionary Database Design 讲解数据库/应用逐步演进的实践。数据模式变更需要同时考虑旧消费者、实际存储数据、读写兼容、回填、部分失败、不可逆清理和恢复；`down migration` 不是适用所有变更的万能回滚。

**Agent 应产出的结果：** 为当前已存在数据/客户端确定 upgrade/rollback/compensation 的实际可观察不变量。

**必须排除的假结论：** 一次 fresh install 建表成功便宣布升级和灾后恢复全都通过。

**外部出处：** [A35](../external-source-catalog.md)、[A04](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K09-03 · 保留行为的 Oracle 与设计变化隔离

**学科观点与适用机制：** Google Software Engineering at Google/企业工程实践强调长期维护成本与测试。Refactor 与 Feature 应当分层：纯结构改善需证明既有公共入口行为不变，需求变化需真实新 Acceptance。如果旧快照不再符合已接受业务，应分析原因而不是机械更新 Golden。

**Agent 应产出的结果：** 列旧行为/新行为/受权变化/不变约束及相应合同测试，实施尽量小步。

**必须排除的假结论：** 大规模重写后只验证新端点，忽略旧用户仍在调用的接口。

**外部出处：** [A41](../external-source-catalog.md)、[A23](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K09-04 · 系统生命周期视角与上下游约束

**学科观点与适用机制：** SEBoK 通过系统全生命周期与相关学科补充复杂服务/多组件升级考虑。实际软件可能涉及后台服务、桌面客户端、数据存储、离线用户、同步状态或分批部署；选择兼容策略前要知道这些组件的实际更新频率和失败恢复边界。

**Agent 应产出的结果：** 在当前实际支持版本范围内画消费者/数据版本矩阵；不要按想象构造没有需求的十年兼容承诺。

**必须排除的假结论：** 所有历史版本强制永久兼容或在没有用户授权的情况下立即破坏兼容。

**外部出处：** [A03](../external-source-catalog.md)、[A42](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K09-05 · 技术债是具有证据的经济选择

**学科观点与适用机制：** 技术债的合理处理优先依据变更频率、缺陷复发、测试/CI 开销、用户影响和未来迁移阻力，而非对代码‘不够优雅’的审美。要比较局部修复、重构、暂缓及替换的维护成本，并向 K11 提供真实/估计数据。

**Agent 应产出的结果：** 记录债务成因、当前痛点/成本、备选方案、受影响用户与停止条件；没有边际收益时不启动无界重构。

**必须排除的假结论：** 因 Agent Token 空闲就让其扫描重写整个旧仓，扩大核心任务范围。

**外部出处：** [A01](../external-source-catalog.md)、[A41](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

## 从学科知识到真实任务的选择方式

1. 确认当前 Product/Task/版本/角色/运行环境，并判断是否真的需要当前模块的学科知识。没有实际问题时不批量加载本模块或组织额外治理。
2. 在上述 F-K09 项中选择能改变该决策的一项，核对外部引用的当前版本与适用边界；知识来自教材/企业研究不意味着本项目必须照搬。
3. 调用 [engineering-methods.md](engineering-methods.md) 的相应 DP，生成明确输入、输出、真实反例和停止条件。
4. 仅对实际受权 Task 执行源码/测试/Host；不能取得的证据记 `UNKNOWN/NOT_RUN`，并保留本知识库尚未 Source/Package Qualified 的现状。

**暂缓领域**：代码库逆向分析和独立软件安全/供应链知识专项仍不建设；原本适用的基础源码读取、权限和保密约束有效。
