## 9. 有界训练与未来验证场景

这是一组供知识审查与后续消费者验证的**设计案例**，没有被标为实际 Host/Agent/CI PASS。

| 情境 | 期望工程行为 | 被禁止的判断 | 真正需要的证据 |
| --- | --- | --- | --- |
| 桌面应用首次启动无配置 | 可以访问安全配置入口，业务动作被阻止 | 系统直接崩溃或进行未授权操作 | 真实首次运行流程 |
| 后台服务配置错误 | 清晰日志和可诊断错误 | 必须弹 UI 才可启动 | 服务模式与错误输出 |
| 请求超时但可能已提交 | 保留 UNKNOWN/查询并有界重试 | 重新执行不可逆副作用 | Host 状态/幂等性试验 |
| 一次性能优化无基线 | 标 NOT_MEASURED | 报告 3 倍提升 | 真实 profiling/对照数据 |
| 恢复后影响仍未验证 | 记录 RECOVERED ≠ VERIFIED | 把先前故障覆盖为 PASS | 事件时间线和验证收据 |

实际效用评估应先冻结测试任务、预算和验收标准，再比较直接 Agent 与选用本知识后的 Tally Agent 在真实软件开发中的需求实现、回归、修复、返工、耗时及成本。不允许以题库问答效果代替实际源码和用户行为，也不得虚构定量提升。

**模块交接边界：** K10 仅提供适用的运行错误/恢复/性能知识，K03 负责 Task 内的代码实现，K06 负责真实故障根因；这三层不建立相互竞争的硬性 Rule。

## 实验如何证明“知识确实有用”

1. 固定任务目标、允许的源/Host、受影响质量标准与成功/失败 Oracle；记录投入/运行环境。
2. 只比较同等条件下的直接 Agent 与选用本模块相应知识/Skill 的 Agent，不能改动数据来源或给一组更多真实权限。
3. 根据实际结果比较用户接受、缺陷/回归、正确测试/故障定位、审查返工、修复尝试与成本；保留失败和负收益。
4. 没有真实执行收据时标 `NOT_RUN`，缺独立资格则标 `NOT_QUALIFIED`；不用小样本问答成绩代替真实源码/用户路径。
5. Tally 未来只有经过所需来源/权利/反例/消费者验证和原权威采纳，才能选用合格知识资产。
