## 学科机制、决策产物与错误泛化

每项知识都对当前真实软件工程任务的某个决策有用，包含受支持来源、适用范围与可证伪反例。来自外部标准/研究/企业实践的**知识方法不是现行 ADS 的新 MUST**；只有实际生效的 ADS 版本和合法项目规则承担强约束。

### F-K10-01 · 质量属性需有可观察的业务场景

**学科观点与适用机制：** ISO/IEC 25010:2023 给出九大产品质量特征，ISO 25023 提供质量测量方向。运行质量应从当前实际系统关切开始：用户可恢复性、请求延迟、错误诊断和资源/可靠性，而不是给每个小型 CLI 引入全套指标、SLO 或分布式追踪。

**Agent 应产出的结果：** 为实际场景给出事件、运行环境、响应与真正可测量的指标；未定义指标时写 UNKNOWN/NOT_MEASURED。

**必须排除的假结论：** 凭经验声称提升 3 倍延迟或必须达到某个从未批准的 SLA。

**外部出处：** [A07](../external-source-catalog.md)、[A11](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K10-02 · 可操作日志与监控的用途

**学科观点与适用机制：** Google SRE Books 讨论监控、服务目标、事故响应与恢复；OpenTelemetry 解释日志/指标/链路等不同信号的作用。关键是用户或运维者知道操作影响、失败原因和可追溯相关 ID，而不是强制每个项目安装大型 Observability 服务。

**Agent 应产出的结果：** 选择适合 CLI/桌面/UI/后台服务的错误输出与技术日志，避免 secrets/敏感请求在日志里泄露。

**必须排除的假结论：** 堆栈和 DEBUG 输出越多就当作诊断质量越好。

**外部出处：** [A31](../external-source-catalog.md)、[A36](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K10-03 · 超时、重试、取消与未知副作用

**学科观点与适用机制：** AWS Builders' Library 说明 API 幂等和安全重试设计；一次超时只意味着调用者未获确认，不能推定远端未执行。只有在当前合同确认幂等或可以读回实际状态时才进行有界重试，针对确定性失败应直接停止而非加大重试。

**Agent 应产出的结果：** 明确 idempotency token/commit point、重试次数/截止、取消语义和 UNKNOWN 状态读回。

**必须排除的假结论：** 超时→立即创建重复业务操作、重试无限循环或报告已成功。

**外部出处：** [A32](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K10-04 · 故障恢复与历史证据不可相互替代

**学科观点与适用机制：** SRE 的事故生命周期包含检测/缓解/恢复/验证和后续改善。服务恢复上线不等于先前每个失败 Task 已被重新验证，也不能用新的好结果去覆盖原始错误日志；不可恢复或权限缺失时保留原 Incident 与残余 UNKNOWN。

**Agent 应产出的结果：** 生成 Incident timeline 和恢复/验证两个分离的收据、真实业务影响与后续行动。

**必须排除的假结论：** 系统重启后就把全部历史 pipeline/red event 改写 PASS。

**外部出处：** [A31](../external-source-catalog.md)、[A33](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

### F-K10-05 · 性能实验必须控制变因

**学科观点与适用机制：** 性能指标不是单个延迟采样：工作负载、平台、缓存状态、基线/候选版本、测量误差和业务正确性要可比较。学科度量侧重为信息需求选择实际措施，多个指标的取舍也要回 K11 分析成本和真实用户收益。

**Agent 应产出的结果：** 固定数据规模/负载/环境测量前后变化，失败或无基线时保持 NOT_MEASURED；功能回归与性能改善分别记录。

**必须排除的假结论：** 不同硬件与数据集前后对比便声称优化成功。

**外部出处：** [A10](../external-source-catalog.md)、[A31](../external-source-catalog.md)、[A33](../external-source-catalog.md)；请以来源总目录的版本和出版方链接核查全文/许可证。

## 从学科知识到真实任务的选择方式

1. 确认当前 Product/Task/版本/角色/运行环境，并判断是否真的需要当前模块的学科知识。没有实际问题时不批量加载本模块或组织额外治理。
2. 在上述 F-K10 项中选择能改变该决策的一项，核对外部引用的当前版本与适用边界；知识来自教材/企业研究不意味着本项目必须照搬。
3. 调用 [engineering-methods.md](engineering-methods.md) 的相应 DP，生成明确输入、输出、真实反例和停止条件。
4. 仅对实际受权 Task 执行源码/测试/Host；不能取得的证据记 `UNKNOWN/NOT_RUN`，并保留本知识库尚未 Source/Package Qualified 的现状。

**暂缓领域**：代码库逆向分析和独立软件安全/供应链知识专项仍不建设；原本适用的基础源码读取、权限和保密约束有效。
