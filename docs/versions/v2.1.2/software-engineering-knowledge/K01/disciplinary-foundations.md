# K01 · 需求工程与业务建模：外部学科知识基础

> [K01 知识库](README.md) · [v2.1.2 #521](https://github.com/kaicreator-mm/tally/issues/521) · [外部来源总目录](../external-source-catalog.md)。**EXTERNAL_DISCIPLINARY_SOURCE_CANDIDATE / NOT_SOURCE_QUALIFIED / NOT_CONNECTED**；独立原创方法总结，非 ISO/IEEE/书籍原文转录，不授予 Tally Package/Host/Task 资格。

## 从学科依据到可供 Agent 使用的知识

本文件**不是来源链接堆积**。对每个主题分别描述：工程学科中的核心问题/机制、在 Tally 的适用决策、典型不当推断，以及可追溯的 Axx 原始来源。适用任务优先使用已经有权的 ADS v4.19.0 规范；外部知识只提出更准确的概念/可选择的方法，**不自动增加 MUST/Gate**。

### F-K01-01 · 业务分析与软件需求的分界

**知识解释：** IIBA 的 Need、Context、Stakeholder、Change、Solution、Value 六种核心概念启发 Agent 区分用户希望达成的业务效果和具体软件功能。用户提出“导出 PDF”不等于 PDF 是唯一解决方案；先明确哪些人要交付什么、可接受何种证据，再确认交付媒介是否有强制性要求。

**Agent 在实际工程任务中应产出：** 输出 Stakeholder→Need→Value→Candidate solution 的独立关系，不把方案预设成需求；当产品来源已确认 PDF 则不重复挑战。

**必须避免的错误泛化：** 将 Agent 偏好的功能界面写成已批准 Product 要求。

**参考来源：** [A12](../external-source-catalog.md)；出版方原文链接和版本见总目录，知识合格性需另行确认。

### F-K01-02 · 需求生命周期与业务规则有效范围

**知识解释：** ISO/IEC/IEEE 29148:2018 涵盖需求活动和必需信息项，IREB 提供需求获取/记录/验证的学习体系。Tally 在当前需求中只选择必要活动：来源确定、冲突比较、用例/状态分析、可观察验收。需求是版本化决定，不是永恒且跨用户群体适用的定理。

**Agent 在实际工程任务中应产出：** 对每条 Requirement 记录原文/版本/适用角色/当前 Owner 与验收方式；不能取得有权决议则 UNKNOWN。

**必须避免的错误泛化：** 将 2018 标准原文未核查条文直接转化 Tally MUST，或由需求研究代签 Product Freeze。

**参考来源：** [A05](../external-source-catalog.md)、[A11](../external-source-catalog.md)；出版方原文链接和版本见总目录，知识合格性需另行确认。

### F-K01-03 · 功能要求与质量场景的结合

**知识解释：** SWEBOK 与 ISO 25010 将功能与质量属性区别对待。性能目标不是“尽量快”，而是给出操作、负载、观测指标和必要的量化依据。可用性/可靠性/恢复能力可能改变架构，但只有实际相关并被接受时才构成设计约束。

**Agent 在实际工程任务中应产出：** 给出情景+刺激+响应+环境+测量/验证来源，无真实数字时明确设计候选和需要采样的 UNKNOWN。

**必须避免的错误泛化：** 擅自承诺 99.99% 可用性或为每个 CLI 小功能制定企业 SLO。

**参考来源：** [A01](../external-source-catalog.md)、[A07](../external-source-catalog.md)、[A16](../external-source-catalog.md)；出版方原文链接和版本见总目录，知识合格性需另行确认。

### F-K01-04 · 需求中的角色、状态与不变量

**知识解释：** 业务对象/状态模型必须区分“谁发起”“当前在什么状态”“执行后必须保持什么性质”“非法行为应呈现什么”。将权限/可见性、状态转移和外部副作用分别作为可测试条件，避免一个按钮就等于完整的业务规则。

**Agent 在实际工程任务中应产出：** 创建角色×状态×动作→允许/禁止/UNKNOWN 矩阵；每个高影响不变量配一条禁止情况与证据来源。

**必须避免的错误泛化：** 从行业通用习惯自创业务政策，或所有角色共享同一状态规则。

**参考来源：** [A01](../external-source-catalog.md)、[A11](../external-source-catalog.md)、[A12](../external-source-catalog.md)；出版方原文链接和版本见总目录，知识合格性需另行确认。

### F-K01-05 · 冲突消解与最小澄清

**知识解释：** 要求冲突可能来自版本差异、不同利益相关者、相互矛盾的目标或证据时效。分析者先检查差异是否能由适用条件解释，再提出真正必须交给有权者的少量问题，按影响下游设计/测试的程度排序。

**Agent 在实际工程任务中应产出：** 输出 source A/B、角色/时间范围、冲突严重度、两个业务选项和未获授权的停止点；其他无争议部分可继续。

**必须避免的错误泛化：** 为避免用户等待直接任选一种政策，或为任何微小缺失启动全量需求工作图。

**参考来源：** [A05](../external-source-catalog.md)、[A11](../external-source-catalog.md)、[A12](../external-source-catalog.md)；出版方原文链接和版本见总目录，知识合格性需另行确认。

## 从知识到 Tally Workflow 的最小决策

| 任务当前问题 | 合适的调用顺序 | 对结果的最低判断 |
| --- | --- | --- |
| 实际源/需求尚未明确 | 先确认当前 Product/Task/ADS 版本，再选最少的 F-K01 知识 | 保留 UNKNOWN，不根据教材里的示例假设作真实业务决定 |
| 已有正确合同，需要一个工程方法 | 从 [engineering-methods.md](engineering-methods.md) 选一条 DP，并结合上面适用条件 | 输出可被代码/测试/用户行为证伪的方法，而非一本教科书摘要 |
| 真实构建/测试/Host 未运行 | 在 [validation.md](validation.md) 区分设计候选与真实执行证据 | 明确 NOT_RUN/NOT_QUALIFIED，不拿来源权威冒充 Task PASS |

**专门保留的限制**：用户要求暂缓代码库逆向分析和软件安全/供应链知识专门建设；国际标准的覆盖面可能包含这些学科，但本模块只提取当前软件开发的必要内容。
