## 一、角色的“意见”“亲历观察”和“制定规则的权力”是三个不同维度

两个人给出相反陈述时，**意见数量、职级、能看到的日志、制定政策的权限**都不能混成一个真值分数。应从五个坐标比较每条陈述：
`(speaker identity, role & authority scope, claim type, applicability interval, evidence and observation method)`。
例如支持专员报告“昨日有三笔异常取消”，这是事件观察；订单策略 Owner 规定“今日起 PACKING 不允许用户自行取消”，是规范性业务声明；客服所见的三个订单无法直接制定未来规范，Owner 的规范决定也不能单独证明昨日哪三笔支付确实完成。

**Authority precedence 是有条件的**：某负责人对“特定产品线取消规则”有权，不代表其能为另一 Tenant、另一个法律适用区或旧合约期作出同样决定。即使一个项目允许 Owner 最终裁定，也应查当前被授权的具体范围，而不是采用“总是最新消息优先”。

## 二、最小可复核的冲突案例

教学输入：
- S1（2026-10-01 版本手册）：“PAID 或 PACKING 状态可由普通用户撤销订单”；
- S2（客服访谈记录）：“我们最近不允许 PACKING 取消”；
- S3（拟发布策略说明）：“从 2026-11-01 起，适用于 Tenant B 的 PACKING 用户请求拒绝；PAID 可申请”；
- X（日志）：“Tenant A 在 2026-11-05 接受了一次 PACKING 撤销”。

问题不是“谁写得最新”，而是分别识别：S3 是否**确已由有权者批准且已生效**、其范围是否 Tenant B、S1 对其他租户是否仍有效、X 中的“接受”是 UI 成功提示还是服务端/数据库真正 Commit。S2 访谈可以提示存在版本/沟通缺陷，却不能自行替代 S1/S3。

| 待判断命题 | 直接来源候选 | 独立最小反驳 | 可能输出 |
| --- | --- | --- | --- |
| Tenant B 2026-11-05 PACKING 不能撤销 | S3 授权文档+生效证据 | S3 仍为草案或生效日未到 | `ASK_POLICY_OWNER`，不代签业务规则 |
| Tenant A 同日 PACKING 仍允许 | S1及继承关系 | Tenant A 有另一生效的局部覆盖 | 只出分支结论，不能泛化全租户 |
| X 证明扣款已撤销 | 真实交易/状态日志 | UI 200、远端退款 Effect 仍 UNKNOWN | `UNKNOWN_EXTERNAL_EFFECT` |

即便查询日志能复现 X，“发生过”不等于“符合最新有权规则”；反之，观察不到某类请求也不证明政策禁止它。

## 三、三角核验不是三个 URL 投票

三角核验指**跨独立观察机制降低共同偏差**，而非只要三个来源都同意就叫证实。假设三个博客都转述了同一条未标日期的产品帖子，来源数为 3，但独立信息源实际上可能只有 1 个。需要至少识别：
1. **规范来源**：批准文档、具体生效时间、作用范围和正式版本；
2. **事件来源**：有可核实身份的真实交易/日志，区分请求、执行、ACK 与持久状态；
3. **利益相关者来源**：访谈样本、谁有条件观察什么、样本选择/回忆偏差；
4. **可证伪交叉检验**：选择会使这些来源给出相反预测的样本而非重复搜索相同关键词。

典型错误：客服、实施工程师、销售均说“以前允许退款”，因此把过去的观察覆盖现在有权财务政策。相反，如果有权规则尚不存在，也不应靠三角核验“创造”一个规则；缺失必须 ASK/UNKNOWN。

## 四、从材料冲突到最小工程动作

对于真实 Agent 要处理的 Goal，K01 最多能提出：
- 目前已证实的 **Fact**（证据来源、适用身份和版本）；
- 仍是 **Hypothesis** 的政策、因果解释或观察偏差；
- 必须有权 Actor 决定的 **Normative Rule**；
- 可仅靠只读资料核实的**最小问题**与不会造成外部 Effect 的验证设计；
- 当前可继续处理的无冲突工作与需要暂停的敏感业务动作。

如果 S3 仍为 Draft，可先设计同时覆盖两种政策的可参数化决策逻辑/单元假设，但在 Rule Owner 批准前不能合并为正式生产 Policy。查询 Source/版本远比无意义生成十个调查 Issue 更有效。K07 承担角色和流程证据，K02 负责接口/边界设计，K05 负责独立 Oracle。

## 五、来源适用性与反证训练

相关公开学科背景：[A05 ISO 29148](../external-source-catalog.md) 需求过程、[A12 IREB](../external-source-catalog.md) 需求调查与验证、[A13 IIBA](../external-source-catalog.md) Stakeholder/Value、[A65 NASA 双向追溯](../external-source-catalog.md)（NASA 适用场景，**非 Tally 必执行审批**）。这些条目作为出版方参考，不代表某真实业务政策已获得资格。

**演算问题**：给定两个相反的客服陈述、一份仍待签发的 Owner 文档和一次远端支付超时，写出哪些事实可以报告、哪个问题需要 ASK、哪个业务 Effect 必须保持 UNKNOWN，以及哪一份来源能真正改变合法决议。正确答案不应按来源数量、消息最后到达或语言模型的自信程度进行投票。

**STOP**：真实规范来源无法确认时不能替用户制定业务/资金规则；已经获得合格政策的无关实现和学科研究可继续。
