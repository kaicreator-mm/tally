## 9. 训练题与验证矩阵（后续可转换为 Cases / Validation）

| 任务/情景 | Agent 期望判断 | 错误或危险结果 | 最小证据 |
| --- | --- | --- | --- |
| 模糊“可批量撤销”需求 | 识别角色/适用状态/部分失败策略未知 | 假设全部记录可删且永久成功 | 用户原话+具体状态与操作源 |
| 两角色对取消权限不同 | 将角色条件映射为规则和负例 | 无条件向所有角色展示/允许取消 | 批准的角色/权限规范 |
| 旧版本规则冲突 | 标注版本差异及权威裁决 | 覆盖旧决定不留痕 | 两版本来源与有效区间 |
| 简单文案修改 | L1 INLINE，少量验收即可 | 创建 6 个研究 Issue | 当前任务范围及明确需求 |
| 研究完成但无 Product 批准 | 提交待裁决项而非 Freeze | 以 Reviewer PASS 代 Product Freeze | 真实 Product Authority 收据 |

**不完整证据的表示**：缺少用户业务决定、来源版本、真实调用结果或正式环境时，记录 `UNKNOWN / NOT_RUN / BLOCKED`，并写明下一项最小可验证事实。案例/模拟结果不能冒充真实 Agent 开发效果。

## 针对边界的对抗变体

- **NEG-K01-01**：在“重复取消请求”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K01-02**：在“权限分层”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K01-03**：在“部分退款”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。

## 最小实测计划（非已完成声明）

1. 固定当前 Task、可读来源、验证环境、质量基线与适用原有 Review/Validation 规则。
2. 执行直接 Agent 基线与选用此模块特定 Decision Procedure/Skill 的受控任务对照；避免在两组之间改变上下游 Product/L2 事实。
3. 让独立 Reviewer 按实际需求/设计/测试结果核实准确性、遗漏、回归、修复轮次和必要环境成本。
4. 报告已执行命令/Host/代码 SHA 与 `NOT_RUN/UNKNOWN`，保留负面结果，不能以知识问答分数代替真实开发结果。
5. 只有源主张、适用条件、独立验证和真实消费者都合格，才可能进入后续有权 Package 选用；本知识库仍 `NOT_QUALIFIED`。
