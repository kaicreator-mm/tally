## 一、知识对象与专业推理的原则

需求工程与业务建模 要从概念的明确语义延伸到工程机制、条件性取舍和可反驳的实际结果。学习一个技术名词不等于学会何时用它；能输出步骤不等于执行/验证通过。此处每个知识点包括**概念、因果/适用机制以及常见错误泛化**，作为 Agent 的系统学习和主题检索基础。只有实际工程问题需要深入时，才延伸到相关 Topic/DP/Skill/真实测试。所有业务效力仍由当时适用的 Product/ADS/GitHub/Host 事实决定。

## 1. 需求价值与边界

### K01.F1.1 — Need/Goal 与 Solution

**专业知识/机制**：Need 表达用户价值和外部行为；Feature 是若干可选解决方案。通过角色、场景、目标结果判断是否需求偷换。

**错误外推及负例入口**：用户说“添加按钮”就把按钮当成全部业务需求。

**判断产物**：选择当前真实任务下适用的解释、已知事实、缺失条件和不能被默认成立的反例；不借此生成现行任务的权限/验证 PASS。

### K01.F1.2 — Stakeholder 与利益冲突

**专业知识/机制**：识别直接用户、运维、监管/业务 Owner、外部消费者以及信息权力差异；同一操作在不同角色下合法行为可能相反。

### K01.F5.1 — 同条件冲突判定

**专业知识/机制**：同 Actor/State/Event/Context 的预期结果不兼容才是实质规则冲突，需比较有效版本和权威。

### K01.F5.2 — 验收与反例

**专业知识/机制**：至少用一个合法/一个非法或边界输入区分正确与错误实现，测试 Oracle 来源不能由 Builder 自证。

**专业知识/机制**：确认修改是否扩大产品范围、影响旧接口和质量条件；需要 Product Owner 决策时保留 STOP。

## 六、完整专业知识如何映射到 Tally 可执行领域智能

**角色**：业务意图、涉众、领域规则与验收语义的唯一解释者。K01→K02 只传已明确业务/质量约束；K01→K05 传可证伪验收和合法原始规则；K01→K09 传对受支持旧用户行为的改变范围。

**专业案例（教学情境）**：批量工单 CLOSE：部分成功与整体原子互斥。对同一个 2×OPEN、1×CLOSED 的输入提出两种候选政策，先确认业务 Owner 决议再生成状态/数据/副作用的验收表。

**禁止的错误判断**：未经决议就以“通常允许部分成功”修改正式状态机，应输出 UNKNOWN/HOLD 而不是 PASS。

**推理/证据链**：当前 Goal/事实/来源 → 选 K01 的相应学科群及 Concept → 明确 Rule/Model 是否具备有权业务前提 → 选择 [方法与 DP](engineering-methods.md)、[Agent Skill](agent-skills.md)、已有或未来 [Topic](README.md) → 给出正反 Oracle 与 STOP → 只有在合法消费者实际运行时才附真实 Host/CI/Review 收据。

**关联专业资料**：[A01](../external-source-catalog.md)、[A05](../external-source-catalog.md)、[A12](../external-source-catalog.md)、[A13](../external-source-catalog.md)、[A44](../external-source-catalog.md)。这些是覆盖和方法的公开参考，**并不表示整套出版物已逐条核对/获得复制许可/成为已认证知识**；当前 ADS 精确规范条款的适用性仍以 [sources.md](sources.md) 为准。核心软件工程和工程基础跨领域关系见 [disciplinary-coverage.md](../disciplinary-coverage.md)。

## 七、知识深化的可观察标准和当前缺口

- **基础层**：这里的 15 个知识点已形成概念+机制+反模式的**原创系统知识纲要**，但不意味着该学科所有细目已经获得全文教材深度或来源 Claim 资格。
- **方法层**：真正要处理的任务应能从本群的术语/条件追溯到现有 DP/Skill/案例或形成新的具体 Topic，且至少能指出一个会使错误判断失败的负例。
- **选用层**：未来根据明确 Product/Task/Package 权限，只为真实使用的知识链补准确 Source/Clause、适用性、许可和消费者测试；没有实际执行仍保持 NOT_RUN。
- **维护层**：新增学科研究、反例或实测失败优先补本群的专业机制与出处，多个 Topic 仅链接到唯一概念解释。未被当前开发用到的理论不因缺运行时资格而从学科知识库删除。
