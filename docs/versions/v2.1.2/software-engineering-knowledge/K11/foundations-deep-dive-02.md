## 一、明确研究对象与反事实

“Agent 知识库是否提高开发能力”不是单一指标，必须先说明：目标软件任务是什么、在什么类型的仓库和初始 Head 上、与哪种不使用新知识的基线比较、有哪些已生效 ADS 约束不随实验组改变。**反事实**是同样条件下没有该知识介入会怎样；若实验组用了更强模型、额外工具权限或更大预算，就无法将全部差异归因于知识本身。

同一个任务往往无法在完全相同条件下重复，因第二次执行者已经看到答案。可使用多个可比问题、随机/交叉分配、不同 Session、事先冻结的任务集和盲审（可行时）降低学习偏差，但不能宣称彻底消除难度差异。

## 二、独立 Oracle 与质量分层比答题数量重要

一个工程任务可分层评价：业务行为正确、材料测试真正执行、架构与兼容约束、最终可安装/运行的产品路径、评审发现、维修后再次维护成本。模型对领域知识的问题回答正确并不代表修改代码安全，测试 100% GREEN 也不代表真实消费者路径覆盖完毕。

评价前冻结**范围内的正确性/必要保证下限**，再讨论效率。一个明显更快却重复扣款、遗漏权限或破坏旧数据的实现不能用成本优势抵消严重缺陷。

## 三、统计报告需要描述不确定性

假设两组各 10 个任务，知识辅助组通过 8、对照组通过 6。观察差异是 20 个百分点，但样本很少、任务难度可能不均，不能直接称“知识提升了 20% 的真实开发成功率”。必须记录分母、数据生成方式、样本选择、错误/未知定义、结果分布与适当不确定区间；进一步推断需要考虑统计功效、相关性、多重比较和偏差。

**研究标准并非一个总流程**：受控实验、定性案例研究、工程研究、基准构建和仓库数据挖掘的证据要求不完全相同。对于无法随机的真实项目，可进行有边界的案例解释和时间序列观察，但更应限制因果声称，不能将相关趋势自动写成 Agent 改进。

## 四、技术投资的时间价值与风险

简单成本公式：`NetBenefit = expected avoided rework/failure cost - new training/integration/review/maintenance cost`。其中概率和成本若未观察，必须显示区间/情景而非一个虚构精确货币值。对于不可逆风险，概率虽低但后果严重时，应首先满足现行安全/用户保证下限；经济目标不是任意豁免。

对某知识群是否继续扩展，可同时考虑：是否是软件工程的系统性必备基础、当前专业理论缺口、真实误判严重度、跨模块重用、可得的可靠来源、现有维护成本。不能把“没有近期消费者调用”直接当作删除基础理论的理由；也不能把已经有 165 个纲要标题当作学科建设完成。

## 五、如何选择停止进一步研究

| 状态 | 合理决定 | 错误做法 |
| --- | --- | --- |
| 核心业务正确性仍 UNKNOWN | 对受影响 Goal 请求有权决议 | 编造结论来减少等待 |
| 已有足够当前 Scope 证据 | 完成受控交付/记录适用范围 | 无材料新证据仍无限审核 |
| 额外研究不会改变方案 | 记录残余风险并停止 | 必须全 11 模块重新研究 |
| 新知识只是教学候选 | 保留 BOK/反例/来源 | 自动晋升 Rule 和 Release |
| 实验结果不支持收益 | 报告负结果并调整适用条件 | 只保留成功案例 |

**教学反例**：将现有 26 个专题、11 个章节和 54 个来源目录当作“54 个已验证模型能力”，再凭一个生成式自测分数宣称产品级效用。这种评价把资料收集、知识正确性、部署使用和实际工程收益混成一个不可证伪数字。
