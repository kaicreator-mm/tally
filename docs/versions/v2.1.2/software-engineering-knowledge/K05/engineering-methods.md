## 知识正文与重要权衡

## 3. 知识正文：核心工程方法

### 3.1 从要求生成 Oracle

先把业务规则、设计合同和已批准示例写成可观察的输入/状态→结果对，标明为什么这个结果是正确的。不能把 Agent 凭空虚构的业务规则变成 Test Oracle。一个重要不变量应同时有可满足的正例与违反时被拒绝的反例，测试假阳性往往来自仅检查内部调用而不检查用户状态。

### 3.2 测试层级与代价

Unit 优先验证局部纯逻辑，Contract 锁定外部 API/Schema/序列化/CLI 行为；Integration 使用真实 DB/filesystem/队列和对外适配 seam；E2E 覆盖少量关键用户结果；Build/Packaging 检查可交付入口与真实产物。各层不能互相取代，也不要求每个小修补都跑完整分布式 E2E。

### 3.3 边界、状态与组合测试

等价类帮助减少冗余组合，边界值覆盖 0/1/max、空值、过期时间、状态转换边界；状态机测试检查非法转移、重复提交、取消、失败恢复。对高价值复杂逻辑可考虑性质/变异测试，但必须有合法不变量作为断言，并评估生成数据的真实来源和成本。

### 3.4 Mock 与真实消费者的分界

Mock/Stub 适用于快速隔离业务算法和对某个稳定合同做初步判断，不能替代真实外部 DB/queue/Host 的副作用行为。测试应该核实选定构建实际加载新模块、公开入口实际调用修改后的代码、界面/CLI 或服务实际观察到正确结果；否则“测试已写但没有消费”仍是未验证。

### 3.5 实际测试发现与执行证明

有些测试命令 exit 0，却没有发现目标测试文件，或者测试套件忽略了变更目录。验证时需读取 runner 枚举结果、用例计数、具体路径/调用或有代表性的失败探针；报告写实际执行命令、环境、退出码、测试 SHA 和失败明细。不要用成功的 npm install 替代 TypeScript build 和测试结果。

### 3.6 最小充分验证策略

按影响范围与风险做测试选择：语法/类型/受影响单元、必要契约、跨模块真实组合、可交付产物。若目标工作区已有等价通过的有效证据不重复 CI；但真正要求独立 Provider/真实 Host/特定 OS 的合同仍需现场证明。对未运行测试诚实标 NOT_RUN，不为“安全感”无限增加独立审查。

### 3.7 测试质量、Flaky 与长期回归

失败测试应反映真实缺陷而不是随机等待、固定日期、外部网络偶然波动；对 flaky 原因归类并选择确定性 fixture/隔离/轮询机制，不能通过增加无限重试掩盖稳定错误。Golden/Snapshot 必须有合法 Oracle，不得随着变更无审查地更新基准使所有回归自动变绿。

## 具体可执行方法与取舍

设计每个测试前先写“若这条业务规则被故意破坏，测试是否会失败？”将状态不变量和接口合同映射到正例、禁止转换、边界值、重复/延迟/断线场景。选择 Unit/Contract/Integration/E2E 层时区分 Mock 是否替换了真正关键副作用。实际执行必须记录 runner 发现的目标测试、退出码、当前源码/测试 SHA 及环境；无需对不受影响内容无条件重复全套 CI。

### 场景选择矩阵

| 真实条件 | 推荐分析/方法 | 需要记录的结果 | 禁止误推 |
| --- | --- | --- | --- |
| 没有可信业务规则但 Agent 想写期望 | 先回 K01 确认 Oracle 的真实来源 | 规则 UNKNOWN | 不得用实现行为倒推要求 |
| 新接口只在 Mock 上验证 | 增加真正公开入口的契约/必要真实集成路径 | 受约束执行计划 | 不能声称真实 Host PASS |
| 0 个测试被发现但 runner 退出 0 | 标为发现缺陷，修正有效测试选择 | test discovery 收据 | 不能作为行为 PASS |
| 仅 docs 改动没有运行时影响 | 复用合法当前证据，跳过无关重测 | 跳过原因与范围 | 不将未运行说成运行通过 |

## 现有 Decision Procedures（输入、步骤、产物与停止）

## 4. 可执行的 Decision Procedures

决策程序定义可复用的方法及终止条件，不创建第二套运行时状态机、审批权威或 Agent 调度器。

### DP-K05-01 · Requirements→Oracle→Test Matrix

**输入：** 已确认 Need/Rule/Acceptance、L2 API 和关键状态

**步骤：**
1. 提炼可观察的成功与禁止行为，标注原始来源。
2. 选择有代表性的正常、边界、无效、重复/失败输入。
3. 根据行为所在边界安排 Unit/Contract/Integration/Critical Journey 层次。
4. 给每个测试写输入前置、断言、不允许结果和运行环境。
5. 审查断言是否会在目标实现有错时真的失败。

**产物：** 最小风险适配 Test Matrix、验证来源及测试命令

**失败/停止：** 业务规则未确认时保留 Oracle UNKNOWN 而非虚构预期。

### DP-K05-02 · 选择受影响验证集

**输入：** 实际 changed paths/Task 目标/当前测试布局/部署合同

**步骤：**
1. 检查项目现有真实测试发现范围及构建工具版本。
2. 运行必要 syntax/types/build，并选行为直接受影响用例。
3. 按公开合同、跨模块/真实 Host 要求增加必要验证。
4. 复用合法且未失效的先前 PASS 证据，明确哪些没重跑。
5. 在当前源码 exact SHA 上验证执行结果。

**产物：** 可解释的测试选择、真实命令和执行收据

**失败/停止：** 不可调用真实 Host 时声明 NOT_RUN/BLOCKED，不冒充成功。

### DP-K05-03 · False PASS 取证

**输入：** CI/测试结果、真实入口/消费者、被修改源码及构建产物

**步骤：**
1. 确认目标源码确实出现在选定构建和模块加载路径。
2. 确认相关测试确实被发现，非 0 用例退出。
3. 确认实际断言观察到需求结果而非仅函数 mock 调用。
4. 发现缺口后设计最小会因错误实现而失败的反例。

**产物：** 验证缺口与最小修复/额外测试建议

**失败/停止：** 有明确证据缺失就不能宣告正式 PASS。

## 抗过度流程原则

一次实际 Task 至多选择足以完成当前判断的 Procedure；除非已知缺口会改变业务、架构或正确性结果，否则不自动开新 Issue、实验或大量 CI。若缺少有权决策者、现行数据或真实 Host，保持 UNKNOWN 并说明最小下一项证据，不通过 Agent 自信度推定通过。
