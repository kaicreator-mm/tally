## 9. 训练与知识资格验证案例

以下是**未来**测试/案例设计，不代表测试或知识资格已经完成。

| 案例 | 期望推断或行为 | 需要拒绝的结论 | 验证依据 |
| --- | --- | --- | --- |
| 空测试集 exit 0 | 发现缺口并标 INVALID/UNKNOWN | “CI GREEN 即通过” | 真实测试 runner 用例清单 |
| 非法状态被实际修改 | 真实接口负例必须失败 | 内部单元测试绿就足够 | 业务规则 + API/DB 运行 |
| 外部第三方仅 Mock | 限定资格为模拟合同 | 直接写生产 E2E PASS | Mock/真实依赖拓扑 |
| 同 SHA 受影响测试已有通过 | 有条件复用，不无意义重跑 | 必须额外反复 CI | 已接受收据+当前性 |
| 测试源变更但版本没绑定 | 重新执行或明确不足 | 使用旧提交结果 | 实际 source/tested SHA |

真实测量时先固定任务、输入、预期标准及基线，再比较直接 Agent 与 Tally 选中知识后的实际质量/修复/成本。不得用文档样例或图谱问答成绩替代实际编码效果；没有结果就标明 `UNKNOWN/NOT_RUN`。

**模块交接边界：** K05 决定哪些测试 Oracle 与层级能证明受影响行为；K08 负责实际 CI/Build/Artifact 运行及来源收据，不得由 K05 文档自行签发 CI 或 Release PASS。

## 评估维度与失效标准

| 评价维度 | 最小合格观察 | 必须视为不足的情况 |
| --- | --- | --- |
| Oracle 有有效需求/合同来源。 | 当前任务中能真实说明何时成立、何时不成立，并指向实际输入/输出 | 只有模型自评、资料目录数量或旧 HEAD 证据 |
| 至少一个负例会在错误实现下失败。 | 当前任务中能真实说明何时成立、何时不成立，并指向实际输入/输出 | 只有模型自评、资料目录数量或旧 HEAD 证据 |

## 针对边界的对抗变体

- **NEG-K05-01**：在“非法订单状态”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K05-02**：在“快照更新”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K05-03**：在“Flaky timeout”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。

## 最小实测计划（非已完成声明）

1. 固定当前 Task、可读来源、验证环境、质量基线与适用原有 Review/Validation 规则。
2. 执行直接 Agent 基线与选用此模块特定 Decision Procedure/Skill 的受控任务对照；避免在两组之间改变上下游 Product/L2 事实。
3. 让独立 Reviewer 按实际需求/设计/测试结果核实准确性、遗漏、回归、修复轮次和必要环境成本。
4. 报告已执行命令/Host/代码 SHA 与 `NOT_RUN/UNKNOWN`，保留负面结果，不能以知识问答分数代替真实开发结果。
5. 只有源主张、适用条件、独立验证和真实消费者都合格，才可能进入后续有权 Package 选用；本知识库仍 `NOT_QUALIFIED`。
