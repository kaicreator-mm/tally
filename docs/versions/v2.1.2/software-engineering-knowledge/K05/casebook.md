## 7. 端到端教学案例与故障反例

**情景：** 新增订单状态变更接口。Builder 写了 8 个 Unit Test 并报告“全绿”；真实 API 使用另一条包装路径，错误状态仍可被修改。

**正确处理：**
1. 从已确认规则提炼允许状态、非法状态、重复请求与权限错误的 Test Oracle。
2. 检查现有 Unit Test 是否通过 Mock 绕开真正的 API/DB 更新入口，不能从数量判断质量。
3. 增加一个公开合同测试和最小真实 API→持久化集成负例，覆盖非法状态拒绝及状态不变。
4. 验证 runner 真正发现并执行新增测试，输出命令/环境和受测试的 SHA。
5. 若部署用户关键路径受影响且项目实际需要，补选定应用真实入口验证；无需每次重复全系统 suite。

**可以观察的正确性：** 非法状态变更必须失败并保持记录未改变；当前测试真实运行且在错误实现下能失败。

**故意错误的候选：** 只在内部方法的 Mock 上检查调用一次；test 命令实际选中 0 个测试仍 exit 0，然后将 UI/Host/Release 都标 PASS。

**变更条件后如何调整：** 若仅改测试文件注释，已有构建/行为证据不失效时无需重复真实 Host；如 public API 变更需恢复相关契约和真实消费者验证。

## 反模式与错误后果

## 8. 常见反模式与止损条件

1. **Zero Test Green**：通过命令成功不代表选择到目标测试
2. **Mock-as-E2E**：所有外部边界由 Mock 替代却标真实 Host
3. **Oracle Leakage**：从错误实现反向定义 expected 值
4. **Golden Rebaseline**：未经来源核对就更新 Snapshot 将回归变绿
5. **Endless Verification**：不区分影响和环境要求，反复跑所有 CI 造成无效成本

## 扩展场景：用不同条件检验知识的泛化边界

### C-K05-01 · 非法订单状态

**问题**：拒绝非法转换且 DB 状态保持不变，不能仅验证 Mock 被调用。

**如何用本模块诊断/解决：** 先识别用户目标、确切源/版本与真实约束，按 [方法矩阵](engineering-methods.md) 选与此情况匹配的一条有界程序；不影响结果的假设不额外提高流程成本。

**反例**：若 Agent 未核对上述关键条件就直接断言相同方法普遍适用，必须以 UNKNOWN/REWORK 处置而不是 PASS。

### C-K05-02 · 快照变更是否真实得到许可（SYNTHETIC_TEACHING_CASE）

**测试输入**：已批准 API 契约规定无效状态返回 `409`、订单状态保持不变；旧 Golden 是 `{"status":"ACTIVE"}`。候选实现错误地把拒绝后的状态设为 `CANCELLED`，Builder 同步更新 Golden 为新响应并报告快照通过。

**应当执行**：
1. 先读取已批准的 Rule/Acceptance，而不是使用新实现生成新的预期值。
2. 以公开 API→真实持久化路径验证非法状态的返回与写入副作用；旧 Golden 仅是辅助证据。
3. 将本次 Golden 更新归类为 **未经业务来源授权的测试 Oracle 漂移**；拒绝由此宣称回归通过。
4. 只有有权 Product 真实修改业务规则、并在新版本形成可核对验收时，才重新建立 Golden 和正反例。

**可证伪 Oracle**：非法状态调用后 `status` 仍为 `ACTIVE` 且错误为 `409`；如果仅更新 Snapshot 使测试绿灯，却仍写入 `CANCELLED`，应输出 `REWORK/INVALID_ORACLE`，不能 `TEST_PASS`。**适用限制**：返回码和状态仅为本教学案例假设，真实项目必须读取本项目的有效契约。

### C-K05-03 · 超时与不稳定测试（SYNTHETIC_TEACHING_CASE）

**测试输入**：一个异步 Job 的完成通知通常在 50–250ms 到达，但测试固定 `sleep(100ms)` 后断言成功；某次 CI 在 130ms 收到通知并 FAIL，Builder 提议将 sleep 提高到 10s 且重试 20 次。

**应当执行**：
1. 读取真正的业务时间限制与事件/完成条件，区分测试的计时假设与服务超时合同。
2. 使用确定性模拟时钟/有上限的条件等待或同步事件，而不是任意固定休眠。
3. 若有真实端到端时限，限定等待上限与失败原因，同时记录实际 Runner/负载。
4. 在相同场景重复执行并证明测试能在事件永不发生时**确实失败**，而不是靠无界重试变绿。

**可证伪 Oracle**：通知在业务允许时间内发生时测试通过；通知永不出现时在明确上限内失败。若只增加延迟/重试仍未验证合同，则 `TEST_QUALITY_UNKNOWN`。**适用限制**：示例毫秒数只作合成输入，不能推定真实项目 SLA。
