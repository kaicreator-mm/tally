## 1. 实验能支持什么，不能支持什么

原 R19 仅有 1/12 首次实现；R19-F 的 6/6 代码和维护结果全部高分而缺少区分度。R19-F2 是**另一个独立前瞻性队列**：两个不同 TypeScript 领域、每领域两次重复、每次三组 A/B/C，共 **12 个首次代码提交和 12 个陌生维护提交**。A 没有 R19 增量知识；B 得到冻结的概念与反例；C 在与 B 相同的概念/反例基础上于 S2 获得额外决策程序。每组 4 个样本，模型按运行者记录全部为 GLM-5.3-Flash。

运行者报告：首次隐藏测试 **只有 2/12 全过**，12/12 新增维护需求测试通过，然而旧与新一起全部通过也只有 **2/12**；双 Reviewer 的 24 份首判与两次仲裁最终为 11 个 `JUST_ENOUGH` 与 1 个 `WRONG`。**没有观察到专业抽象知识对真实代码质量或维护成功率的稳定增益**，也没有观察到 C 相对 B 的稳定增益。

**证据资格**：上述数字来自 Windows 本地 Coordinator 的公开收据。本文核对了冻结的公开 H0 功能任务文字，但**未独立访问/重放**其 `C:\R19F2\evidence` 里的 11,123 个原始日志/代码/QA 文件；不能将此文标为第三方 Exact-Host 复验或经独立证明的因果效应。每臂每任务仅两个重复，并且执行账户与分组绑定，Provider/执行顺序可能混杂；原始 cohort 与两轮先行 cohort 分母互不合并。

## 2. 测量问题：隐含工程期待不是公开合同

| 报告的隐藏失败 | 公开 TASK 已规定的范围 | 不能直接得出的结论 |
| --- | --- | --- |
| 某限流构造器未快照/拷贝调用者的可变规则，外部改写规则后影响行为；A 2/2 通过，B/C 0/4 | 合法 ID、限额、分状态及时间/拒绝语义；没有明确规定「构造器取得规则后是否与调用方共享可变对象」 | B/C 违反已明确授权的防御性拷贝合同；或知识必然降低质量 |
| 某授权查询容忍负时间值；A/B/C 共 6/6 在该断言失败 | 许可记录 `expiresAt` 的合法域写明，但查询 `atMs` 的合法域未独立明确；仅概述非法查询应拒绝 | 六份代码在相同的明文合同下全部违约 |

原始隐藏 QA 分数**不予改写**；在明文或唯一可推出合同覆盖的 15 条共同断言上，按公开结果两类任务的全部 12 个候选均通过。**这是敏感性分析，不是事后重算原始 PASS**。对是否拷贝对象、允许哪些查询时间等问题，Owner 应提前声明 `COPY / IMMUTABLE_BORROW / SHARED_LIVE_REFERENCE` 与明确输入域；没有声明就保留 `SOURCE_UNSPECIFIED`，不能让隐藏 Oracle 替 Owner 创造需求。

未来实验的每条可评分测试都必须在首次执行前具备最短链：

`AUTHORIZED_REQUIREMENT -> LEGAL_INPUT_DOMAIN -> REQUIRED_OBSERVABLE_BEHAVIOR -> TEST_CASE -> EXPECTED_NEGATIVE_CONTROL`

并区分 `DECLARED`（原文明确）、`DERIVED`（可从明确合同唯一推出）、`ENGINEERING_HYPOTHESIS`（有价值但尚未授权）。最后一类可记录为研究观察，**不得单独决定原定功能 PASS、知识胜负或回归**。不要在事后补齐任务书再倒推原模型错误。

## 3. 四项值得纳入知识的可证伪工程机制

### K02：状态写权限与入参对象所有权是两个不同问题

「谁是内部状态的唯一 Owner」不能推出「被传入的 JavaScript 对象已经变为私有快照」。如果对象的原始引用仍保留在调用者手里，对方可以合法地改变它；库保存该引用就可能受到外部别名写入影响。应单独询问：**交接时的拥有权/可变性、对象是否复制/冻结、是否约定共享实时配置、调用方后续写入的可观察后果**。复制与共享都可能合法；应由有权合同决定，不能机械强制深拷贝。

**反证**：若明文允许共享实时可变配置，则测试“调用者改规则后库必须不变”不是合法旧合同；若明文要求快照，仍引用外部对象的实现才构成可复现违约。

### K03：安全整数的输入合同不保证中间数值表达式精确

允许 `Number.isSafeInteger(t)` 与 `Number.isSafeInteger(window)` 不保证窗口端点、下一刷新时刻、重试倒计时的**中间表达式**都安全。运行者在接近 JS safe-integer 极值的合法时间参数上复核到限流代码时间舍入误差：6 个候选中 **4 个受影响**（A=1/2、B=1/2、C=2/2），但单一 Reviewer 只识别其中 1 个。该缺陷强烈随区块变化，不支持按知识臂解释。

**反证/实施选择**：先明确时间精度与合法域；若真实合同要求精确整数边界，考虑按余数/差值推导、使用安全范围证明或在边界处选用 BigInt，再用接近临界值的执行例证伪；不能仅因为 `safe integer` 输入已校验就声明所有输出精确。这里讨论**行为精度**，不是无依据地强制某一种架构模式。

### K05：Reviewer 的 `JUST_ENOUGH` 不是缺陷不存在的证书

最终只有一个 `WRONG` 标签，而同根数值边界缺陷在另外三个样本被漏报。总分标签和 Reviewer 一致率不能代替**受权 Source、源码位置、可执行反例和同类候选的对等复测**。如果已经发现一个可信新反例，应先保持原两份盲评不变，再遮住组别对所有相关候选应用相同刺激；标注 `POST_REVIEW_FALSIFIER` 和漏检/覆盖范围，而不能在知道 A/B/C 后只追加某一组缺陷。

### K09：新增需求成功不代表旧问题被修复，也不代表全量维护成功

维护任务新增需求 **12/12** 全部通过且没有新增旧合同回归，但前态的十个原有失败都继续存在，因此旧+新测试全过只有 **2/12**。必须分开测量：
`OLD_AT_FIRST`、`OLD_AFTER`、`NEW_BEHAVIOR`、`FIXED_PREEXISTING_DEFECT`、`INTRODUCED_REGRESSION`、`OWNER_TOUCH_SET`、`MAINTENANCE_COST`。

允许新需求目标已完成但整体产品仍不合格；不能把 `NO_NEW_REGRESSION`、`NEW_PASS`、`ALL_PASS` 混为一个布尔量。只数修改行数/文件数更不能证明边界正确。

| 每个样本平均 Token（报告值） | A 无额外知识 | B 概念与反例 | C 额外决策程序 |
| --- | ---: | ---: | ---: |

| 两段合计 | 570,301 | 708,569 | 661,941 |

B/C 两段总 Token 比 A 分别多约 **24.2% / 16.1%**；同一组内 r1 与 r2 的变动明显大，模型采样、区块顺序与身份绑定构成混杂。数据不足以证明任何「知识必然提高/降低成本」的通用规律。评审/QA/协调成本还要独立核算，不能只用代码生成 tokens 代表全成本。

## 5. 使用边界与未来验证规则

- 对 **有权的状态隔离、输入交接、数值极值、异构授权/错误语义** 风险，可选用 K02/K03 的一两个针对性反证问题，而不是给每个简单任务完整加载全部知识与步骤；选择 `NONE` 仍是合理的。
- 若任务未明确入参所有权或数值合法域，先记录缺失 Source 并请求/冻结合同，不对未知行为擅自升格为强制规范。
- 新增的反例、评审清单和教学知识不是已证明能够提升 GLM-5.3-Flash 的干预；今后若研究其效果，需**使用全新测试领域/任务和在开工前冻结的合法 Oracle**，且试验身份不能与处理组完全绑定。
- 不复制本研究具体隐藏测试、维护答案、候选代码或组别映射到教学包，避免污染后续独立样本。#559 与旧 #558/#554 实验原始结果永不重算覆盖。

**本篇是经验反馈候选而非生产规则**：数据未支持将 `JUST_ENOUGH`、A 优势或 C 的额外步骤写成已实证有效的领域能力。
