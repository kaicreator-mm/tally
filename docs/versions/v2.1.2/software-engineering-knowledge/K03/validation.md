## 原有训练/验证矩阵

## 9. 训练题与验证矩阵（后续可转换为 Cases / Validation）

| 任务/情景 | Agent 期望判断 | 错误或危险结果 | 最小证据 |
| --- | --- | --- | --- |
| 简单一行空值修复 | INLINE 设计并运行相关回归 | 长篇新框架设计 | 真实 Task/受影响测试 |
| 重复请求导致多次写入 | 检查幂等键或状态前置条件 | 仅增加无限重试 | 重复调用负例 |
| 异步任务超时 | 区分失败与未知，保留回读 | 超时直接标成功 | Host/状态持久化证据 |
| 公开接口有新错误码 | 与 L2 合同及测试一致 | 任意变更旧行为 | 已确认接口版本 |
| 仅有 Builder 日志 | 报 SOURCE_CANDIDATE，等待权威验证 | 把本地 stdout 当 Task PASS | 命令/exit code/exact SHA |

**不完整证据的表示**：缺少用户业务决定、来源版本、真实调用结果或正式环境时，记录 `UNKNOWN / NOT_RUN / BLOCKED`，并写明下一项最小可验证事实。案例/模拟结果不能冒充真实 Agent 开发效果。

**模块交接边界：** K10 负责定义可选的运行质量/恢复模式；K03 只负责将当前批准的错误/日志合同应用到具体 Task 代码，不自行建立新的通用运行规则。K06 仅在出现真实故障时诊断根因。

## 针对边界的对抗变体

- **NEG-K03-01**：在“批处理重复请求”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K03-02**：在“异常资源清理”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。
- **NEG-K03-03**：在“可操作错误”场景中故意移除一项关键来源、改变适用角色/版本或提供矛盾证据；合格 Agent 应明确辨认未知或条件改变，而不是重复正例的结论。

## 最小实测计划（非已完成声明）

1. 固定当前 Task、可读来源、验证环境、质量基线与适用原有 Review/Validation 规则。
2. 执行直接 Agent 基线与选用此模块特定 Decision Procedure/Skill 的受控任务对照；避免在两组之间改变上下游 Product/L2 事实。
3. 让独立 Reviewer 按实际需求/设计/测试结果核实准确性、遗漏、回归、修复轮次和必要环境成本。
4. 报告已执行命令/Host/代码 SHA 与 `NOT_RUN/UNKNOWN`，保留负面结果，不能以知识问答分数代替真实开发结果。
5. 只有源主张、适用条件、独立验证和真实消费者都合格，才可能进入后续有权 Package 选用；本知识库仍 `NOT_QUALIFIED`。
