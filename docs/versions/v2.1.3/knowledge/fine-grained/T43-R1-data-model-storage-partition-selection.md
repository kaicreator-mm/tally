# T43-R1 · 数据模型、物理存储及分区的条件选择

#658 / #563；K02 权威数据模型及边界，K03 表示/存取算法，K01 观察及业务不变量，K10 容量/恢复，K05 独立评价。冻结 a55fc5718dc39d298a3195e79a2fc831df5fbbd3。DA-08 有限收敛选题；复用 T27b-1 关系约束和事务、T27d-1 数据结构、T40-R2 表示充分性、T32b-2 来源与删除。不同逻辑模型、物理组织、分区/部署和读投影不是互斥的同一选择轴。公开机制来自 MongoDB 8.0、DynamoDB 写分片、RocksDB 固定 Wiki 修订及 Parquet 文件格式；非真实用户系统或全引擎比较。以下合同及计算原创教学，目标 NOT_RUN。

## 1. 先确定权威事实、查询和共同写约束

教学设备管理：项目 P 关联多个独立设备；设备 identity=(tenant,deviceId,generation)，项目关系有独立角色与有效状态，设备状态需全局当前事实；另有被允许陈旧的列表和历史遥测。需要回答按项目列设备、按设备列项目、改设备名称、并发准入和按时间查记录。先核观察与约束，后选表示；若只需小集合和本地文件，且实际并发、持久和恢复合同有支持，甚至不必独立 DB 服务。

| 逻辑表示候选 | 支持与变化 | 不得隐去的条件 |
|---|---|---|
| 关系表 | 多对多关系、独立身份/外键、双向查询、共同事务 | 实际键与约束、谓词冲突、索引及迁移成本 |
| 单文档内嵌 | 小且有界的从属记录同读同改、单对象原子更新 | 文档大小/独立生命周期；跨文档不变量仍需真实协调 |
| 键值/复合键 | 已知键或前缀的高频操作、明确条件写 | 反向访问、范围和跨键约束不是自动能力 |
| 图关系 | 多跳路径/邻接关系和路径约束是核心问题 | 方向、节点/边身份、路径语义、循环和有界遍历；关系表也能表达图 |
| 时序/列式读投影 | 时间范围、扫描少数列、聚合/归档及可接受延迟 | 事实时间和单位、覆盖、修订、索引/文件及快照合同 |

同一权威关系模型可以有 JSON 字段、图投影、列式历史和搜索索引；不是因此所有数据都需要多种数据库。图遍历必须区分可达性、路径数与去重节点数：P→A→C 与 P→B→C 两条路径、末端同一 C；若求独立目标仅一个，不能把两条路径当两个设备。若需最短路径则区分无权与加权算法（T27d-1），不从数据库类型推出正确路径。实时权威数据与只读副本/索引/归档的职责不同。

## 2. 内嵌、引用与复制的实际反转

假设某设备 X 被 P,Q 同时引用，当前名称 N。把权威名称分别内嵌在两个项目文档，修改 P 为 N1 时 Q 仍 N，违反本例要求所有当前读取遵守同一名称权威；若复制名称仅作明确版本的列表展示且允许陈旧，则可合法保留 X 权威记录并更新两个投影。若要求历史成交名称，复制当时名称恰是所需独立业务事实，不应被当前名称更新覆盖。独立有权历史合同见 T40-R2。

反过来，小型检查单中固定上限10项，每项仅属于该检查单，不独立引用，且业务要求一次确认所有状态：一个文档含检查项与当前版本，可在同一有条件原子写更新；仍须先定义合法状态变化、授权、版本和错误，原子写不是所有输入均合法。若检查项后来独立共享、数目无界或新增跨检查单约束，重新评估引用及实际共同事务，不仅把 JSON 拆开。MongoDB 8.0 数据建模指南按读写场景说明内嵌/引用、重复数据的一致成本及 schema validation；单文档写具原子性，跨文档可使用多文档事务但有实际开销。具体约束、读隔离、耐久和部署行为另核，不将 MongoDB 的能力推广所有文档/键值库。

## 3. 分区键、热点及全局查询合同

在简化模型中，事件以 (tenant,day,eventId) 唯一标识，某租户某日的逻辑写流 1200 条/s，假设每个独立物理分区在该负载下最多持续处理400条/s，不考虑其它负载且要求不积压。若全部在一个固定分区，缺口800条/s；若通过稳定 hash(eventId) mod 4 分散到四个独立物理分区，恰好均匀时每个300条/s，才满足假设。若实际分布为900/100/100/100，首分区仍有500条/s缺口；新增四个逻辑桶并不证明映射到四个物理资源或一定均匀。示例容量不是 DynamoDB 实测或配置值。

按 (tenant,day,bucket) 存、eventId/适用时间作为排序身份，可通过确定桶定位已知事件；按日期查全集则需读所有实际桶、核覆盖及同一可接受观察边界，合并同一完整排序键，再去重/分页。DynamoDB 官方写分片指南给出按日期附加随机或计算后缀的机制及全日查询扇出代价；这里不承诺实际服务布局、全局快照或自动事务。若四个桶的有序读为 [1,9]、[2,7]、[3,8]、[4,6]，按全局升序前3为1,2,3；取第一个桶的前3不充分。多路归并可维护每个非空流的首元素于堆，反复取最小并补对应流，固定完整且全序的 m 路下 O(m+k log(m+1)) 比较上界（线性建堆，忽略各源读取成本）。某桶超时且无能证明它不能包含更小键的下界时，不能声称全局前3精确；完整性/权限同 T42-R1。全局唯一、库存或配额也不会因分桶自动变成各桶独立约束；沿 T40-R1 证明实际独立或共同协调。重分桶须有映射版本与迁移/去重合同，不能让同 eventId 在两个桶双算。

## 4. 物理组织、读写放大与预算

B-tree 等页式有序索引支持按键定位/范围，但页更新、分裂、WAL 及缓存影响写成本；T27b-1 的计划和 T27d-1 的复杂度不等于实际 IO。LSM 类组织以可排序批次写入、形成有序 runs，读可能要合并多个版本/层；compaction 合并、重写并在满足可见历史条件后回收旧版本。RocksDB 固定2021 Wiki 修订区分 leveled、tiered 及混合；不同策略在写放大、读放大、空间放大之间权衡，实际分布/配置影响，不从一个算法名推出永远快。

教学同一观测期写入新增逻辑值100 MB，假设计数范围为初次落盘100 MB及其后重写200+300 MB，不含 WAL/元数据/复制且不重计；按此范围写放大600/100=6。若长期逻辑写100 MB/s，且相同长期比例、读写争用暂忽略，持久设备只有400 MB/s写能力，则所需600 MB/s，不能长期维持无积压；不靠前台确认快宣称吞吐达标。实际需核 WAL、压缩、读 IO、缓存、后台预算、峰值空间与可恢复性。空间若活数据100 MB、占用150 MB，本口径为1.5倍；compaction 中新旧文件可能共存，稳态余量不足可阻止维护。读放大须固定一次业务查询的实际读次数/字节等分母；不存在单一可互换三放大指标。墓碑不可只因合并或 TTL 退休就宣称历史删除/不复活，复用 T32b-2。

列式文件另一个轴：Parquet 公开格式中每 row group 含各列 chunk，元数据定位所需列。假设1万行、20个等宽8字节字段，仅查2列，无压缩、行筛选、额外元数据及编码开销，理想值字节1.6 MB vs 0.16 MB（十进制），10倍值字节差；不是实际10倍耗时，点查询/完整行更新、页粒度、解码与内存仍需考虑。Parquet 文件布局本身不提供数据库事务、授权、快照发布或自动并发合并。若数据需要跨文件一致发布，必须有真实版本清单/原子发布机制及可恢复边界（R2），不能读取半组文件当最新。

## 5. 最小选择及限定核验（NOT_RUN）

从一个真实问题记录：权威身份、读取/写入路径和分布、共同不变量及可见历史、延迟/恢复/保留约束、物理负荷，再比较最小候选与反转条件。单一事务库可同时服务大部分普通工程；只有新约束及负荷真实存在才引入专门读投影/存储。纸面独立 Oracle：P/Q 名称共享冲突与合法历史复制；图路径2/独立末端1；容量1200/400、均匀与偏斜；四流全局前三及缺桶；写/空间放大和列值字节。实际数据库、文件、并发、故障、性能均 NOT_RUN。非关系选择不等于无 schema 或无事务。
