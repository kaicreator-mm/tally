## 1. 生命周期的决策与反馈

生命周期不是每项目强制按相同阶段完成全部文档。对需求探索、方案选择、构建/获取、集成验证、运行维护、退役等实际活动，明确要解决的不确定性、受影响使用者、输入与输出的事实、下一活动依赖以及裁决责任。活动可重叠和迭代；但依赖尚未满足的不可逆动作不能先执行。NASA Systems Engineering Handbook 6.1 将技术规划与总体项目规划区分，技术工作应与风险/评价反馈和各生命周期目标衔接；这里借鉴原则，不把其17个技术过程或机构要求推广至全部软件。

教学：企业需要在多网点查询库存并持续支持不同设备。初期需求有未知：离线必须能出库还是仅申请？供应商 API 是否有权限和真实效果查询？先调查关键业务规则，设计小原型验证最不确定接口；获得足够证据后冻结受影响合同及验收判据，继续并行实现无依赖部分。若原型失败，不把它包装为生产承诺；若后期发现供应商不支持租户隔离，重审受影响接口和购买决定，不因为已花钱就保持失效前提。单一脚本的明确格式修复可一次交付，无须套用复杂采购或多级计划。

## 2. 自研、购买、外包、复用的可比较边界

| 方案 | 主要控制与未知 | 需要的证据 |
|---|---|---|
| 自研 | 控制源代码与变更但需长期能力、维护与运行资源 | 关键技术可行性、真实人力与依赖、维护/替代方案 |
| 购买现成 COTS 或订阅 | 上市时间可能短；功能、许可、版本、数据与支持受供应商约束 | 实际候选版本/部署模式/许可、真实接口、样例数据及差距 |
| 委托开发/运营 | 技术交付与运营责任可外部承担；仍有产品责任与合同风险 | 交付物身份、权责、独立验收、升级与故障协作、知识交接 |
| 复用现有组件 | 已有历史证据但新环境/需求可能不匹配 | 当前适用性、版本兼容/权限、修改与分发约束、可维护性 |

先定义同一业务场景和必需约束，再比较候选；不把某产品的营销承诺当测试，也不把开源等于零成本、拥有源码等于拥有知识/维护能力。试用版、现有部署与拟购版本可能不同；记录身份、选项依赖、环境、未知、证据来源、有效期和裁决人。NASA SWEHB Ver D 7.03 指导从需求、方案比较、供应商与风险到验收和结束；其政府合同特定审批与等级要求仅限适用组织。

教学粗略三年未折现成本，单位为假定资源单位，所有必需能力可实现且服务水平相同才可比较。自研初始70、每年维护18、退出10，总134；订阅初始12、每年24、迁移退出20，总104；若订阅每年另需12填补接口差距，则140。未确认退出费为未知而非0。成本排序在每年额外差距成本10时相等（104+3×10=134）；更高时原自研成本较低。并非真实报价、净现值或决策结论；折现、机会成本与估算不确定性留工程经济专题，RISK 原有权威不变。若供应商不支持必要权限隔离，低成本不能抵消硬约束；选择自研也须验证能力，不自动 PASS。

## 3. 将供应商能力变成可验收的交付合同

供应商评估区分陈述、正式承诺和实际证据。针对获权需求建立能力映射：目标版本/功能、实际运行/数据地域（如适用）、接口/权限、支持环境、依赖与容量、升级/弃用、故障处理和数据权利/退出。用少量真实区分性任务测试候选版本，要求负例、异常及禁止效果，不能只观看供应商控制的正常演示。证据无法获得时保留未知并决定是否可接受；合同条款、隐私/许可由有权专业人员确认，不自行编造法律要求。

SLA 是双方约定的服务责任，不等同内部 SLO 或实测 SLI。若教学合同约定一30天连续服务窗、全时段服务可用目标99.9%、无排除，则时间预算43.2分钟（43200×.001）；若累计不可用50分钟，则不满足该目标。若经授权排除计划维护，须按合同重算时间窗及分母；不能在事故后任意排除。按成功请求定义的SLA必须用请求分母，不能换算成同一停机分钟数。合同还应写测量位置（客户端还是供应商端）、起止/时区、故障/降级与排除、报告数据及纠纷处理、通知/响应与恢复目标。赔偿条款不能使失去的数据或越权结果成为可接受；具体商业条款需另行授权。参见 [T33a-1](T33a-1-reliability-fault-analysis-recovery.md) 的RTO/RPO及 [T28c-1](T28c-1-product-quality-assurance-evaluation.md) 的评价证据。

## 4. 监控、验收、运行移交及退出

| 活动 | 可观察完成事实 | 典型假完成 |
|---|---|---|
| 合同准备 | 获权范围、交付清单、版本、验收判据及数据/支持责任 | 报价单写“全支持” |
| 持续履约 | 真实里程碑产物、偏差、变更影响和风险处理 | 只收进度百分比 |
| 产品验收 | 实际待交付版本在规定环境通过独立业务/接口/权限/恢复检查，记录未决及有权决定 | 供应商报告全绿、不同版本演示 |
| 运行接手 | 运行配置、依赖、授权、备份/恢复和支持联系人，接手者独立完成合法任务 | 仅文档交接会议 |
| 替换/退役 | 数据及必要元数据可迁移并对账，新旧消费者衔接，撤销旧权限及获权处置旧副本，正式结束责任 | 能下载CSV就声称可替换 |

供应商更换不等于一次文件复制：教学系统导出订单表但没有订单与付款的稳定关联ID、政策版本、时区、未决效果和审计信息，无法判断新系统能否保留语义。先在可控范围试迁移：冻结数据模型/映射、来源快照/增量位置、独立身份与余额/关系/状态对账，核新系统合法业务操作、旧凭据拒绝与故障回退。决定停写、双运行或受控切换需根据真实业务一致性合同；不能双写即宣称原子。明确移交期间支持、备份保留/删除/撤权的责任与授权；保留旧记录可能为合规或恢复所需，不机械删除。合同结束、产品验收和安全退役是不同事实，未交付/未验收/未结束事项需明示。技术方不能替代合同授权方。

## 5. 学习反例与独立 Oracle

| 教学问题（NOT_RUN） | 可区分证据 |
|---|---|
| 订阅低价但缺必要权限；自研估时无真实人员 | 独立获权需求与实际版本负例、资源/能力证据；未知不能晋升 |
| 30天服务窗累计50分钟失败，供应商只统计成功请求 | 冻结SLA口径与独立事件时间线，保留失败；按合法排除重算 |
| 合同要求交付V2，实际验证V1 | 制品身份、独立安装与消费者行为；V1报告不能证V2 |
| 导出缺ID或未决效果，迁移行数相同 | 权威源与目标逐身份/关联/语义及外部结果核对 |
| 供应商已交付但接手者不会恢复，旧密钥仍可写 | 接手者隔离恢复、真实权限负例与服务移交收据；不能宣称退出 |
