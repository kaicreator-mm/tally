## 1. 从实际问题选择知识，不按目录逐章注入

先识别目标、受权约束、当前消费者与环境、权威状态、已有实现、真正变化方向及失败后果。未确认事实保持 UNKNOWN；只向有权来源澄清会改变决定的事实。候选知识的采用理由必须指向当前合同或风险，不能只匹配函数名。K03 的 [R19 抽象选择](../../../v2.1.2/software-engineering-knowledge/K03/advanced-abstraction-level-selection-and-semantic-reuse-r19.md) 保持原粒度决策机制；K02 [正交边界](../../../v2.1.2/software-engineering-knowledge/K02/advanced-extension-authority-state-and-consumer-boundaries.md) 保持依赖/授权/数据/消费者四个独立问题。本章以真实情境组合它们，不复制选择矩阵。

## 2. 组合演练 G1：本地导入工具与运行配置

教学合同 G1（假定已授权）：单用户本地应用可在无配置时打开 UI；配置选定一个目标目录与本地数据库，明确点击应用后才激活；无合法激活禁止写。导入一个有上限的 UTF-8 CSV 文件，合法行含唯一 itemId/名称/正整数数量（教学单位为件）；空文件/重复ID/非法字段/现有ID冲突全部拒绝；整次导入要么新增全部行，要么不新增任何行。导入完成前不发布成功；不用覆盖现有数据，无远端 Effect。小文件上限属于教学假设，未指定实际数值；超限拒绝，用户可查询原因。明确允许配置失败保留上一个合法激活版本，未激活新配置不能偷偷替换旧上下文。

- 需求：选 [T24a](T24a-requirements-discovery-negotiation.md)、[T24b-1](T24b-1-business-rule-decision-contracts.md) 和 T24c，分开输入形状、业务唯一性、运行许可及用户可恢复错误。真实产品中上限/编码/冲突政策须获权，不能默认本例。
- 架构：只有一个目标和数据所有者，可用单进程单 DB，配置读取与激活明确分离；导入动作捕获激活身份（目标和版本），本例约定激活切换等待正在提交的导入结束或其安全取消后才生效，不并发替换目标。若无法证明旧资源已停止，不确认新激活。无独立插件或远程消费者，不需要 Provider Registry 或跨进程消息。
- 实现：候选 A 在一个导入领域模块内解析、校验、事务写入；候选 B 每行调用通用 CRUD 并将已写行逐个报告成功。选 A 因合同为整批原子而 B 在中途失败泄露部分提交。解析可用成熟库并受限读取，保留合法字段语义；所有必需校验包含事务内最终唯一约束或足以保护当前状态的机制。纯解析/字段校验有真实独立复用时可局部抽取，不把领域约束下沉到任意 CSV 通用解析器。
- 验证：使用实际支持的本地 DB 和独立预期数据，输入两合法行期望均新增；末行非法、重复ID、已有ID冲突、输入截断/非法编码/超限、事务中第二写入失败均期望无新增。尝试未配置写、切换激活目标时导入以及取消后的最终状态，核数据库身份、内容、实际事务结果与资源关闭。响应丢失时查询实际提交事实，不凭 UI 报错自动重试。
- 交付/维护：以 [T28a-2](T28a-2-consumer-contracts-installed-artifacts.md) 核实际安装首启、配置和导入目标路径；[T31a-2](T31a-2-configuration-management-baselines.md) 保留版本、输入和运行制品身份。若后来获权增加 TSV 格式但相同领域合同，抽取窄解析器并保持领域操作；若新格式允许部分成功，它不是同一个导入合同，需单独命令或显式获权行为。观察实际变更范围与回归，不以提取接口数量称收益。

纸面区分：原 DB 有10条，文件3行、第三行非法；合法全量提交合同下最终仍10条，而逐行保存得到12是反例。若合同改为明确允许逐行部分成功并返回逐行结果，12条可能合法，必须更改验收而不是套用旧事务策略。当前没有实际运行、真实 DB 或测量。

## 3. 组合演练 G2：异步刷新、查询与版本化投影

教学合同 G2：服务按租户维护权威源条目；用户请求刷新一个来源，或批量选择当前有权的到期来源。请求可在持久受理后返回任务 ID；一个成功任务只表示其目标来源按获权版本更新，批量结果逐项成功/失败/UNKNOWN，非全量原子。UI 可显示明确版本和陈旧状态的投影，不允许依据缓存作新的受保护写决定。外部 HTTP 读取和本地写分开；只有本地权威状态提交后才能报告相应更新。若产品改为同步短请求，则不必新增调度服务。

| 真实边界 | 设计选择及排除 | 正反向可区分事实 |
|---|---|---|
| 任务受理 vs 完成 | 单/批共享领域刷新操作，入口各自定义返回合同；持久接纳记录+有限 Worker，队列/拒绝依真实容量 | 持久受理后崩溃仍可查询任务；若仅起 goroutine 后返回，不满足持久受理 |
| 查询与权限 | 按实际租户/来源过滤、稳定分页语义及真实迭代失败；缓存 key 包含权限相关范围及必要版本或仅缓存公共数据 | 同名来源跨租户不可访问；第二页失败不得称全部已选；旧权限缓存不可授予写 |
| 并发更新 | 同一来源按获权顺序及当前版本条件更新；旧 Worker 不能覆盖新结果；不得把限制并发当唯一提交 | 两任务读 v7，只有满足当前版本的提交可晋升；迟到旧响应不得覆盖 v8 |
| 投影同步 | 若只有当前读，直接读权威；若需异步投影，按实际协议保证一致基线/增量、持久应用 checkpoint，与 UI 版本分离 | 接收但未应用就崩溃不能越过记录；无法证明连续性重建，不能静默跳历史 |
| 取消/恢复 | 明确未受理、已受理、获许可、执行中、已提交/未决；取消信号不撤销已提交；未知保留 | 任务已提交后取消，实际 DB 保留新值；已排队取消按合同观察终态 |
| 运行质量 | 记录计划/接纳/完成/失败/在途和资源需求，按 [T33b-1](T33b-1-performance-queueing-capacity.md) 选择负载；[T33a-1](T33a-1-reliability-fault-analysis-recovery.md) 验实际恢复 | UI绿但未决来源仍旧，不能宣称刷新全部完成 |

候选对照：短单入口直接刷新，不引入持久队列；有重启后仍须追踪的明确异步合同则持久受理及执行恢复是必要能力，内存队列本身不够；分布式复制只在单节点边界不满足真实场景时再论证。若读取外部 HTTP 本身有计费或其它效果，先确认重试及授权，不能只因名为 GET 推断无效果。对重复任务、过期版本/租户、崩溃窗口、取消与错误必须以独立权威记录/实际任务身份和 UI 可观察值作 Oracle。

历史 T19-C01 Miniflux v2.2.3 的单条/批量204完成边界不同、无缓冲通道与 Worker 数、查询迭代错误及共享 RefreshFeed 是已登记的局部机制与风险分析；本例的持久接纳、投影 checkpoint、租户写约束为新教学合同，不是声称 Miniflux 已提供这些能力。T08-C01 调度 tick 与执行不同，T05-C08 取消与完成不同；[T20-C03](../casebook/waves/T20-historical-abstraction.md) 补 wrapper 清队列能力，但只清仍在队列未获许可项，不能取消已获许可项；这些历史参考支持边界判别而非本例实现证明。
