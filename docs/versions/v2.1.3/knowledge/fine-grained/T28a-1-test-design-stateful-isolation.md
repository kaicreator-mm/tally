# T28a-1 · 测试选择、状态模型、生成式验证与隔离

归属 K05.F2/F3/F4；#563 有限第三批任务，原稿 #7167352369，#588 延续跟踪，K01 需求/K03 实现/K06 诊断。复用原 [ORA](../../../v2.1.2/software-engineering-knowledge/K05/advanced-oracle-adequacy-and-test-selection.md)（b4c0fc78b86dca163d3f46deb223115e583ed716）L7–34 与 [GOLD](../../../v2.1.2/software-engineering-knowledge/K05/focus-f4-2-golden-snapshot-evidence-freshness.md)（f8a51a301d0b7103b66b95fa4adb9d416166ea06）L7–33；不复制覆盖/Golden 基本定义。以下补选例到独立预期、生成序列、数据隔离及可重现失败，所有例与 Oracle NOT_RUN。

## 1. 先写故障模型，再选测试
假设有权教学合同为“登记组合 (project,device) 唯一，同一对象重复登记返回已有记录，不允许新增第二条；其他项目可登记同一设备；无权主体不能读写”。合同可变，测试不自行选择业务规则。正常输入、边界、无效形状、状态、并发、权限与失败不是同一维度。先列可能错误及区分它的最小输入，再决定单元、组件、真实消费者、集成与端到端；不能要求每条相同测试都跑所有层。
| 缺陷假设 | 区分性输入与预期 |
|---|---|
| 键遗漏项目 | 同设备登记到 P1、P2 均成功且为两条 |
| 键遗漏设备 | P1 下 D1、D2 都能登记 |
| 重复产生新记录 | P1/D1 两次，返回同身份且只一条 |
| 权限只在 UI 检查 | 直接合法测试入口尝试无权变更，预期拒绝且数据无副作用 |
| 状态未重新检查 | 预先合法，执行前项目变为不可登记；按合同检查拒绝 |
| 查询把未知当空 | 模拟迭代终止错误，不能报空集合成功 |
测试代码应有独立预期、明确观察点、必要时负断言（未修改其他记录、未创建新外部效果）。仅断言 HTTP 200 或 mock 调用次数不能证明上述持久事实。

## 2. 组合测试、边界和状态路径
划分输入类时应考虑真实行为区分：有效整数、0、负数、最大值、超过范围、空/缺失、字符串数字，不为每种长度随意增加用例。边界值来自有权规格，不是源代码当前 if。决策表中不可达条件需写明约束，不删除关键业务合取；ORA 已有 pairwise 不能覆盖三元拒绝的反例。状态机测试除了单步迁移，还应检查前置路径、非法转移、重复动作和恢复历史。例如登记→删除→重登，旧对象 ID 是否复用由合同决定，不从实现生成预期。状态覆盖不等于所有历史、并发交错或数据空间覆盖。

## 3. 性质、变形、差分与状态模型
性质测试：对一类输入检查不变量，例如区间集合 add 的 AF 等于原集合与新增区间的并集（[T27a](T27a-detailed-design-representation.md)）。变形关系：无绝对答案时使用合同已知的输入变换关系，例如集合重复添加同一元素不改变集合内容；如果记录审计历史或顺序属于抽象值，则不能直接断言所有观察均不变。差分测试：比较独立参考实现与目标实现的共同语义子集，两个实现同错、版本和合法输入范围不同都可能掩盖或制造差异。

原创有限状态模型：用小集合存 (project,device)，操作 add、remove、list；测试数据有两个项目、两个设备和已定义权限状态，按有权规则更新参考集合。每一步在目标实际返回并到达约定观察点后核成员关系、重复及未授权负断言；不从目标数据库读取后填进模型作 Expected。测试程序生成操作序列，记录可重现的缩减后反例（不保证全局最短）。例如 add(P1,D1),add(P2,D1),remove(P1,D1),list(P2) 应仍含 D1；仅单步成功不能识别错误的全局删除。Hypothesis 6.170.17 文档的 RuleBasedStateMachine 通过 rule/Bundle 组织操作及复用数据，并用独立模型比较，invariant 可在步骤间检查约束。生成有限样本不是证明所有序列；缩减后要保留合法前置和可重现条件。对并发 API 还需额外调度控制及独立线性化/允许历史判定，不能把串行模型直接当并发证明。

### 3.1 成员、记录身份、持久基数与 Effect 的不同 Oracle（FG-05）

原集合仅定义成员关系 M，不代表记录 ID 或原始持久记录数。教学合同：一次成功登记首次返回的合法身份 r1 可作为后续关联锚点（先校验身份类型、项目/设备归属与实际独立读回；不从被测输出推导业务成员或预期记录数）。参考模型另维护每个仍存在组合的首次合法身份；后续重复登记必须返回同一身份，删除后是否重用身份需另定合同，不臆造。另由有权的独立测试观察入口读取同一提交边界、同一 scope 下未去重的实际持久记录，验证每个期望存在组合恰一条、缺失组合零条、记录身份与锚点相符。若底层不可观察，只能报告公开投影与身份关系的限定验证，不能报持久基数已证明。未授权调用前后比较授权范围内独立读回的成员、身份、计数、应保持的状态及禁止的业务 Effect；拒绝审计日志等获权效果可以允许，不能要求所有字节不变。外部 Effect 需独立权威观察，否则 UNKNOWN。

| 教学错误实现 | 集合模型 | 新增区分性 Oracle（NOT_RUN） |
|---|---|---|
| 重复登记将 r1 换为 r2，组合不变 | 通过 | 重复返回及独立读回身份必须仍为 r1 |
| 持久层插入第二条，但 list 去重 | 通过 | 原始记录计数应为1，实际2时失败 |
| 无权调用返回拒绝，却改备注或发送禁止的通知 | 成员不变 | 独立前后状态/禁止 Effect 比较；无外部证据不能标 PASS |

上述状态模型是串行教学，实际并发需明确观察点和允许历史；不是已运行测试。基础定义见 [K05 卷一](../../../v2.1.2/software-engineering-knowledge/K05/foundations-deep-dive-01.md)、[卷二](../../../v2.1.2/software-engineering-knowledge/K05/foundations-deep-dive-02.md)。

## 4. Fuzz 与失败归类
生成式性质测试倾向由领域策略构造有意义输入，覆盖引导 fuzz 可通过变异语料寻找新路径；二者可结合。Fuzz 的判定不是只有“不崩溃”，可检查超界拒绝、解码往返在指定域内相等、资源上限和不得产生非法副作用。教学选择二进制 parser：固定最大输入和合法格式，初始语料包含空、截断、合法最小帧、未知类型、超长长度字段；独立参考读取器/边界规则判定。对于任意字节，允许明确格式错误，不要求都解析成功；对 Unicode 仅按定义的有效字节域要求严格往返。异常分类：预期拒绝不是 bug，未预期异常、错误结果、hang/资源耗尽、无权副作用需要分别定位；确认最小输入、版本、环境，保留种子及真实运行条件。Go 官方 fuzz 文档建议目标快速、确定且不保留调用间共享状态；失败输入可成为回归语料。不是一次 fuzz 无失败证明无缺陷；未运行不报告覆盖率或失败数。

## 5. Fixture 生命周期与依赖替身
Fixture 应有明确创建、可见性、重置、清理和失败处理。pytest 8.3.x 文档的 yield fixture 在成功进入 yield 后执行相应 teardown；在 yield 前异常则该 fixture 的后半段不会被执行，已成功建立的其他 fixtures 仍按框架规则清理。将有副作用的获取拆成可独立清理的步骤，或在获取后立即建立 try/finally。若创建 A 成功、创建 B 失败，不能依靠还未安装的 B 清理回调处理 A。不要让 session 共享可变数据污染每个测试；高成本只读资源可共享，写入使用独立 schema/目录/事务等隔离并核真正范围。回滚本地 DB 不保证远端效果回滚。
Stub 提供预定回答，Fake 实现简化可运行机制，Mock 检查选定交互，真实组件验证实际兼容/运行合同；不同术语体系有差异，此处以测试职责区分，不强制类名。替身不能证明真实 DB 隔离、文件持久、第三方幂等、包安装等。若业务依赖外部错误形态、时序或取消，应有相应替身及真实合同/集成验证；不把实现调用顺序的脆弱断言当业务 Oracle。默认避免向生产发送真实请求/支付等不可逆操作。

## 6. 时钟、随机、并发与发现
业务有效时间、计时和测试调度不同。注入可控时钟用于 TTL/期限，另核真实运行时/调度行为；假时钟并不使外部 IO 自动变快。Seed/样本语料、版本、环境、时区、数据初态和并发交错共同影响复现，单 seed 不足以固定调度。优先用明确 barrier/event 控制竞态，避免仅 sleep 期望调度。对 flaky 先保留首次失败与重试结果、区分不稳定产品或测试/环境，不能重跑变绿后删除失败记录。检查发现的测试身份、选择条件、skip/xfail 及实际运行结果，零测试通过不等于通过；Golden 更新按原 GOLD 权威。测试资源清理失败同样是事实，不能掩盖主故障或宣布整个测试环境已恢复。
