## 1. 身份、来源与质量是不同事实

在获权的产品资料库中，源 A 负责商品说明，源 B 负责检验记录，目录只拥有可搜索投影。假定商品实体 key=(tenant,productId,generation)，来源记录 key=(source,sourceId,sourceVersion)，每次转换记录实际 source 输入、transform 版本、runId、输出身份/版本和观察边界。不同源的同名商品不能靠字符串自动合并，映射需有权依据。区分源业务有效时间、采集时间、转换时间和版本；迟到事件不按采集时间覆盖新状态。

OpenLineage 1.55.0 object model 将 Dataset、Job、Run 分开，并允许 Job 的源码位置/版本 facet、输入质量指标/断言和输出统计；其事件描述观察到的血缘，不自动证明数据正确或已安全删除。具体字段级血缘、运行完整性、去重及采集者信任另核。用其启发记录实际输入版本和运行身份，而不是以一张血缘图代替对账。

教学：A 的 R1 12行，R2 11行，B 有4条检验。导入接受10、拒绝1、未读0，须满足 11=10+1+0（按互斥且同观察边界的输入计数）；不能直接断言目录只有10商品，因为一商品可有多个来源记录，亦不能把 B 的4条当4商品。质量断言分别检查唯一键、允许空值、单位、映射合法、版本和完整性；计数相同但商品互换仍错误。异常记录保留获权身份与理由，拒绝/修复归责任源，禁止静默补造或将 UNKNOWN 变为零。

## 2. 真实冲突机制及其限制

CouchDB 3.5 conflict model：同节点用旧 revision 更新可收到409；独立副本分别从共同祖先写入并复制后可保有冲突分支，普通 GET 与 view 只读确定性选中的 winner；可查 conflicts 或 open_revs 获取其它叶；应用合并后可删除其它冲突叶，删除叶仍是带删除标记的历史。压缩与 revision pruning 不等于永久保存全部历史。该模型不是普遍的最后写入时间获胜，也不提供跨业务字段自动合并。确定性 winner 是展示选择，不是有权业务解决。CouchDB revision 不是下列教学的业务整数版本或向量时钟；不能把 CouchDB 的 revision token 排序解释为跨节点因果。

## 3. 具体教学冲突与删除政策

假定中心权威目录允许离线设备准备补丁，正式提交需中心授权。源 A 商品 P generation1 version7，name=N，price=100；D1 改名 N1，D2 改价120，都基于 v7；中心已明确允许不同字段且不违反联合约束时进行三方合并。先 D1 提交 v8，D2 基于 v7 对照 v8，仅价字段变化且无共同约束冲突，当前授权有效才可作为新操作提交 v9 (N1,120)；若双方同改 price 为110/120，则保留候选与冲突，交权威人工决定，不能以设备时间决定。若修改字段分别为数量及单位且联合不变量相关，也不能因字段不重合自动合并。无中心权威的真正多主系统需另定因果/冲突政策，此例不证明多主收敛算法。

删除政策教学：源 A 权威删除 generation1 v10，中心同时撤销该 generation 的当前可见性、登记持久 tombstone (key,v10,source,operationId)，通过 [T27c-3](T27c-3-reliable-messaging-outbox-offsets.md) 的可重复事件传播给目录。离线 D2 带旧 v7 恢复并重发更新，必须因 generation1 已删除拒绝，不能用新到达时间或空目录自动重建。若允许同 productId 再创建，须有权新 generation2；旧事件、旧缓存、旧设备不能写 generation2。删除一来源不等于自动删除其它责任源的独立合法记录；目录按产品映射和政策撤回受影响投影。记录删除事实不代表所有副本、历史备份或外部存储物理清除。保留期限、合法恢复/清除、隐私义务由权威决定，未获权 UNKNOWN。

墓碑保留须根据可重放事件、最长允许离线/重新加入合同及备份恢复策略；如果有限期限到期后旧设备仍可能写，不可仅按 TTL 删墓碑。选替代：保留最小拒绝身份/代际水位（政策允许），或强制旧设备重新登记/全量校验且旧写权限确实失效；如两者均无法证明，不能承诺无复活。删除历史与当前读权限分开，保留审计元数据本身也需合法范围。

## 4. 恢复与独立验证（NOT_RUN）

| 场景 | 独立 Expected |
|---|---|
| 合法不重合补丁 / 同字段或联合约束冲突 | 中心版本、实际授权、base/diff、政策独立比对；前者得 v9 (N1,120)，后者不自动覆盖 |
| 删除 v10 后旧 v7 到达；同 ID 新 generation2 | generation1 不复活；旧写不命中新身份；真实有效新建按政策 |
| 目录丢失、备份只到 v9 | 可在隔离环境还原 v9 历史作恢复材料；在对外开放当前目录前应用 v10 删除或重新核权威当前状态；不能把恢复旧历史当撤销删除 |
| 质量断言 11行中错换两商品 / 缺一来源 | 逐来源身份、版本、转换 run 及映射，隔离错误；不以总量相等为通过 |
| 部分投影 ACK/重复事件/删除传播超时 | 权威删除已发生、各副本应用/未决分别记录；核持久进度、重放与当前读授权，不由发送确认宣布全删除 |
| 墓碑退休后旧设备重入 | 验证实际拒绝/重建前置；保留期未知时保留未决，不声称无限安全 |

选取恢复边界时按实际 RPO/RTO、备份一致性、删除规则和数据范围核对；本例不实际运行恢复。单中心、冲突人工协调和自动三方合并的代价取决于离线写需求及权威规则，简单只读缓存不需多主机制。
