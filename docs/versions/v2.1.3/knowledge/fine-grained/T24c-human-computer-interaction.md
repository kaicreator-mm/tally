# T24c · 用户任务、交互合同与可访问的纠错

归属 K01 用户目标、K02 交互合同、K03 实现、K05 评价；#586 / T23 HC01–04 CORE。复用 [T24a](T24a-requirements-discovery-negotiation.md)、[K03 错误语义](../../../v2.1.2/software-engineering-knowledge/K03/advanced-error-semantics-observability-and-validation-proof.md)、[T07-C07 表单](../casebook/waves/T07-business-functions.md)。后者是既有源案例解释（未重新运行），不是可用性证据。本文案例、测量及 Oracle 为原创教学 NOT_RUN。

## 1. 任务和心理模型不是界面组件

用户任务由目标、参与者、开始条件、子目标、环境、资源、例外、完成事实组成；心理模型是用户对操作与后果的理解，不一定与内部实现一致。用户说“保存”可能指本地草稿、服务端持久化或正式提交，不能用按钮名称掩盖差异。

例：报销申请从找到原始凭据、填写、校验、确认到查看处理结果。实际用户可能在移动网络断开、使用键盘或屏幕阅读器、切换语言；任务还包括离开后继续、纠正错项、查询拒绝原因。任务图：
- 准备：有哪些资料与角色？无资料如何继续？
- 填写：哪些字段可自动带入、哪些需明确确认？
- 检查：局部格式与跨字段/业务规则；能否定位错误？
- 提交：服务端是否接受，是否已持久化，是否有唯一确认标识？
- 跟踪：已提交、处理中、拒绝、未知结果、再次打开。
内部状态不必全部暴露为枚举，但用户看到的结果不能与真实状态冲突。

研究应观察实际操作过程，区分使用困难与需求变化。用具体任务而非指示按钮路径；记录用户目标、操作、求助、误解、恢复、是否完成。不同设备、经验、语言及辅助技术需要代表性覆盖；不能以少数测试用户推断所有用户。

## 2. 信息架构与交互选择

信息架构（内容的分类、名称与位置）回答用户怎样找到任务及信息；导航回答怎样移动和恢复位置；反馈回答当前状态及后果。按用户任务组织，而非按数据库表或后台微服务命名。

| 设计候选 | 适合情境 | 失败与反向条件 |
|---|---|---|
| 单一直接操作 | 简短、熟悉、低风险 | 不适合复杂依赖、不可逆操作 |
| 分步向导 | 有真实顺序及复杂输入 | 熟练用户批量工作可能更慢；跨步返回和恢复不能丢数据 |
| 搜索/过滤 | 对象较多、用户知道线索 | 空结果应区分未搜索、无匹配、失败和权限范围 |
| 列表+详情 | 同时比较多个实体与操作 | 小屏/键盘导航需保持位置；不要用一屏堆所有信息 |
| 明确确认或可撤销 | 不可逆或高代价动作 | 重复无价值弹窗会产生习惯性确认；撤销需真实可逆 |

导航含义须一致；同一功能避免不必要的名称变化。用户返回列表要能理解当前筛选/排序、选择对象及变动；深链接/刷新恢复仅在产品明确需要时支持。不是每个应用都需导航框架。CLI 可能通过命令、help、可解释的输出和退出码实现类似任务指导，而非照搬 Web 页面布局。

## 3. 交互状态与异步反馈

分离业务事实、当前视图、编辑缓冲、请求状态及缓存；派生信息尽量从权威数据计算，不独立维护第二真值。教学状态：
```text
EDITING -> VALIDATING -> SUBMITTING -> ACCEPTED -> RESULT
                   -> INVALID
SUBMITTING -> FAILED_KNOWN / OUTCOME_UNKNOWN
EDITING -> DISCARDED (only local draft)
```
状态图不是通用 API。同步短操作可能只需输入/结果；异步需明确等待、可取消的对象、状态来源、失败后安全下一步。若重复提交被允许/禁止，实际业务合同决定去重范围。按钮禁用只减少当前视图重复点击，不保证多窗口、多客户端、网络重放不会重复执行。

用户查询 A 后查询 B，A 较晚返回；可用当前请求身份校验，使 A 的结果不能覆盖 B 的视图。取消旧请求只是节省资源的候选，不能假设远端从未执行。显示旧数据时标明刷新状态或时效；不能用“正在处理”长期掩盖失败；进度只有可测单位才能显示百分比，否则显示阶段/不确定状态。

## 4. 输入和错误恢复

字段输入形状、跨字段约束、业务当前状态、授权四层分别验证。T07-C07 已有实际字段/表单/post-clean 观察；此处补用户纠错合同。客户端早校验提高反馈速度，服务端/业务执行点仍承担权威检查；服务端错误映射到可修改字段或整体任务，而非直接展示堆栈/密钥。

| 失败类型 | 合理反馈 | 不应做 |
|---|---|---|
| 字段格式 | 指出字段、原因、可接受格式或修正提示 | 只变红、无文字、静默替换含义 |
| 跨字段矛盾 | 解释两项关系、标出可改对象 | 只标最后一项，导致反复试错 |
| 业务条件已变化 | 指出当前状态、允许操作及必要重新确认 | 用旧客户端验证结果当提交资格 |
| 权限拒绝 | 给用户可知的范围/合法求助入口 | 泄露其他租户数据或绕开限制 |
| 连接失败/UNKNOWN | 区分确定未提交与未知；提供查询/人工核实 | 一律提示重新提交 |
| 草稿离开/超时 | 按产品隐私和保存政策保留合法输入或明确丢失 | 自动跨账号保存秘密或未经许可持久化 |

撤销本地编辑可恢复旧缓冲，撤销已提交业务可能需要获权补偿；历史记录不能无条件删除。对高风险操作，可比较预览确认、可逆提交、输入检查，选满足真实合同的方法，而非所有按钮弹窗。

## 5. 可访问性与文本

WCAG 2.2 Web 规范中的 SC 2.4.3(A)、2.4.7(AA)、2.4.11(AA)、3.3.1(A)、3.3.2(A)、3.3.3(AA)、3.3.4(AA) 分别提供焦点顺序/可见、焦点不完全遮蔽、文本错误提示、标签/说明、已知纠错建议和指定高风险输入的防错条件。级别、触发条件与例外应以正式规范为准，不能声称只满足这些条目就全站合规。实际交互候选：
- 用有语义的控件、可访问名称和关联错误信息；键盘可操作，焦点转移保留任务顺序，打开/关闭临时界面后关注点可理解。
- 不依赖颜色或图标作为唯一含义；错误文本可被阅读，必要状态变化可被辅助技术获知。避免每次输入都打断用户。
- 保留非敏感且仍合法的输入；按实际政策清理密码、令牌等秘密。屏幕阅读、键盘、缩放、不同屏幕与文字方向需实际验证。
- 文本长度合同区分编码字节、Unicode code point、用户感知字符（通常可用 extended grapheme cluster 近似，依版本及 profile）；显示截断不要切断组合序列。例：e + combining acute 是两代码点，但默认分段视作一个 extended cluster；不能凭字符串单位长度判断用户输入字符数。IME 组合输入期间不要把未提交的中间文本当最终错误。排序/比较需指定 locale、归一化及业务身份规则，不能把显示等价自动变成账户身份等价。
- 日期、货币、数字、时区的用户呈现应保留真实单位与底层值；不要按当前语言猜测 01/02 的实际含义。具体 Unicode/locale/runtime 实现留 T25b。

此处 Unicode 引用固定 **UAX29 rev47**（实际读 §2、§3 标准，Unicode 17 系列）；不声称读到 rev49 原文，不宣称某 JS/Python runtime 已支持指定版本。W3C 是 Web 范围，不自动要求 CLI/嵌入式相同控件。

## 6. 可用性验证与反例

用用户目标作为任务，如“提交有效申请并确认其状态”，而不是“点击第二个按钮”。同时记录完成、错误、求助、时间、主观困难；分母、样本、任务环境与失败定义明确。试验人员不要代替用户完成任务；对真实敏感数据需独立许可与安全条件，否则使用可控假数据，承认真实性局限。功能自动化可验证接口/状态；人工/辅助技术检查验证可访问行为；实际用户观察用于发现任务理解困难；不能互相替代。

| 候选观察（NOT_RUN） | 独立预期 |
|---|---|
| 键盘从表单首项到提交，再返回错误 | 顺序保留语义/可操作性，错误对象可识别、焦点可见 |
| 输入 e + combining acute、混合方向、IME 中间态 | 按已确定单位/locale 保持用户意义，不截断错误位置 |
| B 查询先于 A 响应 | 当前 B 视图不被过期结果覆盖 |
| 超时但服务器已提交 | 不显示确定失败或诱导盲重试，提供合法核实 |
| 切换角色或会话 | 不显示不再获权的数据，不把旧草稿泄露给另一用户 |

仅原型看起来可操作、CSS 颜色正确或一个自动扫描工具无报错，均不证明完整可用性/无障碍。样本与测试版本保留，未知不得晋升。后续需具体平台规范、实际用户/辅助技术及产品需求。
