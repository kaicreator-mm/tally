## 1. 从程序文本到可分析模型

词法/语法分析建立程序结构；名称解析关联定义与使用；类型约束限制表达式及操作。抽象语法树 AST 保留语法结构，但语句相邻并不等于实际执行相邻。控制流图 CFG 将基本块（内部顺序执行、进入/离开边界明确的指令序列）及可能转移表示为有向图；分支、循环、异常、返回等可形成不同边。调用图表示可能调用关系；虚分派、反射、动态加载、回调及外部库合同影响其精确性。无异常边的模型只能证明所表示的正常路径，不能证明资源异常释放。

数据流分析关心某个点可能/必须成立的值、定义、初始化、可达性、别名或资源状态等；与业务事件的数据传输图不是同一个概念。前向分析从前驱传播；后向分析从后继传播。例如 reaching definitions 可前向求可能到达定义，liveness 可后向求当前值之后是否可能被使用（在被覆盖之前）。没有使用不代表赋值可安全删除：求值可能产生外部效果、异常或同步。控制依赖决定执行条件，数据依赖涉及读取某定义/状态；程序切片可以辅助定位依赖，但不能把保守包含的所有语句认定为根因。

## 2. 格、传递函数与固定点

教学模型：无异常、整数精确、局部变量、无别名；抽象状态以可能取值集合表示，包含关系为偏序，空集为不可达，全集为未知任意整数。此处不是未初始化状态模型；若需检查未初始化，另加相应状态。抽象域有限化，例如只保留至多两个可能常量，更多则为 top；join 为并集后按域抽象。分析必须过近似所有模型允许的具体行为，不能为获得精确结论直接扔掉第三个值。

```text
entry: x = 1
if b:
    x = 2
else:
    x = 3
join: y = x + 1
```
b 未知，两个分支的出口为 {2}、{3}；合流 {2,3}，赋值后 y={3,4}。若再有第三路径 x=4，按上述域合流 top，不能证明 y 仅为 {3,4}。若实际 b 有约束需显式纳入模型，不从命名猜测。一般前向方程 IN(B)=join(OUT(P) for P in predecessors(B))，OUT(B)=F_B(IN(B))，入口事实单独给定；边可进一步过滤分支条件。工作列表从底及边界事实开始，按变化重新传播。有限高度、单调传递、正确边界及公平处理条件下，这类上升迭代收敛；有环的 CFG 不是错误。

教学循环：x=0；while b: x=x+1。假设任意次数循环，循环头逐次可能值 {0}→{0,1}→top（域上限2）。top 是丢失精度，不是 x 实际可取负数的证据。区间域可保留非负性；无界链可能需要 widening 加速收敛，narrowing 或更精细域恢复部分精度，具体算法有自己的条件。不能同时要求任意复杂程序分析总终止、无限精度及低成本。

## 3. 资源与路径条件

教学资源域：U=未取得，O=持有，R=已释放；分析值为这些状态的集合，未知外部调用可能需要扩大集合。获取成功转移到 O，获取失败保留 U（前提无部分取得）；释放仅对合法 O 转 R，实际失败合同另建。例：获取后有一个 return 分支跳过 cleanup，正常出口可能含 O，提示泄漏。若外部方法移交所有权，分析需建模移交；未知调用不能默认释放，也不能将所有警告宣称为实际泄漏。若异常出口未入图，则即使普通路径证明无泄漏仍无异常保证。

路径敏感分析保留分支条件：x 非负分支中 x>=0 与 x<0 的同时要求不可满足。路径合并降低状态数量但可能产生不可行组合。例：两个条件分支保持 (a,b)=(0,1) 或 (1,0)，逐变量集合独立合并后也包含 (0,0)/(1,1)，因此对 a+b=1 可能误报。可用关系域、延迟合并或路径条件提高精度；时间和内存随分支、循环、调用而增长。

## 4. 抽象解释、符号执行、求解和模型检查的区别

| 方法 | 主要对象 / 能提供什么 | 边界 |
|---|---|---|
| 局部 lint/类型检查 | 语法或类型规则及部分语义模式 | 规则未表达业务属性，绿不等于正确 |
| 数据流/抽象解释 | 抽象域、传递、固定点；在健全模型内保守推断性质 | 精度损失、环境/别名/调用假设，工具未必对全部语言健全 |
| 符号执行 | 符号值、路径条件、反例候选 | 路径爆炸、循环/外部模型、超时 |
| SAT/SMT 求解 | 给定公式及理论的满足性 | 不是自动理解源码；编码和理论必须匹配真实表示 |
| 模型检查 | 在给定状态/转移模型检查安全或时序性质 | 状态空间、抽象、边界、公平性及模型对应关系 |
| 演绎验证 | 证明义务、前后置与不变量 | 规格、环境假设、未覆盖效果，不能替代实际用户目标 |

例如用数学整数推导 x+1>x；在固定宽度机器表示及边界溢出语义下可能不成立。SMT 若以整数理论编码而实际为模2^w 位向量，UNSAT 也不证明真实机器属性。验证 P 时可构造“合法前提 ∧ ¬P”；SAT 给模型中的反例候选，需检查真实可达性；UNSAT 仅对公式证明无此反例；UNKNOWN/timeout 不得当 UNSAT。工具有时不返回模型或证明对象；以实际结果合同为准。

模型检查教学：两个任务共用许可，状态是 (holderA,holderB)，初始 (false,false)。原子 acquire 仅在两者均 false 时允许，release 由持有者执行；枚举可达 (false,false),(true,false),(false,true)，安全性质“不同时持有”成立于此小模型。若拆为非原子 check 和 grant，加入各自已检查状态，两个 check 均通过后各 grant，得到反例。此为纸面模型，不是执行过 TLC 或验证实际锁。即使安全性成立，若调度可无限不选择某任务，也不证明最终获得许可；活性需环境/公平假设。有限步无反例不等于无界性质。

## 5. 选择分析深度与实际诊断

先明确属性、代码语言/版本、环境、入口、依赖模型和错误代价。常规代码用类型检查/合适规则与测试；资源跨分支、复杂错误路径可考虑路径敏感分析；关键协议状态组合可用有界模型先找反例；需更强证明时明确义务、模型及工具可信边界。分析配置、排除范围、版本和超时属于证据。无警告仅证明实际规则未报告；若分析不完整或非健全，不能宣称无该类错误。真正的健全证明也只覆盖其假设及属性。

告警处理：定位具体路径和事实→与真实版本/接口对照→复核可达性与约束→修复或记录有据的误报/未知→独立验证。不要只屏蔽警告或改测试期望。以下 Oracle 均 NOT_RUN：构造缺失 cleanup 分支；加入别名/未知调用检查精度；给定整数最大值比较数学与位向量模型；双许可错误模型必须可达双持有；正常变体在所述有限模型不出现双持有。实际工具运行、机器证明、性能测量、完整形式验证学科留后续任务。
