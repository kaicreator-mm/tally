# T40-R2 · 领域状态、历史事实与表示的逐步精化

#650 / #563；K01 业务语义、K02 权威边界、K03 表示、K09 演进、K05 评价。基线 42332eeb00bc0c1869172a667944e9c02abbc0a7。复用 T27a RI/AF、T25b-2 有效与记录时间、T32b-2 血缘及更正、T27c-3 事件传递、T35-4 审批/导出。此处补同一业务查询合同如何反推表示的最小充分信息及升级路径，不重写事件/消息、时钟或数据库基础。以下原创教学，目标 NOT_RUN。

## 1. 从两个不可区分的历史找出表示不足

判断表示是否足够不能只看字段多少。设 H 为获权历史，R(H) 为保留的表示，O(H,q) 为合同规定的查询或后续决定 q 的结果。如果存在两个合法历史 H1/H2，R(H1)=R(H2) 而 O(H1,q)≠O(H2,q)，则没有仅依赖 R 与 q 的确定性正确实现可以同时回答两者（相同输入不能产生两个必需不同的输出）。这是相对给定观察合同的信息不足证明；若另有可信来源可读取，实际表示加该来源可能充分，不能据此要求复制全量历史。反过来找不到反例也不是充分性证明，应说明支持域和可计算映射。

教学：资料订阅的当前价格为100单位。H1 一直为100；H2 昨日为80、今日变为100。仅需当前价格时两者可以共用同一表示；一旦要求昨日价格，当前行不足。若再要求“昨日结算时系统知道的价格”，仅有最新修订的有效时间线也可能不足。增加表示的原因是获权观察合同变化，不是抽象层数。

## 2. 同一价格事实的三层表示

假定单一价格责任源，币种及单位固定，整数精确金额，日期是已确认业务日；以源提交序号 r 表示获权记录版本，非跨主机时钟。商品价格在下列历史中按生效日确定：
- r1：自日1起100。
- r2（日10获知）：有权更正自日5起应为120。
- r3（日15获知）：更正 r2，自日5起应为110。
日8已按 r1 确认订单100，付款记录100。政策规定已确认订单保留当时成交价；更正价格不自动产生退款/补收。

| 查询 | 正确答案 |
|---|---|
| 日8价格，以 r1 所知 | 100 |
| 日8价格，以 r2 所知 | 120 |
| 日8价格，以 r3 所知 | 110 |
| 日3价格，以 r3 所知 | 100 |
| 日8订单实际成交金额，以 r3 所知 | 100（独立成交事实，不是价格查询） |

第一层仅当前值：适合只问现在且不要求历史/未来价格的合同。第二层有效区间：按当前获权知识保留日1至日5与日5之后的区间，能答历史有效值；若 r3 覆盖 r2，则无法重建 r2 所知。第三层双维表示：可用获权不可覆盖版本快照，或存有效区间与记录版本范围；例为每个记录版本的完整有效分段，r1=[1,∞):100；r2=[1,5):100,[5,∞):120；r3=[1,5):100,[5,∞):110。通过指定记录版本再找包含目标业务日的区间回答上表。每个被支持的记录版本在合同域内恰一有效值；若允许空档、冲突或未知，应有明确结果，不能默认0或取最新一行。实际存储可压缩相同部分，但须保持观察映射。Fowler 双时态文章说明有效历史与记录历史分离；本文用独立订单及版本例，不将作者示例当本域政策。

## 3. 事件历史不等于审计日志或历史查询

若命令 ChangePrice 经有权核验和预期版本条件后提交 PriceChanged，事件是已发生事实；被拒绝的请求不是 PriceChanged，可独立记录必要审计。按源版本顺序用确定的解释器得到上述时间线，可以选择事件为权威、当前状态为投影；也可以选择关系表版本为权威并同事务记录变更事实。消息队列不是自动权威事件库，投影不能替代实际写入权威，事件存储也不自动保证双时态或业务合法性。Azure Architecture Center 将 event sourcing 描述为以事件序列为权威重建状态，同时指出迁移、并发、查询及 schema 演进代价；不由此规定必须采用异步事件写入或独立 broker。

重放合同至少需要明确事件身份、作用域、顺序、schema及语义版本、初始状态、历史依赖与解释规则。例：若旧 PriceChanged 只记“重新计算当前价格”，不记录实际获权值或确定输入/规则，未来改变公式后可能无法重建历史。重放只计算所支持的状态/投影，不再次执行付款或发信；外部效果的实际记录及未知结果独立。旧事件解释与新事件产生政策分离；迁移/转换须保留旧观察合同或获权改变，不能仅改 schema 后宣称历史正确。快照只在绑定源版本、解释器/表示版本、完整性及后续连续记录的合同下用于重建；缺事件则报告缺口，不能从最新快照臆造已删除旧历史。对隐私/删除与保留期限按实际权威选择可持久内容，不宣称 append-only 天然合规。

## 4. 逐步升级及最小充分结构

如果当前只需价格与订单成交事实，可用当前价格表和独立不可静默更改的成交记录；只有历史有效价格才增加有效区间；当确有历史认知/追溯更正需求才保留记录版本；只有真实重建、多个历史投影或业务事件权威需求与成本比较成立时才考虑 event sourcing。当前行加有权版本历史已能满足不少查询，不必为历史查询自动引入 CQRS 或事件驱动服务。读优化和写入权威是独立选择。合法反转：若政策另允许追溯结算，必须引入有权调整命令、原成交关联、差额及实际效果确认，不能以重放历史替代实际会计动作。

纸面区分（NOT_RUN）：用上述两个历史碰撞否定当前值充分性；用 r2/r3 对日8查询否定仅最新有效时间线充分性；用已成交100反驳直接按110重算历史交易；用旧事件缺公式版本反驳任意重放确定性；用重复事件/外部通知反驳重建等于再次执行。各候选只证明可表示对应教学观察，不证明真实并发、恢复、性能或完整保留。
