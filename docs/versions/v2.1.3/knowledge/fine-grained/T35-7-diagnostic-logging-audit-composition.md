## 1. 三种事实不能由同一条文本代替

诊断日志用于区分故障及行动，允许依获权策略采样和有限丢失；遥测指标/trace 侧重系统观察和相关性；业务审计记录已获权操作及结果，是否必须持久、可查询、不可抵赖等由实际业务合同决定。三者可共享关联ID，不因此共享写入/保留/访问政策。用户可见错误只需足够行动：发生阶段、公开错误码、可安全执行的下一步、支持引用、是否可安全重试；不直接展示秘密、全栈、数据库连接参数或内部文件内容。

OpenTelemetry Logs Data Model 区分 Timestamp（发生时间）、ObservedTimestamp（观察时间）、TraceId/SpanId、Severity、Resource 等。时间字段可缺失；不同机器时间偏差与收集延迟使排序不能独立证明因果。TraceId 不是业务幂等键、审计授权或可信身份。教学选择另设 eventId、operationId、attemptId、actorRef（受权内部标识）、resourceRef、stage、reasonCode、outcome、version、实际观察点；数据字段需具体任务获权，禁止任意扩大采集。诊断错误链保留首要错误及清理错误、来源和分类；不能因 finally 失败掩盖真实首错。错误码与严重度不等于根因或业务结果。

## 2. 同一操作的三种可区分历史

教学：向外部服务提交操作 O，尝试 A1。记录 send_start，网络超时，随后查询原操作。若没有独立权威，outcome=UNKNOWN；若权威确认已提交，更新业务结果，不再产生新O。不得把 timeout 日志、HTTP成功码或 trace 终止视为外部效果事实。日志出现 send_start 仅证明记录动作已发生；发送前崩溃或缓冲未刷出皆可能导致误判。缺日志也可能是采样、队列丢失、收集器故障或记录点未执行，不能证明业务动作没发生。

若本地有权合同要求业务状态与审计事实同提交，则可在同权威事务写业务变更与持久审计事实/Outbox（参 T27b-1、T27c-3）；下游诊断传输失败不撤销已提交事实，按真实传输/保留合同重试去重。若必要审计事实无法在该提交边界写入，按该合同拒绝新业务提交；这不同于普通诊断 sink 故障，不应盲目令所有业务停止。若日志是非必需观测，失败时记录覆盖 UNKNOWN、使用获权替代观测，防止无限缓存或递归报错。仅 append-only API 也不能证明存储未被管理员修改、完整留存或符合审计要求；实际权限、完整性控制、备份及独立读取另核。

## 3. 记录内容与输出边界

OWASP Logging Cheat Sheet 列出通常不应直接记录的凭据、令牌、数据库连接串、密钥及敏感个人/支付信息，并要求对不可信数据作输出编码和防日志注入处理。优先定义允许字段并在进入日志/遥测前排除不必要敏感字段；对自由文本长度、结构、控制字符和编码作明确边界。只在获权场景使用不可逆或可逆替代标识；低熵值简单 hash 不代表匿名，关联标识本身可能敏感。不能先把秘密输出到 stdout 再依赖中心收集器脱敏，因为中间副本可能已保存。异常对象的 message、堆栈、嵌套 cause、命令参数、请求/响应头和第三方 stderr 都可能含秘密，不仅业务 payload。导出、搜索、告警邮件和支持包按实际权限再检查；诊断读权限不自动授予原业务数据。

教学反例：外部名称含换行与伪造字段，应由结构化编码作为单个字段保存，不能产生伪造独立事件。若合法多行堆栈是受控诊断内容，可以结构化字符串记录并限制读取，不必破坏其语义；区别在于字段边界而非删除全部换行。若新增诊断要求需要原始数据，先取得有权范围、存储、访问和删除合同，不能全量开启 debug。有限队列、分级保留及丢弃计数应有明确覆盖标志；对全量业务审计不可用采样替代。

## 4. 可反驳评价（NOT_RUN）

| 场景 | 独立观察 |
|---|---|
| A1 timeout 后实际已提交，A2未发送 | 原操作权威已提交、尝试分别记录、用户提示查原结果，不凭日志重发 |
| collector 停止或磁盘满 | 普通诊断按预算降级且覆盖 UNKNOWN；若必要审计不能提交则按该业务合同拒绝，不伪造完成 |
| 输入带换行/伪JSON、异常携带令牌 | 结构化单记录、所有出口的敏感值不出现；不只测单个 redactor |
| 时间逆序、同 trace 多次尝试 | 核实际因果/身份及权威结果，不按时间戳或 trace 去重业务动作 |
| 普通日志采样关闭、必要审计仍要求全量 | 独立审计事实不被采样；确认真实业务提交与记录合同 |
| 租户切换/支持包导出 | 实际访问控制、字段范围与获权脱敏，不能因工程人员可读普通日志而公开秘密 |
