# T41-R1 · 分析型数据的事实粒度、聚合合同及版本

## 1. 先定义一行事实代表什么

指标从业务问题开始：对象身份、实际事实类型、发生/生效/入账时间、单位/币种、分母、允许过滤分组维度、版本/完整性、NULL 与未知的处理。事实粒度是“一行代表一个什么事件/状态观察”，不是列数；事实表的合法唯一身份不必等于维度键集合。Microsoft 的 Power BI 星型建模指导区分用于分组筛选的维度和用于汇总的事实；其月-商品例说明仅看列名不能确定粒度，实际键值和测量语义同样重要。Fabric 的事实表设计讨论订单行事务事实、期末库存定期快照和流程里程碑累积快照；三者支持不同观察，不能用某一存储方式替代定义。

教学合同：一个租户、单币种最小单位、只计已确认销售/退款的实际业务金额，费用税费另排除。订单 O1 两条销售行 L1=100、L2=200；退款事实 F1=30、F2=20（均关联 O1，未分配至具体行）。销售按行、退款按退款事件，订单级净额应为300−50=250。若直接以订单号联结两组事实，产生四行，销售重复为600、退款重复为100，净额500错误。即使 SELECT DISTINCT 也未必修复，合法两笔同金额仍是不同身份。正确候选是在各自真实粒度独立汇总到共同订单键，再合并 300/50；若查询包含无退款订单，左连接缺失能否视为0取决于来源完整性以及确实无匹配的合同，不把未知来源当零。按商品计算净额须有真实退款行关联或有权分配规则，不从订单级50推断两条商品分摊比例。跨租户同 O1 不可合并，跨币种不直接相加。T35-8 的 provider/bank 逐键对账仍是不同权威问题，报表净额不代替资金结算事实。

## 2. 聚合的可组合性和丢失的信息

定义允许合并的范围：互斥事实集合、相同单位及指标版本。总金额在合法不重复且同币种的记录集合可加；同一库存品种、同单位的两个互斥仓在同一观察时点可汇总余额，但同仓日1余额8、日2余额10不能相加为18件库存；期末10，变化2，均值9只表示这两个等权采样点的平均（不自动表示整个时间段时间加权平均）。库存跨商品、单位、时间是否可加由明确测量合同决定，不套普遍规则。

平均值应保留 sum 与 count（或加权分子/分母），不能任意平均子组平均值：A 有1笔100，B 有3笔20，各均值100/20，整体均值(100+60)/4=40，非60。成功率 A=1/1、B=1/9，合并为2/10=20%，非两比例算术平均；如合法分母为0应按合同标为未定义/不适用，不默认0%。不同日期的用户去重数也不直接可加：日1 {u1,u2}、日2 {u2,u3}，分别2/2，合并 distinct=3。若仅保留每天计数2/2，无从区分与另一组互斥用户4的历史；按 T40-R2 的观察充分性推导，须保留合法可合并的集合/摘要或重新访问源；近似算法必须另获权误差合同。任何汇总均不能绕过原有权限；不能假定聚合后绝对无敏感泄露。

## 3. 从版本与负载选择存储和更新方式

若业务只查当前少量记录，带索引的权威关系查询可能足够。大量跨时间/维度的扫描与分组、分析与事务并发干扰、历史保留或多来源整合确有需求时，再比较只读投影、物化汇总、独立分析存储、按列扫描等候选；存储组织和业务事实定义独立，不能从 OLAP 名称推出必然更快。新增投影后须明确源版本、已覆盖范围、指标定义版本、转换版本、输出发布点及当前读权限；报表可陈旧的实际界限必须获权，不能用于不允许陈旧的库存写决定。

示例商品 P 日1–5属 C1、日6起属 C2（按半开有效期），日3卖100、日8卖200。按销售时所属分类，C1=100/C2=200；按当前分类重述，两笔均在C2=300。这是两种不同获权查询，后者不应伪装成前者。可用已绑定的合法维度版本键或按实际有效时间匹配，确保一个事实只匹配一个适用版本（若业务多分类，须定义多重成员及分配/去重合同）。补录更正是否改变历史报表需有权决定；若还需过去报告生成时已知的分类，使用 T40-R2 的记录版本维度。重建投影不能删除实际成交历史。

来源导入先明确输入覆盖和一致边界、原始记录身份/版本、解析拒绝/未知及获权转换；从有权稳定快照重建候选，核实际逐键结果及摘要，再按版本发布完整制品或明确部分状态。对增量按受支持的源变更语义处理新增、更正/删除，重复版本不得重复加金额；同 ID 异内容按实际修订/冲突合同。源 checkpoint 推进和实际输出提交须具备 T27c-3 的一致恢复机制。报告更新完成不等于每一用户已看到新版本，不应把单次任务成功当所有报表最新。

## 4. 有界判断与反例（NOT_RUN）

独立以原始获权记录枚举：O1 销售300/退款50/净250，联结后500为错；另一订单无退款需保留且按来源完整性决定0/UNKNOWN；若同额不同身份不能以 DISTINCT 去重。平均40、成功率20%、去重3、期末10分别验证不同聚合。分类两种查询预期不同，维度缺失/多重匹配不静默消失或倍增。若源缺尾部记录，应标覆盖未知而非宣称全部；重传及修订核稳定身份及实际值。无需实际数据仓库/Power BI 运行即可纸面否定上述错模型，真实性能和源系统执行均 NOT_RUN。
