## 1. 命题、谓词及量词

在经典二值逻辑中，命题具有真值；谓词随变量及解释变化。P⇒Q 仅在 P 真且 Q 假时为假；不等于 P 与 Q 等价，也不能从 Q 推出 P。逆否命题 ¬Q⇒¬P 与原命题等价；逆命题 Q⇒P 不一定成立。工程例：每个成功完成任务均有结果记录，不代表每个有记录的任务成功（可能为失败收据）。形式化前明确“成功”究竟指哪个合同，不能用同名字段偷换谓词。

∀x∈D P(x) 的否定为 ∃x∈D ¬P(x)。一个合法反例足以否定全称命题；有限测试全过不证明未穷尽的 D。∃x P(x) 的否定是 ∀x ¬P(x)。量词顺序重要：∀消费者 c ∃版本 v Supports(v,c) 不推出 ∃v∀c Supports(v,c)；每种客户端都有可用版本不代表存在一个适合全部客户端的共同版本。若 D 为空，全称命题在经典逻辑中空真；“全部发现的测试通过”在发现0个时不能满足另需存在至少一个材料测试的工程合同。

教学授权谓词：Allow(u,r) = Authenticated(u) ∧ Owns(u,r) ∧ Enabled(r)。在该特定假设下，拒绝条件为任一条件不满足；实际系统若有管理员例外或未知授权状态，必须建模扩展，不能从二值教学直接推出未知等于否。SQL 三值逻辑参见 T27b-1；带副作用短路表达式不可仅凭真值等价就交换执行顺序。

## 2. 集合、函数、关系

集合不含顺序与重复次数；序列、multiset、映射是不同抽象。对有限集合 A、B，|A∪B|=|A|+|B|−|A∩B|。例如两个扫描器分别发现 {d1,d2}、{d2,d3}，合并得3个不同身份而非4个；若需记录两次 d2 观察，不能仅保留集合。笛卡尔积 A×B 表示所有有序对；业务合法组合往往仅是其子集。函数给每个定义域元素唯一输出；部分函数需说明未定义域。单射保持不同输入可区分，满射覆盖指定陪域，双射才有整个陪域上的逆。迁移反例见 T32b-1。

二元关系 R⊆A×B 可用边或表表达。集合 A 上关系：
| 性质 | 数学条件 | 工程含义/反例 |
|---|---|---|
| 自反 | xRx | 非严格依赖的可达闭包含自身 |
| 对称 | xRy⇒yRx | 同一等价类可双向判断 |
| 反对称 | xRy∧yRx⇒x=y | 偏序允许自身，禁止不同元素双向 |
| 传递 | xRy∧yRz⇒xRz | 间接依赖关系，不是原直接调用许可 |

等价关系自反、对称、传递，将集合划分为不交叠等价类。业务相等关系若使用“金额差小于1”，0与0.6相等、0.6与1.2相等，0与1.2不相等，不能直接作等价类/去重键。偏序自反、反对称、传递；全序还要求任意两元素可比较。排序比较器若违反传递性，无法依赖其产生合法全序。缺失/未知状态如何比较由合同给定，不任意放在最小。

## 3. 图、闭包与依赖

有向图 G=(V,E)，E⊆V×V（本例简单图），约定 u→v 表示 v 消费 u 的产物。路径是依次相接的边；可达性由路径定义，零长度路径允许自身可达。严格先于关系用非空路径；DAG 的非空可达性无自身环且传递，其自反闭包形成偏序。直接边不必传递：A→B、B→C 可推导 A 可达 C，却不能推出 C 有权直接调用 A；授权另由接口合同定义。反向追踪影响时必须使用正确边方向、类型及版本。

教学 V={A,B,C,D,E}，边 A→B,A→C,B→D,C→D，E 独立。拓扑序 A,B,C,D,E 与 E,A,C,B,D 均合法；B 和 C 不需要固定次序。Kahn 算法保持未输出节点的剩余入度，选入度0节点输出并移除出边，直到无候选；若未输出全部节点则存在有向环（有限静态图、正确入度与边处理）。加 D→A 后 A/B/C/D 全有剩余入度，E 可输出但其余不能。不能将无候选时强制挑节点冒充合法顺序。证明：有限非空 DAG 必有入度0节点，否则反向沿前驱无限行走将在有限节点中重复，产生环；移除零入度节点仍为 DAG，归纳可输出全部。任意图中的未输出节点可能是环上节点也可能仅被环阻塞；定位实际环须额外 DFS/SCC 等分析，不能把所有剩余节点都标循环成员。

在上述图中合法拓扑序不是业务执行资格，权限、失败、资源互斥与实际产物需另核；关键路径及资源限制复用 K04，不由拓扑序直接推导完成时间。

## 4. 证明、归纳与工程边界

直接证明从假设推出结论；反证假设结论否定并推出矛盾；分类讨论需穷尽合法域。归纳证明 P(n)：证明基例 P(0)，对任意 k≥0 证明 P(k)⇒P(k+1)，才得自然数上的全称结论。强归纳可使用所有更小的合法规模。例：有限记录序列经过逐项有权过滤后输出只含合法项。基例空序列；步骤假设前 k 项输出皆合法，处理下一项仅在谓词明确通过时加入，否则不加入，且不修改原已输出合法项；因此前 k+1 项输出也满足安全属性。此不证明所有合法项均已输出、输出次序、算法终止或外部副作用。补完整性须证明每个合法项恰按合同加入；终止须输入有限且每步终止。并发修改合法性时，原模型的稳定谓词不成立，须重新明确观察点/版本。
