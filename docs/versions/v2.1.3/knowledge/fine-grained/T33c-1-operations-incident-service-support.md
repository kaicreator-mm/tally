# T33c-1 · 运营准备、错误预算、事故协同与服务支持

## 1. 运行责任与准备证据

运营目标不是部署成功，而是维持获权用户任务、管理故障与变更、支持用户恢复及持续学习。先定义服务/版本/部署拓扑、用户与合法操作、依赖/数据责任、支持时段、负责人、权限边界、响应与恢复目标。运营准备与发布批准分别有权，运行手册存在不等于可执行。
| 准备对象 | 可观察证据 | 不能替代 |
|---|---|---|
| 运行与配置 | 实际环境启动、配置、权限负例、依赖身份及可行动错误 | 仅在开发机启动 |
| 监测与接报 | 用户路径、指标分母、日志/告警路由、测量缺失检测、实际接报人 | 仪表盘存在 |
| 变更与恢复 | 受权部署、已验证制品、状态兼容、可停止/回退及实际恢复材料 | 有rollback命令 |
| 支持与交接 | 支持范围、升级联系人、已知问题、接手者可执行任务 | 文档发给接手者 |

长期联网服务可能需要轮值、升级机制、服务支持和跨团队协调；本地桌面工具更适合版本识别、首次启动/配置、可行动诊断和用户可访问的支持入口，不强制24小时轮值。不能让诊断工具越过产品权限或记录秘密。备份、恢复点和真实恢复完成条件由 T33a-1 定义，容量由 T33b-1 给出。

## 2. 错误预算燃烧率的可复算合同

设获权请求型SLO为s，0<s<1。窗口中有效请求N>0，不合格E，错误比例 e=E/N，燃烧率 b=e/(1−s)。b=1表示以目标允许的错误比例消耗预算。针对同一完整评价周期总有效请求 N_T，窗口实际占周期预算比例为 E/[(1−s)N_T]=b×N/N_T；若假设均匀流量或采用相应时间型指标，才可用 b×w/T（w窗口长度，T周期长度）表示比例。未来 N_T 未知时需标为预测或用已完成的历史完整周期，不能声称知道最终预算。无有效请求不计算比率；遥测丢失与真实零请求分别调查。

教学：30天（720小时）目标99.9%，近1小时不合格比例1.44%，b=14.4；若均匀流量，预算比例14.4/720=2%。近6小时0.6%则b=6、消耗5%。若1小时正好占完整周期请求量10%（例如业务突发），同样b=14.4实际预算占比144%，远超2%；不能用持续时间替代真实请求分母。若完整周期100000请求，则预算100次；窗口10000请求中144不合格即144/100=144%。这些是不同假设下的纸面情景，并非同一个生产观测。

Google SRE Workbook ch5 给出多燃烧率、多窗口告警例，按同一SLI分别统计长/短窗，示意逻辑为 (1h>14.4 且 5m>14.4) 或 (6h>6 且 30m>6) 触发及时接报；数字是其99.9%示例的起点而非通用阈值。比较的是各窗的燃烧率，不直接比较错误次数。短窗确认近期仍有问题，长窗限制预算消耗，两个条件必须同时成立；低速持续失败可另设工单级条件。例：1h b=15、5m b=0，第一对不触发，若其它告警条件不成立不代表无事故或已恢复；需要历史损失和业务对账。低流量、采样缺口、不同端点/服务目标、时间边界和告警抖动需要独立处理，不把无数据默认成绿。严重越权/数据错误不能只等错误预算耗尽。

## 3. 事故的发现、指挥与沟通

事故处理（减轻影响/恢复）与事故管理（协调、沟通、责任）不同。事前确定适用的宣告条件、联系人、通信渠道、升级/交接方式、可执行权限以及谁能接受残余风险。Google SRE Workbook ch9 的IC/OL/CL角色仅作大型协同参考：小事故可以由一人兼任，多团队事故需明确指挥者，技术执行者协调变更，沟通负责人按已核事实更新相关方。委派不自动授予数据库、付款或生产权限。
| 运行阶段 | 应保留的事实 |
|---|---|
| 接报与宣告 | 用户影响/作用域、开始及发现时间、监测来源、已知/未知、责任人与升级理由 |
| 缓解 | 当前目标、候选动作及副作用、获权执行者、变更身份、前后真实观测 |
| 恢复 | 用户路径及正确性、数据/外部效果、仍有风险与后续责任 |
| 关闭/学习 | 可授权关闭范围、未决事项、独立修复证据、复盘行动项 |

教学：库存服务的队列延迟升高，部分预留请求超时，两个值班者分别提议扩大Worker与重启数据库。先明确受影响业务、正在发生的影响、可用权限与变更互斥；指挥者协调同一资源的改动，不允许两个相互冲突的动作同时实施。优先考虑获权限流/隔离等可逆缓解，保留证据；诊断根因可并行，不能延误必要安全缓解。超时请求按独立意图查提交状态，无法确认则保留UNKNOWN。向用户报告确认的影响、已采取措施、可行替代/避免重复提交的提示、下一沟通责任与条件；不能猜测恢复时间、暴露秘密或宣称全部请求失败。交接应复述当前行动、风险、权威状态、未决效果与接手责任，不仅转发聊天记录。

## 4. Runbook 与长期支持的执行合同

运行手册按情境而不是命令堆砌：适用版本/环境、触发证据、必要权限、诊断入口、动作前置、执行对象、预期观测、负例/停止条件、回退或升级、记录与责任人。示例：队列积压时先核真实队列、接纳/离开率与DB容量；若已获权限流则检查受控范围并观测拒绝/在途完成，避免自动清空未知业务；停止新增压力后仍须对账、确认用户操作与恢复目标。若观测不可得、动作身份错误或存在未决不可逆效果，则停止相关危险动作并升级，不盲目重复。实际演练应有受控环境、故障模型、数据安全、独立观察、终止/复原计划，不能把在真实生产中任意故障注入当默认做法。

服务支持按版本、用户影响、支持承诺、信息安全与可复现性登记：识别环境/制品/配置版本、步骤及非秘密日志，区分使用问题、缺陷、需求变化、供应商故障和待核事实。支持回复与工程修复采用独立状态，工单已回复不意味着修复；修复提交不等于已发布到受影响用户；正式结束须记录真实处置、未决责任或适用限制。重复工单可按真实同源机制关联，但不应仅因相同错误码合并不同根因。

## 5. 复盘、改善及独立 Oracle

复盘保存可复查时间线、影响、检测/缓解/恢复事实、触发与系统性贡献因素、尚未证实的假说以及预防/检测/缓解行动。避免将个人归罪代替机制分析，也不因此免除真实授权责任。行动项应有具体对象、责任、优先级、可验证完成条件及跟踪关系；例：同一外部意图的重复写风险，行动项应验证失去ACK时独立权威记录无重复效果，而非“加强测试”。关闭事故、完成临时缓解、验证永久修复、关闭行动项是不同事实。若后来重复失败，应重查机制和原验证范围，不删除原始失败记录。复盘共享按隐私与访问权限，不机械扩大敏感材料分发。

| 教学反例（NOT_RUN） | 独立预期 |
|---|---|
| 变流量下仍按1小时/30天算预算 | 根据同周期实际N/N_T及E计算144%，未完成周期标预测 |
| 短窗恢复、长窗仍高或数据缺失 | 按真实规则/有效请求及测量覆盖裁定告警，不由告警清除推出恢复 |
| 双人同时重启与扩容、未决超时自动重发 | 检查动作授权、互斥变更记录、独立业务效果及责任交接 |
| 进程启动且队列清空，但用户预留未恢复 | 独立用户路径、持久记录、RTO/RPO及未知Effect核对 |
| 复盘写完、修复项只有“提高稳定性” | 具体机制、跟踪责任及区分性回归证据；未验证不宣称关闭 |
