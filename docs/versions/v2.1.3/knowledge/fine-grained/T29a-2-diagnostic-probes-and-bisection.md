## 1. 固定观察量和竞争假设

同一个失败现象可能有不同原因。先定义合法预期、实际输入、被测版本/制品、工具链、平台、配置、初始数据与可观察阶段；记录第一材料失败、传播路径及最终症状。设计一次探针使竞争假设的预期不同，而不是收集更多相同日志。探针也会改变调度/资源，应记录采样频率、覆盖范围、开销与遗漏。缺少日志不能证明事件未发生；不在无权生产环境运行破坏性探针或泄露秘密。

## 2. 真实历史复用：CPython 迭代协议

T29a-1 D01 已登记 #127682 报告3.13.0/3.13.1 的额外 __iter__ 调用及报告者 bisect 到 bcc7227ef7fd21aa48c8f1c57922e8beced5737c（未重跑）。修复 main d87e7f35297d34755026173d84a38eedfbed78de、3.13 backport 132bdf6990003df61d30c379a12c041010d00245：移除外层取迭代器 helper/GET_ITER，新增仅 __next__ 的返回对象测试；非 iterable 错误时机也改变。这是已登记的实际代码和测试差异，不再作为新案例登记。本次打开原 issue 和 backport 页面，机制依据已审 T29a-1 的实际差异；不声称重跑或重新证明引入 patch 完整因果。

竞争假设 H1 外层/内层重复获取迭代器；H2 只是日志重复输出；H3 消费值重复。原报告值可能正确而 __iter__ 次数错误，不能只验证输出数组。拟议独立 probe：记录构造、首次 next、遍历各阶段的真实调用计数/对象身份，消费值和非 iterable 异常时机；只具有 __next__ 的合法返回对象与原防崩溃回归分别测试。反汇编检查外层是否有 GET_ITER，不能代替实际执行。若删除安全检查也消除日志重复但重现旧 crash，则拒绝此修复。明确复现报告与真实修复测试差异；源码断言存在不代表前 FAIL 后 PASS。

## 3. 可复查的 bisect

Git 2.52 git-bisect 文档：脚本退出0表示 good，1..127（125除外）表示 bad，125用于当前版本无法测试，其它退出码中止。126/127 亦可能被解释为 bad，故不能把找不到测试命令当缺陷。先实际核一 good 一 bad，冻结外部测试脚本/工具及可比依赖，区分测试未运行、构建不适用与真正目标失败。若目标本身是构建失败，则构建失败可定义 bad；若目标是迭代次数而历史构建不可用，则 skip，不能偷换。若已知最小修补使旧版本可编译，记录补丁与复原，证明不改变目标观察。路径限制、first-parent 都是缩小实际搜索范围的选择，可能排除真正引入点；须说明依据。

纸面单链 C0 good、C1 good、C2 无法构建、C3 bad、C4 bad：仅能把首次持续 bad 的候选限制在 C2/C3，不能声明 C3 唯一引入点。若 C2 适配环境后实际 good 才可进一步缩小。若缺陷先引入后修复又重现，单一 good/bad 分界不成立，定位范围须重分；随机失败先固定/重复试验并记录不确定，不能强行贴标签。实际操作用隔离干净工作树，记录每一 HEAD、test receipt 与判断；不改用户原工作区、不自动提交试验代码。以上是教学演算，不是 CPython bisect 结果。

## 4. 性能/并发诊断：观察量不能互换

Go runtime/pprof go1.25.0：heap 按最近完成 GC 的统计，inuse_space/inuse_objects 表示当前存活分配，alloc_space/alloc_objects 表示累计分配；block 采样等待位置与累计阻塞，mutex 采样造成等待的临界区结束位置及其它 goroutine 的等待时间（采样估计）。若一锁持有1秒且5个等待者全程等待，累计约5秒争用，不是墙钟5秒。没有采样不等于没有争用。

教学同一服务尾延迟变差，竞争 Hcpu=CPU计算，Hlock=锁等待，Hdb=远端查询，Hmem=保留对象/分配压力。冻结输入、到达率、版本及环境，观察请求范围与实际阶段。选探针而非一次开启全部：

| 假设 | 可区分探针与反例 |
|---|---|
| CPU | CPU profile 热点 + 同负荷 CPU 使用、减少纯计算的单变量对照；等待占主导时 CPU 热点不能解释全延迟 |
| 内存 | 多次可比 GC 后 inuse 增长 vs alloc 累计；例如 alloc 1GiB→2GiB 而存活20MiB稳定，并不足证明 leak；若存活20→60→100MiB且同逻辑工作量则进一步核保留根/生命周期，不能只看 RSS |
| 锁 | block 等待栈与 mutex 持有者解锁栈对应；缩短受控临界区后检查等待、实际业务不变量和吞吐；不能因降低锁时间而删除必要同步 |
| DB | 同授权输入的计划估计 vs 实际行数、扫描/排序/等待和请求 span；如估计10实际10000，应检查统计/选择率与查询语义，不凭一条 EXPLAIN 换索引；EXPLAIN ANALYZE 实际执行，限获权环境 |
| 跨进程 | Trace/span 关联请求/消息身份与发送/接收、服务端真实提交；采样遗漏与异步 trace 断裂留 UNKNOWN，不能凭时钟顺序判定根因 |

用假设→独立预期→具体 probe→可反转结果→安全修复→回归的有限证据链；保留错误假设及失败探针，不只留成功图。控制组同实际负荷和语义；采集工具不同阶段时间不可直接相加。对真实历史变更应独立验证前后产物、原修复与当前回归，不把模型生成的 trace 当日志。
