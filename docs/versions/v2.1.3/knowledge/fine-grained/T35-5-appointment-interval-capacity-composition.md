## 2. 明确教学合同：时段、身份及资源

预约请求为 tenant、resource、业务预约身份、操作身份、获权主体、开始和结束的实际时间点、正整数需求量 q。展示可用性不是提交承诺。资源标识必须在实际竞争域全局唯一；若多个租户共用同一设备，tenant 只是授权范围，不能把资源物理容量按租户各算一次。本例先假定资源归单一租户、单权威数据库、同一已确认时间尺度，采用有限非空半开区间 [s,e)，s<e；时段单位、精度和可接受范围由合同确定。结束时刻不占用下一时段。

对于合法非空区间 I=[s,e)、J=[u,v)，重叠当且仅当 s<v 且 u<e。证明：共同点存在要求 max(s,u)<min(e,v)，在两个自身合法条件下等价于交叉不等式。09:00–10:00 与10:00–11:00不重叠；09:30–10:30与前者重叠；09:15–09:45包含于前者亦冲突；不能只检测新起点落入旧区间（新大区间可完整覆盖旧区间）。空区间先拒绝，不以交叉不等式给非法区间授权。若业务需15分钟清洁间隔，则对实际占用集合建模（如预约后附加15分钟），展示结束时间与资源释放时间不同；不能全行业统一端点或清洁政策。

本地时间输入须有地理时区与日历规则，按获权合同处理重复时刻的 fold 与不存在的 gap，不用服务器时区或静默猜测。两个不同实际 instant 可有相同当地显示；持久竞争键以解析后的时间点及实际资源身份为准。重复预约保留原 civil 意图、时区规则与生成身份，未来时区规则变化是明确的重评问题，不把既有确认时段无声移动。本文不实现 recurrence 或全部日历政策。

## 3. 独占与容量资源不是同一谓词

独占资源容量1、每份需求1时，只需保证同一资源的任意两份有效占用不重叠。容量为C且需求q可不同，正确不变量是对每一实际时刻 t，所有有效占用且 s≤t<e 的 q 之和≤C(t)。允许重叠不等于允许超容量，简单 pairwise non-overlap 会错拒合法需求。容量本身可能随排班/维护变动，变动须与既有承诺协调，不能直接把 C 减至低于有效占用并仍报告满足合同。

固定 C=3 教学例：A=[09:00,10:00) q2，B=[10:00,11:00) q2；新请求 N=[09:30,10:30) q1 合法，两个局部峰值均3，不能把与N重叠的A+B+N=5直接判超量。若N需求2，则两个局部峰值4，拒绝。另一反例：C=3，三份完全相同区间各q=2，任意两份已超量；即使改为C=4，所有两份均合格，三份合计6仍不合法。检测容量需按实际时间分段求和，而非只验任意两条。

有限恒定容量与有限占用集合，可把开始记+q、结束记−q，将同一时刻增减合并后按时间顺序扫描；每段活跃总量应在[0,C]。如果逐个事件检测而未按半开边界处理同刻结束/开始，可能产生虚假瞬时峰值。变化容量再加入容量边界；不同初始窗口必须纳入跨越窗口起点的既有占用。此为给定权威集合的数学检查，查询不完整、陈旧或并发新增时不保证提交。单资源固定长度整齐时槽可直接按 slot 做唯一或容量计数；不对齐的任意区间不可仅用唯一开始时刻，跨多个槽必须原子占全。对可互换但具体设备有各自不可用区间的资源池，聚合容量充足不一定能分配到一台连续可用设备，需实际分配约束。

## 4. 从业务约束选择提交机制

PostgreSQL 18 范围类型提供 tstzrange（带时区时间戳的范围）、&& 重叠操作；GiST 排斥约束能组合资源相等与区间重叠；btree_gist 为整数等标量提供对应 GiST 运算符类。CREATE TABLE 支持带 WHERE 谓词的排斥约束，用于约束表的指定子集。它不同于以相同开始时间为键的 UNIQUE。示意如下，针对单租户资源或已经映射为全局唯一物理 resource_id、独占且有限非空时段的单表教学模型，DDL NOT_RUN：

```sql
CREATE EXTENSION btree_gist;
CREATE TABLE occupation (
    id bigint PRIMARY KEY,
    resource_id bigint NOT NULL,
    during tstzrange NOT NULL,
    state text NOT NULL CHECK (state IN ('HELD','CONFIRMED','RELEASED')),
    CHECK (NOT isempty(during)
       AND NOT lower_inf(during) AND NOT upper_inf(during)
       AND isfinite(lower(during)) AND isfinite(upper(during))
       AND lower_inc(during) AND NOT upper_inc(during)),
    EXCLUDE USING gist (resource_id WITH =, during WITH &&)
        WHERE (state IN ('HELD','CONFIRMED'))
);
```

此约束拒绝两条同资源且重叠的有效占用，状态 RELEASED 不参与；须另有实际授权、正确资源映射、状态转换、操作幂等、期满释放、请求合法性和事务合同。示意未包含预约业务表、外键、付款、租户授权或权限配置，不可直接作为产品 schema。数据库配置、扩展安装权限及迁移已有冲突需实证；不将当前时间作为自动变化的索引谓词，期满是否允许再占用由显式状态事务处理。不能用此排斥约束表达 q>1 的总量限制。

可替代机制：固定离散槽使用权威槽记录及条件更新；动态容量或任意时段可锁定共同资源记录，再在适合隔离下读取当前权威集合、检查、提交；所有相关写入（含维护停用及容量修改）必须使用同一保护协议。PostgreSQL Read Committed 下在取得共同锁后的后续语句读取当前可见集合；如果使用稳定旧快照或其它引擎，要重新证明可见性与重试。也可采用实际可串行化事务及全事务重试。不可仅锁已有冲突行（空集合没有可锁行）或只执行查询后无条件插入。独立 DB/外部资源无共同原子事务，需要获权额度、协调/部分结果、真实失败处理，不能把单表方案套过去。规模与争用未测，不宣称某方案必然性能更好。

## 5. 临时占位、确认、取消与改约

假设获权政策：HELD 和 CONFIRMED 都占用相同资源容量；HELD 在权威期限 E 到达后不可确认，可由获权事务显式释放，释放前仍保守阻塞其它预约；CONFIRMED 不随占位期限消失；取消有独立权限/费用规则，不由数据库决定。确认与期满释放必须在共同权威下按可观察的先后顺序裁定。确认操作的获权线性化点必须严格早于 E 且当前仍 HELD；在 E 或之后到达不得新确认。迟到的定时器、过期显示或外部付款未知都不能证明已经释放。精确权威时间采样与保护顺序需在实际引擎/事务中定义，不用任意客户端时钟或长期事务开始时间代替提交合同。

操作身份绑定原业务预约、实际主体、规范输入与版本；同身份同参数的已知结果在当前获权查询范围内可读回，异参数冲突。若响应丢失不假定失败，不另创预约。若远端付款可能已完成，付款确认、预约占用及补偿义务分别记录；是否保留、释放或另行安排由获权政策裁定，不借确认/取消状态推断资金结果。

本例改约要求原 CONFIRMED 占用保留，直到新时段已获权原子替换；新时段不可用或事务失败，旧约不动。09:00–10:00 的预约改为09:30–10:30，必须排除自己将被替换的占用，且检查其它竞争者；同一权威下可更新当前占用或在一个事务内撤销旧占用并写入新占用，失败全回滚，操作记录及版本同提交。不能先跨事务释放旧约再尝试抢新约，也不能在外部系统调用后承诺本地原子性。若另获权“取消旧约，尽力新订”政策，则两步部分结果可合法，但须明示用户风险，不能称原子改约。取消后的时间只对获权新操作重新开放，原操作重放不复活已取消预约。

## 6. 选择最小结构及独立反例（NOT_RUN）

| 决策点 | 独立可反驳预期 |
|---|---|
| 同资源相邻/包含/重叠、不同资源、非法空区间 | 由集合交集及资源身份独立推导；相邻允许，包含冲突，不同独立资源不冲突，非法输入拒绝 |
| 同租户不同资源与跨租户同一物理资源 | 授权与容量分别核；共享设备不能按 tenant 分隔后超订 |
| 容量3的A/B/N变体、同刻事件、容量下降 | N1合法峰3、N2不合法峰4；实际全时段和，不靠重叠总和或两两检查 |
| 两并发预约均读为空、提交先后反转 | 独占同一冲突时段至多一成功，不强制某用户获胜；核实际占用与操作记录 |
| 占位确认/到期释放竞争、延迟定时器 | 依权威时间和状态顺序，不能同时释放并确认；释放前不自动视为可用 |
| 改约失败、ACK丢失、同操作不同输入 | 原约不变或已实际原子迁移；读回原身份，冲突不再写 |
| 夏令 gap/fold、设备维护、15分钟清洁、外部资源 | 明确新增合同及适用机制，未确定事实为ASK/UNKNOWN，不把原独占简例推广 |

简单单房间、固定槽及无需临时占位时，不必引入通用调度引擎、事件溯源或多服务。共享纯区间/单位机制仅在语义相同处复用；房间、人员、设备、医疗资格与取消政策仍归各业务 Owner。若真正需要跨多资源、连续分配、优化排班、公平优先级、预约系列或跨外部供应商，按实际目标再补知识，不由本章自动宣称已覆盖。
