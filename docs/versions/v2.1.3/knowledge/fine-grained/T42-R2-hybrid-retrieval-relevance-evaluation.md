## 1. 语义目标、向量距离和近似算法三个不同问题

用户可能需要准确部件号、指定版本合同、自然语言同义概念或多个证据。精确词项/标识约束与语义相似度不同，不把合法候选身份交给 embedding 自行决定。向量表示由实际模型、输入规范、维度、度量及版本决定；同维度不证明新旧模型坐标可比，升级须核语义兼容、重建或隔离。余弦相似度仅在非零向量下定义；欧氏距离、内积与余弦不能任意替换。对 L2 单位向量 u,v，||u−v||²=2−2(u·v)，因此在这个条件下最小欧氏距离与最大余弦排序等价；非单位向量不一定。例 q=(1,0)，a=(10,0)，b=(1,1)：余弦 a=1>b=1/√2，而欧氏距离 a=9>b=1，故两排序不同。距离近不证明文档真实、有权、适用当前版本或回答用户问题。

在确定同一获权集合、向量版本、度量及并列次键后，精确近邻可作为近似算法的独立计算参考。假定精确 top3=[A,B,C]，近似 top3=[A,C,D]，近邻重合率=2/3。这个指标只回答近似算法是否找到既定距离下的邻居；若真实独立相关集合={B,E}，近似结果相关召回0/2，精确向量结果也仅1/2。因此改进 ANN 候选预算未必解决模型/信息需求不匹配。参考 Elasticsearch 8.19：近似 kNN 每 shard 有候选预算 num_candidates，经合并取 k；增大候选通常可改善找到真近邻的机会并增加计算成本，非逐查询单调保证；另有穷举向量评分。过滤发生在候选搜索中与取 top-k 后过滤是不同操作，具体引擎的过滤成本并不总随过滤范围缩小而降低。近似索引、预过滤、重排与最终授权均须核实际合同，非引擎安全资格。

## 2. 多路候选融合不等于证据完整

假定所有候选已经按统一的获权范围和稳定事实身份限定，词项路 L=[A,B,C]，语义路 V=[D,B,E]。不同路的原始评分单位和分布不必可比，不能因为 BM25=12 而向量相似度=.9 就直接认定前者更相关。若有获权的标定及权重合同可用分数融合；另一候选是 Reciprocal Rank Fusion（RRF）：对每个出现在各路结果中的身份，将 1/(c+rank) 求和，rank 从1起，c≥1；未出现不贡献，完整比较仍需明确并列规则。

教学 c=10：
- A、D 各为1/11，B 为2/12=1/6，C、E 各为1/13；B 排第一，A/D 和 C/E 各自并列，按预定稳定次键处理。
- 若每路候选窗口只取1，候选只有 A,D，B 即使是两路原第2也无法被后续融合或重排找回。
- 若任务实际必须优先精确部件号 A，而 B 仅为类似产品，两路一致支持 B 也不能覆盖硬约束。应先实现精确范围或独立精确查询路径，而非靠任意调权重补救。
- 两路都没有独立相关文档 F，则任何仅在其并集内重排的算法均不可能返回 F。重排可改善已有候选的位置，不创造遗漏的合法证据。

Elasticsearch 8.19 RRF 文档给出相同等权形式，rank_constant、rank_window_size 与最终 size 互为不同参数；子检索器取其实际候选，再在协调端融合，k 大于窗口则截断。其特定 API 不支持某些组合（如 sort、scroll、rescore）；不能把 R1 的一般分页/重排建议原样套在此 API 上。若只需准确标识查找无需多路；确有词项与语义互补且业务允许有限候选时才评估融合。多路读取同一文档须按实际 source/scope/id/version 处理同一身份，不能以标题相同合并不同记录或让旧版与新版静默替换。所有路与后续阶段均不得扩大授权；RRF 不证明统计/时延非干扰。

## 3. 由实际信息需求选评价指标

固定同一查询、获权语料快照、独立相关等级、唯一结果身份和截断 k，以下纸面指标采用明确教学约定，不声称所有工具在缺失标签/空集合时实现相同。设完整相关集合 R={A,B,C,D}，结果各有三条，系统 X=[A,E,F]、Y=[E,B,C]。
| 指标 | X | Y | 解释 |
|---|---|---|---|
| P@3 | 1/3 | 2/3 | 前3条中相关比例 |
| Recall@3 | 1/4 | 2/4 | 全部已知相关中找回比例；要求独立完整 R |
| RR@3 | 1 | 1/2 | 第一条相关的位置倒数；没有相关则0 |

仅找一条答案的任务可能更重视首条相关；多证据任务则要查是否同时找到所有必需证据，不能用首条成功替代。若两个必需证据 A,D 均须存在，X/Y 都不合格，即使某单指标不错。查询分组和权重由真实用途决定，不凭大样本自动取总体平均。若返回不足 k，事先约定固定槽位分母 k（空槽为未命中）或实际返回长度（另报覆盖），两者不能直接比较。无相关真值时 Recall 无定义或按预定无相关查询规则另报；未知标签不是已证实不相关，若使用池化标签集只能报告相对于该集的召回，不能称全语料完整。Elasticsearch rank_eval 支持典型查询及人工相关标签，提供 P/R@k、MRR、DCG 等不同指标；其 ignore_unlabeled 政策及实际分母需按版本核，不能用 API 默认值代替上述合同。

等级相关性例：三条合法文档 A等级3、B等级1、C等级0；固定教学增益 g(r)=r，折扣1/log2(i+1)，i从1。列表 [B,A,C] 的 DCG@3=1+3/log2(3)≈2.893；理想 [A,B,C] 为3+1/log2(3)≈3.631，NDCG≈0.797；理想序列自身为1。不同增益（如 2^r−1）、折扣、截断及无正增益时的处理必须明确，不能将不同定义直接比较；理想 DCG=0 时不直接除零。以上为自定 DCG 变体的算例，不声明与 Elasticsearch 的实际实现数值完全相同。MAP/MRR等跨查询汇总须先固定逐查询指标和合法分母、查询权重；平均掩盖关键查询失败，必须独立报告精确标识、关键证据与禁止披露等底线。

## 4. 从失败定位到最小改进

先区分独立事实：合法源是否已收录、查询是否有权/正确解释、候选是否覆盖、融合/重排是否按合同、输出是否过期或截断。例：必需版本事实存在于权威库但未索引，增大 ANN 预算无效；已经索引且精确距离排名靠前但 ANN 漏掉，评估候选预算/索引；候选含正确事实却排在截止线外，评估排序/重排；精确向量也不相关，检查表示/任务语义或选择精确查询；实际查询无权，不以改进召回绕过授权。候选 union 覆盖增加不证明前 k 质量增加，且可能增加资源、噪声、延迟及权限检查成本。

评价数据应由真实用途建立独立查询/相关等级/必要证据，不用候选自身评分作为真值。按精确符号、同义自然语言、范围版本、多证据、无答案/未知、权限及数据缺口分层，冻结语料/查询/标签和版本；调参样本与保留评价区分，记录未标注、失败、超时及查询级结果。不得把真实用户点击直接当无偏相关性（排名位置与曝光会影响点击）。同一查询的多个文档不是独立查询；宏平均查询分数与按记录加权的微平均不是一回事，复用 T25d-1/T34b-1。实际性能/成本需另有同条件测量，离线排名指标不能证明用户实际成功、因果收益或 LLM 使用效果。

纸面 Oracle（NOT_RUN）：非单位向量的不同距离排序；精确近邻重合2/3 vs 真相关0/2；RRF B第一与窗口1反例、硬约束反转；独立 X/Y 的 P/R/RR、等级DCG以及无标签/零分母边界；索引缺失、权限、候选漏项和排序失败应有不同诊断。无实际引擎、embedding、模型、benchmark、用户或生产数据；不新增产品或消费效果结论。
