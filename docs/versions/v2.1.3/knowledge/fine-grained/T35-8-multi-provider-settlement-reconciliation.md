# T35-8 · 多支付方、结算与跨权威对账（B6）

## 1. 区分业务订单、实际付款、服务商余额、银行到账

订单可能对应多个获权付款分配或尝试。订单应收、授权、capture、退款、拒付、provider balance movement、结算批次、payout、银行入账及本地会计记录分别有身份与发生/生效时间。支付成功不等于已结算，已结算不等于银行已实际入账；provider 报表与银行账分别是相应事实的证据，不能用其中一个凭空补另一个。业务 ID 关联多个来源，不替代 (provider, merchant account, environment, provider resource identity)；相同外部字符串跨服务商可合法重复。修改记录或报告可能需要类型/子身份、真实稳定记录身份；不能仅凭 original capture id 去重所有退款、手续费、调整和结算记录。

Adyen Settlement details report 的标准列含 Merchant Account、Psp Reference、Merchant Reference、Journal type、Modification Reference、币种及金额；文档明确部分 Chargeback 修改引用可以等于 capture 修改引用，MerchantPayout 的字段又表达批次及银行可对应的 payout reference。由实际记录类型与契约确定关联，而不是统一假设修改引用全局唯一或每行即一笔支付。本章仅借该具体报表说明异构来源，未实现适配器。

## 2. 不确定结果下的跨支付方切换

教学：同币种订单应收10000。获权政策允许 P1 收6000，P2 收4000；本地对每个分配有稳定意图和单独 capture 身份。确认6000且另一笔4000未知时，不能声称订单全付，也不能改发 P3 的4000；在未查明原结果前，保留待确认承诺以免超收。若政策要求整笔支付而不允许分配，不能把此示例作为自动拆单授权。不同 provider 的幂等合同相互独立，复制同一个 key 不提供跨 provider 去重。明确终局未发生且无迟到成功可能，才依获权切换合同释放承诺；若允许用户明确承担可能重复付款风险并有补偿方案，需另获权合同，不用本章默认。

退款按原 capture 身份、币种和已确认额度约束；教学取消2500，若获权分配 P1退款1500/P2退款1000，P1未知时仍占P1额度，P2确认不解除P1。全订单余额不能替代各 capture 上限；实际 provider 若人工调整须查证和冻结不明自动动作。不要把两渠道视为一个事务，分别记录确认、未知、拒绝与独立恢复义务。

## 3. 多层对账：固定范围、逐键及总额

教学同一结算币种最小单位，固定两个独立 merchant account 的已获权记录，无税费、FX、储备和拒付，仅此范围：
- P1 期初余额1000，capture +6000，已确认 refund −1500，手续费 −120，payout −5000，期末380。
- P2 期初余额0，capture +4000，已确认 refund −1000，手续费 −80，payout −2920，期末0。
- 两渠道合计确认 capture10000、refund2500、费用200、payout7920；期初1000+10000−2500−200−7920=380。银行只观察到 P1 的5000，P2的2920不能标记银行到账；可在途或有差异，依真实结算时窗、币种、银行匹配及来源核验。不得拿期末余额380去补造银行流水。

独立对账分别比较：(a) 订单/意图到 provider capture/refund 的实际键及金额；(b) provider 报表的余额变化、费用、批次与对应来源；(c) payout 到真实银行流水（可能有一对多、多对一、银行费、FX、日期差异，须有权匹配规则）；(d) 本地账务引用及差异处置。例：两笔相同金额跨账户互换，合计不变却逐键不符；同批重复导入一笔正一笔负总额抵消，也可能掩盖重复。相同金额和相近日期不独立证明身份。对差异区分尚在途、已确认差异、无法匹配、源覆盖不足、重复/更正等；阈值、关账、核销和人工调整必须由有权财务政策确定，不能从代码默认。

报表输入须核真实账户范围、币种、日期语义（业务、booking、结算、入账）、时区、schema、来源版本、完整性和是否为修订。不能按文件名去重或把收到文件当日结完整；保留获权的原始记录及更正关系。相同报告重传可在实际稳定身份/内容及授权一致时去重，修订/冲突不得覆盖历史。无稳定逐条身份时需依 provider 真实合同或保留 UNKNOWN；不得假定所有报表行存在统一唯一键。汇总分别按币种与账户，FX须用获权汇率/时间/费用/舍入，不能直接合计不同币种。若真实来源显示额外储备或拒付则重新定义完整余额桥接，不把教学公式作为普遍会计公式。

## 4. 结构选择及反例（NOT_RUN）

小型单支付方、无需独立结算时，可直接采用有限业务动作与权威读取；真正多方、周期对账和修订才需要 provider-specific 解析/身份映射、规范化来源事实与独立差异处理。共享精确值及通用关联合同，不将不同渠道退款/结算状态压成同一个不带原始语义的枚举。缺权限或不确定来源停止自动财务效果，不强制停全部独立业务。

| 场景 | 独立预期 |
|---|---|
| P2 timeout，P3尝试接管 | 旧意图未知时不产生无权重复付款；核真实各 provider 状态 |
| P1退款未知、P2退款确认 | capture 级承诺分别保留，订单状态不覆盖两者 |
| P1/P2 相同外部ID/金额，两个账务引用调换 | 使用实际来源身份，逐键发现差异，即使总额相等 |
| 报表重复、修订、缺账期或列变化 | 同版同身份幂等、修订保留历史；不完整标 UNKNOWN |
| 两笔 payout 仅一笔银行到账 | 分别确认，不按 provider payout 自动补银行事实 |
| 新增币种/银行手续费/拒付 | 先取得有权转换及记录合同，独立回归旧分配和余额桥 |
