## 1. 计划、事实、资格及业务效果不能互相替换

一个执行实例包括不可静默改写的已发生事实 H（真实节点/尝试身份、所读输入及版本、已接受的输出/效果或 UNKNOWN、验证收据）、当前获权剩余计划 G_r=(V,E,contracts) 及其版本 r、实际运行/资源/授权状态。节点定义、节点实例、尝试和业务 operationId 是不同身份；两个步骤同名不等于同一实例，两次尝试亦不自动代表两次业务效果。已有工作流不意味着必须把每个局部函数建成独立节点。固定短过程可用顺序函数；动态有实际依赖、等待、重新规划、可独立验证产物时，才引入对应粒度的有界图和执行身份。

边应表达所需事实或明确顺序/资源/控制义务，不能把所有入边简单解释为“前驱有终态即可继续”。对于节点 v，准入至少需要当前计划中的合法身份、所有必需前置在真实当前观察点成立、相关输入与验证收据符合版本及范围、当前授权和资源许可；候选 READY 不等于 ADMITTED/RUNNING 或外部效果已提交。若前置 UNKNOWN/CONFLICT，不默认 true 或 false；按已授权的三态分支查证、等待或拒绝，不能因此跳过必需验证。前置读取的授权/数据版本在实际提交点可能改变，需沿 T40-R1 的提交保护重新核验。节点后置验证描述真实输出和效果，验证失败/未知保留实际事实，不能将已发生效果改写成“未执行”。

## 2. 用义务而非节点名称解释插入、跳过与替代

教学申请 P revision7，原计划 A=冻结输入，V=独立核金额及授权约束，C=权威确认，N=发送通知。边 A→V→C→N。必需业务义务 O1=输入对应 revision，O2=有效批准及当前确认资格，O3=权威确认收据；通知仅在确认实际发生且当前允许发送时执行。A 已完成，V/C/N 尚未准入。获权新政策要求金额>10000 增加独立风险证据 R；A 的输出金额12000。
| 候选修改 | 实际判断 |
|---|---|
| 插入 R，A→R→V，原 V→C 保留，且 V 核 R 的实际版本证据 | 在本例满足新的前置结构，后续仍需实际验证 |
| 仅添加 R 节点，但 C 不依赖 R，V 不读 R | 拓扑上无环也不足，存在 C 先于 R 完成的非法执行 |
| 跳过 V，直接 A→C | 未履行 O2，拒绝；SKIPPED 不是成功验证 |
| 政策明确金额≤10000 不需 R，已核金额9000 | R 可不生成或明确标 SKIPPED_NOT_APPLICABLE，保留该政策、输入版本和判断依据；仍执行 V |
| 用等价节点 V2 替 V | 只有获权输入域、义务、结果、版本、失败/效果合同和独立证据均适配才可替代，不因名字相似就复用 |

边条件需要声明 AND/OR 和义务：例如合法分支 B1 或 B2 各能提供同一获权的风险收据，join 只需实际选定分支的合格证据及任何其它共同前置；不能等一个从未准入的互斥分支，也不能把未选分支的 SKIPPED 当收据。若两条路径提供不同必需证据，则必须 AND。教学选择 riskRequired 取 {YES,NO,UNKNOWN}，UNKNOWN 不能静默选 NO；若业务允许无风险判断就继续的另一种合同，须有明确权威而非引擎默认。条件计算输入及规则版本应留证；若金额或政策改变，旧条件资格需重新核验而不是更改原历史。

## 3. 局部图修改的充要图条件与实际发布

固定有限 DAG G。只添加一条 u→v（u≠v）时，新增环当且仅当原图已有 v→…→u 的路径：若已有路径则闭合；若新图有环，它必须经过唯一新边，去掉该边即得原路径。u=v 自环直接拒绝。多边修改须对完整候选图检查，不能仅分别对旧图检查。例如原 A→B 与孤立 C，分别加 B→C 或 C→A 都不在原图成环，同时加两边却得 A→B→C→A。可对候选用 Kahn/DFS，有限图按邻接表示及常数身份查找 O(|V|+|E|)，不从局部改动数量推出同规模成本；已有拓扑序在新边方向与旧排序相容时可作为快速充分检查。结构无环仍不证明义务完整、数据类型/版本匹配、资源可用或业务可执行。

计划修改是获权操作，候选必须绑定 expected plan revision、已发生事实/已准入工作及相关读依赖。最小安全候选：冻结已提交/不可移动承诺；仅在获权未准入未来节点上改动，新增节点引用真实定义版本和合法参数；核完整依赖/条件/义务、循环和有界资源；在共同权威处以实际版本和准入 fence 原子切换；旧计划下发但未执行的工作不能使用已失效的资格提交。若两个候选都从 r7 出发，各自合法（上例分别加 B→C 与 C→A），先接受一个为 r8，第二个须以 r8 重建并重验，不能直接合并两个 r7 结果。若运行中确需修改，先有获权取消、停准入、join/确认效果或明确保留正在执行的节点及其承诺，不能用“最新计划”覆盖 UNKNOWN。

不得向已经完成的 C 添加 R→C 并宣称过去已满足 R；可以在新版本后追加补充审查/修正动作，保留原 C 历史、发现的问题及当前资格。若政策要求重新确认 revision8，另生成合法新实例/业务操作，明确原批准是否有效、撤回/补偿及外部效果，不因换节点 ID 自动获得重复执行业务权利。

## 4. 子工作流的边界与终止

将一个未来节点 W 替换为子图可以降低局部复杂度，但父节点的输入、可观察输出、失败、取消、资源、权限和效果合同仍由实际 Owner 负责。例父节点 W 要求两项独立合法检查 x,y，子图入口绑定父输入/版本，两个子节点 X,Y 完成并取得可复核收据后，出口 J 才能报告 W 合格；Y 为 UNKNOWN 时 X 成功不能令 W 成功。调用身份区分父实例、子实例及每个生成节点；同一子定义被两处使用不等于两个实例共享副作用。若子节点已发生不可逆效果，父取消或失败不得把该事实删除。生成子图也须检查实际跨边界依赖、权限、资源，禁止通过父/子间隐式回调产生未表示的等待环。

单次有限 DAG 不足以证明动态执行终止：每完成一个节点便追加一个新的后继，始终无环却无限运行；无限重试同样如此。可选择有界 worklist：全实例的新增节点总预算 B（包括嵌套子图）、每节点尝试上限、总时限及真实取消/收敛合同，超过预算返回有权部分/UNKNOWN/失败而不是假成功。若欲证明有限调度步骤终止，可用自然数度量：预先给每次合法生成或尝试分配有限全局 token，每次动作消费至少1且不补充，故至多该数量的这类动作；还须证明单步实际返回或有可执行的停止/隔离合同，等待远端未知不能凭 token 保证完成。安全、完整、终止和性能分别评价。

## 5. 独立验证与最小机制（NOT_RUN）

基于独立义务表与历史检查，不由生成器自身声明“所有验证已包含”。至少区分：A 已完成后合法插入 R 与缺边反例；条件 NO/UNKNOWN 的合法与非法跳过；两个基于同旧图的补丁组合成环；过期计划准入和正在执行效果；已完成节点不被 retroactive edge 改写；子图部分结果和跨实例 identity；无限追加无环反例及总预算。仅具固定步骤的任务不要求动态工作流平台；若实际流程允许根据有权新信息局部变化，再在必要边界采用上述图/义务和版本机制。无实际 runtime、调度系统、SDK、Agent、LLM 或产品运行。
