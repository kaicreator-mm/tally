# T31a-1 · 编译、链接、加载、ABI 与依赖身份

## 1. 生成链中的不同成功事实

源码的名字、类型与运行语义不直接等于目标产物。以 C/GCC 驱动为例：预处理展开 include/macros 等输入；编译产生汇编；汇编产生目标文件；链接结合目标及库，解析符号、安排重定位和输出。GCC 的 -E/-S/-c 分别停止在预处理、汇编文本、目标文件阶段；并非每个工具链都对用户暴露相同阶段。解释器、字节码/JIT、TypeScript 到 JS 的生成各有实际合同，不能用 C 的链接模型描述所有运行时。

| 阶段 | 实际需核的输入与结果 | 典型失败 |
|---|---|---|
| 预处理/代码生成 | 头文件、宏、schema、生成器、目标配置 | 未包含正确声明、生成旧接口 |
| 编译 | 每编译单元、类型/语言模式、优化和目标 | 非法表达式、未声明名字、不同目标 |
| 汇编 | 指令/目标架构、目标文件格式 | 不支持指令 |
| 链接 | 符号引用、库、重定位、目标兼容 | 未定义/重复符号、架构不匹配 |
| 加载 | 运行时依赖、搜索路径、实际导出及 ABI | 找不到库或符号、版本不匹配 |
| 执行 | 有权业务输入、运行环境、资源及错误合同 | 错误结果、崩溃、生命周期泄漏 |

编译成功只说明特定编译器的该阶段接受输入；链接成功未必核所有运行加载路径（例如延迟解析的动态符号）；加载成功不证明布局/行为或业务正确。K08 的发布证据链负责后续资格。

## 2. 符号、链接与依赖边界

教学 C（假定同工具链与目标，分开文件）：main.c 声明 int add(int,int) 并调用，math.c 提供匹配定义。gcc -c main.c 可生成含外部引用的 main.o；单独链接 main.o 缺 add 定义会失败。将 math.o 或实际导出匹配符号的库纳入链接才满足该引用。头文件声明本身不是实现。静态 archive 是成员目标文件集合；GNU 风格链接通常按命令行顺序搜索 archive 以满足到达时已有未解析引用。gcc main.o -lmath 与 gcc -lmath main.o 不一定等价（假设存在实际 libmath.a，且无其它满足符号的库）；循环依赖、group、whole-archive 有各自条件和代价，不普遍强制重复库。链接过程选择哪些目标并不自动验证其业务许可或声明依赖。

静态链接可将所需库实现纳入制品，减少相应共享库的运行查找，但体积、更新、许可和系统调用依赖仍需评估；不能认为所有静态程序都无外部依赖。动态链接可共享实现及更新库，但版本、加载搜索与 ABI 是部署条件。Linux ld.so 对带斜线依赖按路径解释；无斜线时按实际规则考虑 DT_RPATH（无 RUNPATH 时）、LD_LIBRARY_PATH（secure-execution 例外）、DT_RUNPATH、cache 和默认目录等。RUNPATH 仅用于该对象直接依赖，子依赖另需自己的搜索合同；RPATH 的适用范围不同。不能仅设置一个环境变量就断言所有平台会加载指定库。检查目标平台实际路径、文件身份、架构与依赖闭包；不要从不可信目录随意加载库。

## 3. API、ABI、行为合同是三个层面

API 约定调用者可使用的源级名字、类型及语义；ABI 约定已编译组件之间的数据表示与调用（目标架构、字长/对齐、结构布局、调用约定、符号命名、异常及相关工具链合同）；行为合同还有合法值、错误、所有权与生命周期。源代码可重新编译不代表旧二进制可直接运行。相同符号存在也不证明参数、返回值、布局一致。

教学结构：假定已发布 struct Item { int id; int qty; }，新库在 id 前插入 int version。即使旧函数符号未变，旧调用者按旧偏移解释/分配结构，新库按新布局读取，可能读错字段或越界。具体偏移由目标 ABI 确定，不能假定 int 永远32位。若需要兼容，可考虑不暴露内部布局的 opaque handle、带大小/版本的明确结构（仍须验证读写范围）、独立版本化接口，或有权同步升级全部消费者。跨边界内存必须由约定的分配者/释放者管理，不能盲用另一运行时的 free；回调需明示线程、对象生命周期、异常不能任意跨 ABI 传播及所有权。

Node22.17.0 Node-API 是具体 ABI 稳定机制，其承诺针对受支持的 Node-API 版本与限定接口；直接 Node C++、V8、libuv 及外部库不自动得到相同保证。若 addon 使用 Node-API 并依赖某系统库，仍需确认系统库 ABI、OS/CPU、目标版本支持及实际可加载制品。不能将 Node-API 稳定解读为 Windows/Linux 二进制互通或所有 Node 版本都支持最新 API。纯 JS 模块无该 native ABI 问题，但仍有语义、运行时功能与依赖版本兼容。跨进程 CLI 可避免直接二进制内存合同，但引入 IPC、序列化及进程管理（参见 [T25c-1](T25c-1-os-process-memory-ipc.md)）。

## 4. 解析、版本、生成及发布身份

依赖声明是允许解析的范围，锁定结果是某环境下的确定选择，实际安装/加载是另一事实。记录源、版本、内容身份、解析目标、平台可选条件、工具链与生成参数；直接使用的依赖应按实际项目合同显式声明，不能因为开发机恰有传递包就省略。锁文件不保证所有 OS 获得相同可选二进制，也不能证明真实构建未用其它路径。动态库同名、旧 build 目录、不同 include 路径可能让本地生成通过但安装环境失败。候选生成输入闭包、缓存正确性及可复现性复用 K08 D1/D2；不新建第二套生成流程。目标版本支持来自获权环境与实际使用特性，不因开发机版本较新就提高最低版本。

选择验证边界：源检查→干净目标环境实际生成→链接/加载依赖检查→以真实旧/新消费者调用约定接口→业务负例→制品身份及发布证据。若本次只是源码兼容调查，不必强行发布；若承诺 native 包可安装，则单独编译成功不足。对外部动态库查找应记录实际加载路径、摘要/版本（若可获）及依赖来源，不执行未经授权的未知制品。

## 5. 独立 Oracle（NOT_RUN）及资料

| 教学场景 | 独立预期 |
|---|---|
| 仅有声明未纳入定义 | -c 与链接结果分开，不将前者报为完整产物 |
| 目标库缺失/搜索到同名错误库 | 实际加载身份与预期比较，失败/错版本不报兼容 |
| 新结构布局、旧已编译消费者 | 按原 ABI/值/错误合同验证，不用重新编译后的成功替代 |
| Node-API addon 引入 V8/第三方库 | 分别核目标版本和实际动态依赖、安装/加载；不宣称普遍 ABI 保证 |
| schema 改、旧生成缓存仍命中 | 实际产物对照当前输入和真实消费者；未测不宣称可复现 |
