## 1. 将陈述变成有权、可判定的事实

先区分定义（可售量的含义）、事实（某仓在某版本的量）、约束（不得产生负可售量）、推导（按获权公式计算可售量）、决定（是否接受此次预留）及动作（提交预留）。例如从“可售量为7”不能推出任何人有权预留7；来自统计报表的数量未必是当前业务权威。为每条候选规则记录身份、来源/版本、责任人、适用对象/角色/操作/条件、有效区间、例外及优先级的授权出处、正反例和未决事实。技术实现或现有代码分支可以是发现线索，不是自动授予政策。

域值须包含必要语义：数量及单位、币种及舍入点、标识范围、日期/时区、是否未知/缺失/不适用。教学假设按最小货币单位计整型金额；0.10 与 0.20 的精确货币语义不能由任意浮点比较代替。两种币种数值相同也不能直接相加，需获权汇率来源与生效点。对缺失仓库、负数量、单位不匹配，不以默认0、默认仓或字符串强制转换悄悄形成有效输入；格式拒绝与政策 DENY 及事实 UNKNOWN 是不同原因。

## 2. 决策表：匹配集合、覆盖及冲突

有限表把合法输入域 D 映射到规则谓词 P_i 与输出 O_i。给定已知输入 x，匹配集合 M(x)={i | P_i(x)}。若要求每个合法输入恰一条规则，则需对 D 内每个 x 同时满足至少一条和至多一条。两条规则有重叠是存在 x 使 P_i∧P_j；规则空缺是存在 x 使所有 P_i 均不成立。非法或不可达输入从 D 排除需独立依据，不能因测试困难而删除。全域覆盖与输出正确是两个独立性质。

假设某仓预留规则获权为：仅有权限且仓开放、请求量为正整数件且不超过当前可售量时允许，其余已知合法输入明确拒绝。前置已验证请求域及权威数据；A 表示权限已确认，B 表示仓开放，C 表示请求量≤可售量。下表用 1/0 表示已知真/假，* 为任意已知二值。
| 规则 | A | B | C | 输出 |
|---|---|---|---|---|
| R1 | 0 | * | * | DENY |
| R2 | 1 | 0 | * | DENY |
| R3 | 1 | 1 | 0 | DENY |
| R4 | 1 | 1 | 1 | ALLOW |

八个已知组合的覆盖基数分别4+2+1+1=8，规则对两两不相交（最早假条件不同），故在该有限域恰一命中。对照错误表：R1改成 A=0→DENY，另加 C=1→ALLOW，则 A=0,B=1,C=1 同时命中且结果冲突；若删除R3而不补规则，则 (1,1,0) 无结果。即使所有行覆盖，R4 输出写成 DENY 也仍违反原业务合同。连续金额区间可用有序端点分析：整数件 1..10 与 10..20 在10重叠；1..9 与11..20 缺10。实数域和整数域不能套同一边界结论。

Camunda 8 文档所述 DMN hit policies 是具体机制：Unique 限制最多一个匹配而非保证至少一个；Any 允许多个匹配但输出相同；First 按顺序选择首条；Rule order 返回所有匹配并保持规则顺序；Collect 允许多项并可按具体聚合合同汇总。First 可能隐藏冲突，除非顺序就是有权政策；Any 的输出一致性也须核完整输出，而不只主状态。Collect 不能将同一事实的重复规则当两次合法奖励；重叠是预期还是错误由规则目标确定。本文不要求使用 DMN 引擎，未验证整个 DMN 规范或运行时。

## 3. UNKNOWN 与版本、例外的选择

前表 * 不匹配未知值这一点由本教学合同限定，而非 DMN 通用 null 规则。对部分输入，若权威政策明确某已知禁止条件足以拒绝，则可给 DENY（例如确认无权限）；否则对可能改变决定的未知输出 ASK/UNKNOWN，不执行预留。可采用有限补全推理：A=1,B=1,C未知时，C=0/1分别DENY/ALLOW，不能确认允许；A=0且其余未知时，所有合法补全均DENY，但真实规则的适用性、权限来源有效性及补全域非空仍需成立。不存在合法补全应报告事实冲突/无效，不利用空全称推出允许或拒绝。业务 UNKNOWN 不等于 SQL NULL 或异常；未确定的事实不能通过布尔默认值变成有权规则。

例：版本 V1 在 [2026-01-01,2026-07-01) 生效，最大预留10件；V2 在 [2026-07-01,∞) 生效，最大8件；假设业务明确以提交时刻（指定时区）选择政策。6月30日申请9件、7月1日提交，按V2拒绝；若合同要求以受理时刻锁定版本则另判。若两版在7月1日都含端点且输出冲突，需授权修正规则，不用文件更新时间决定优先级。记录有效时间与记录/更正时间、版本及所依据事实；追溯更正是否影响历史决定必须有业务裁定，不能重新解释已发生效果。跨时区及夏令时参见 T25b-2。例外可缩小通用规则适用域或用明确优先级表达；不能依代码位置默认例外优先。

## 4. 决策与状态提交不可混同

纯 Decision 函数可以输入有权政策版本和同一权威快照，输出条件性结果及命中依据；不写状态、不调用外部服务。若 ALLOW 之后事实改变，执行者必须按获权提交合同重新核对相关状态/版本/权限或使用合适事务保证；本地判断不是远端授权凭证。教学 A、B 各看到可售1并获 ALLOW，各提交1若不保护联合约束将超额；应在同一权威资源的提交边界检查剩余量，或采用已批准的独立额度。跨多行/远端效果需各自合同，参见 [T27b-1](T27b-1-relational-data-and-transactions.md) 与 [T27c-2](T27c-2-distributed-consistency-coordination-recovery.md)。执行后读取实际效果；超时不自动变成 DENY 或安全重放。
