## 1. 设计从行为和数据责任开始

先列真实消费者、输入、输出、错误、修改状态、资源生命周期、调用完成点、合法变化轴；再决定函数、局部 helper、模块、公共接口、替换组件。函数不一定纯，模块不一定类；需要理由的是某个边界能隔离哪些知识与变化、保护哪个不变量。一个有多步但同一事务/责任的业务操作可有内聚性；把每一步做成跨模块公共函数可能破坏不变量。

内聚关注内部职责为何一起存在、何种变化共同发生；耦合关注外部必须知道或依赖的细节（数据形状、顺序、时序、共享资源、失败处理、版本、权限）。文件数量、函数行数、参数数量只是线索。循环依赖也可能隐藏在回调、共享数据库表、初始化顺序、隐式环境变量，不只 import 图。

| 候选设计 | 判断证据 | 反例 |
|---|---|---|
| 局部函数 | 单一局部机制，无独立消费者 | 为单次三行转换建公开接口，额外兼容承诺 |
| 内聚模块 | 独立状态/不变量、共同变化，明确输入输出 | 将所有工具按动词放 Utils，数据 owner 分散 |
| 窄公共合同 | 实际调用者只需稳定能力，能定义错误及状态 | 公开内部可变 map，调用者绕过维护 |
| 组合/委托 | 同一业务主合同，附加能力有独立责任 | 把不同业务规则伪装同一策略，调用者无法区分结果 |
| 继承/替换 | 子类在支持条件下保持消费者合同 | 覆盖方法更改错误或副作用，却认为同签名即可替换 |

真实 T17 Oscar 级联允许跳过不合格订单行，而 Odoo 扩展库存职责；参见 [T17-C01/C03](../casebook/waves/T17-business-function-abstraction.md)。不因名字都是订单动作就合并不同规则；不把项目片段推断成全系统事务或权限。真实选择还需外部业务事实。R19 的变化轴判断应与下述表示合同联合使用。

## 2. 抽象值与表示不变量

设 A 为外部抽象值集合，R 为具体表示集合。表示不变量 RI(r) 判断 r 是否为合法表示；抽象函数 AF 将合法 r 映射到 A。一个抽象值可以对应多个合法表示。仅声明字段类型无法定义所有语义。构造者必须建立 RI，后续操作必须使可观察边界上的合法状态持续满足 RI；临时中间状态若在独占操作内部且不被外部观察，可由明确实现保证最终恢复，不能让异常/回调暴露非法状态。

教学例：整数区间集合，抽象值是被包含的整数集合（假定有限、整数运算精确）。表示为按起点排序的闭区间序列。
```text
RI: each lo <= hi; ranges ordered; next.lo > previous.hi + 1
AF: union of all integers x with lo <= x <= hi
```
合法 [(1,3),(7,8)]；[(1,2),(3,3),(7,8)] 映射数学集合相同但违反本规范的合并约束；空序列合法。另一实现可以用无序 set，RI/成本不同、抽象行为相同。若领域需要保留原区间来源/重叠历史，抽象值不再是单纯集合，不能共用此设计。

添加 [4,6] 应合并成 [(1,8)]。纸面推理：原有区间有序，遍历时将当前新区间与相交或相邻部分合并，输出尚不相交且有序的部分；最终输出覆盖原集合与新区间的并集且无相邻项。数值上溢风险在固定宽整数的 hi+1，需改用安全比较或规定合法范围；不能由数学证明自动推出具体语言安全。测试空集、相邻两边、包含、无交、极端整数，Oracle 用小范围独立集合展开；大范围不要求逐整数物化。无执行。

## 3. 修改范围（frame condition）与别名

后置条件不仅说明“返回正确”，还须描述允许修改哪些可观察对象和不允许改变哪些对象。若不描述，调用者无法推断状态是否保留。frame 是行为合同，不要求任何特定语言语法。例：更新订单某行备注，必须保持数量、价格、其他行及订单身份（假设业务允许备注修改）；原型不允许意外更新库存。若多个引用指向同一对象，修改一处会被另一引用观察到；仅声明参数为只读视图也不证明没有其他可变别名。

```text
createRangeSet(input):
  copy or establish exclusive ownership of input
  validate/normalize representation
  return opaque set

ranges(set):
  return independent snapshot or explicitly scoped read-only view
```
反例：构造函数保存外部数组引用，调用者在构造后 append [0,0] 打破顺序；getter 返回内部数组，调用者绕过合并逻辑。浅复制若内含可变 interval 对象，仍有共享引用。候选：
- 值/不可变结构：分享安全取决于深层语义；复制/持久数据结构有成本。
- 防御性复制：隔离输入/输出，成本随数据规模与访问频率；必要时只复制可变边界。
- 明确所有权移交/借用：降低复制，依语言及运行时约束；必须避免释放后访问与多写者。
- 受控视图：只有确需观察 live 状态时使用，注明有效期、同步条件、读取一致性。不能把“只读类型”当运行时冻结。

## 4. 行为合同与错误边界

参数可选、默认值、null/缺失、空集合分别有不同含义；不可因实现方便合并。例如 patch 中缺失字段代表不修改，而显式 null 代表清空，空字符串可能是合法值。边界先解析形状、再验证业务合同，不将不可信外部对象 cast 成有效领域值。类型表达某些结构约束，但持久状态、权限与外部效果需真实合同。

函数可声明前置、后置、错误集合、完成/取消含义及 frame。比较总函数返回 Result（含合法业务拒绝）与异常传播（非局部失败）；两者皆可合理，依据消费者、语言惯例、恢复责任、错误不可忽略程度。避免将所有异常吞成 false；也不要求每一层重新包装同样错误。保留因果、可观察阶段、已知效果及安全下一步，错误上下文不含秘密。参见 [K03 错误语义](../../../v2.1.2/software-engineering-knowledge/K03/advanced-error-semantics-observability-and-validation-proof.md)。

## 5. 资源与控制流

资源（文件句柄、连接、锁、订阅、计时器）生命周期与业务操作不是同一件事。构造失败后是否取得部分资源、谁负责释放、释放顺序、重复关闭、异常中的清理失败、异步取消是否已收敛，都需要合同。资源所有者应尽量靠近获取/使用边界，跨模块传递需明确移交或借用。
```text
acquire A
try:
  acquire B
  try:
    work(A,B)
  finally:
    release B
finally:
  release A
```
这是结构示意，不是某语言完整异常实现；若 release B 抛出可能掩盖 work 的原始失败，实际语言的 finally/exception suppression/RAII 规则不同；需保留主故障与清理故障事实。若 acquire B 失败不得释放未取得的 B，仍处理 A。取消请求后仍可能执行清理/远端提交；不能在资源未释放前通知“全部停止”。语言级实现细节留 T27d/T25b，现有 [T16 跨语言退出](../casebook/waves/T16-cross-language-scope-exit.md) 已有 Java/C++/Rust 源例，非统一语言语义。

## 6. 设计评审的实际判断

先画真实数据流（谁创建、谁读取/修改、谁持久化）与控制流（谁调用、等待、捕获、恢复），再检查异常路径和变化传播。图可简为文字，不强制 UML 或额外类。若把模块 A 的内部存储从数组改为树，理想观察是合法消费者无需改变；若调用者依赖数组顺序或直接改内部内容，需承认现有合同包含表示泄漏，不能冒充无行为变化重构。设计文档写重要 AF/RI、公共合同及被拒绝候选，避免只复制源码结构。

| 设计反例 | 区分性 Oracle（NOT_RUN） |
|---|---|
| helper 合并不同错误/状态策略 | 两种消费者的同一异常分别检查原合法合同 |
| 表示泄漏 | 构造后修改输入、修改返回快照、异常中断，RI 仍成立 |
| frame 越界 | 更新一个实体时对未授权对象及外部效果作负断言 |
| 资源未释放 | 获取 B 失败/工作失败/清理失败/取消，核真实持有资源与原始错误 |
| 接口虚假替换 | 同一输入、合法前置与独立预期下比较两实现，不能只比签名 |
