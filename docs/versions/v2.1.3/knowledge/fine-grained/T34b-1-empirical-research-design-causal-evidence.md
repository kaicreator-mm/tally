# T34b-1 · 实证软件工程：研究设计、因果识别与可复查证据

## 1. 研究问题决定方法，不以单一实验形式替代专业判断

ACM SIGSOFT Empirical Standards 区分研究方法及相应证据期望。选择要回答的实际问题，而不是为满足形式将一切叫做实验。
| 方法 | 可回答的问题及证据 | 不能直接推出 |
|---|---|---|
| 受控实验/准实验 | 操纵明确干预，比较预定结局；记录分配、对象、外部变量与偏差；准实验无随机分配 | 全部团队与未来任务的普遍因果 |
| 工程制品评价/基准 | 固定输入与可反驳合同，测算法、工具、LLM制品行为与成本 | 人类体验、真实长期组织效益 |
| 案例研究 | 在真实情境中研究机制及变化，通过多来源事实、时间线、解释及反例建立证据链 | 总体发生率或随机实验效应 |
| 仓库数据挖掘 | 对明确采样框和记录单位提取历史事件，描述/建模实际趋势 | 每个未记录行为或相关性即因果 |
| 问卷/访谈 | 获得真实参与者的自述、理解及实践障碍，按适用采样与分析方法 | 单凭自述证明代码质量或真实工时 |

实际选择例：要解释为何两个模块被错误合并，可研究真实变更、原始需求、评审、测试及维护者叙述，寻找相互矛盾的证据，而不是只访谈作者。要比较某种知识输入是否改善架构和代码，宜控制任务与执行条件，观察真实制品。若仅有单项目前后数据，可作情境化比较，不自动宣称因果。SIGSOFT Experiments 标准页面限定人类参与者实验；纯模型/工具实验可借鉴其控制与报告原则，依据实际研究方法选择其它适用标准，不宣称人类实验规范直接适用所有 Agent。

## 2. 把知识干预分解成可识别条件

研究对象示例：相同合法需求、初始仓库、模型、工具、预算和流程约束下，专业知识是否使真实工程制品更正确、维护更容易？目标量（estimand）先定义为指定任务总体、固定观察期和独立验收合同下，不同分配策略的合格率差及总资源差。处理分配、实际接收/使用、最终结局是不同事实。知识被提供但未被采用仍属于原分配组，按 EMP 保留全部分配任务，另记录实际消费机制，不能删去未使用者后声称因果。

教学 2×2 设计：因素 K=是否提供冻结的相关知识；因素 S=是否在各阶段按任务预定时点提供材料（S=0一次提供）。各组收到同一基础任务、流程和权威合同；K=0使用明确的控制材料，S在两种K水平上都定义为同一阶段化交付策略。控制材料的内容、总预算、可检索范围及阶段开放时点均记录；若不能控制知识长度/上下文，效应定义为整套交付策略差异，不冒称纯知识语义效应。
| 合成全分配结局 | S=0 | S=1 |
|---|---:|---:|
| K=0 | 10/20=.50 | 11/20=.55 |
| K=1 | 12/20=.60 | 16/20=.80 |

固定 S=0 时 K 的合格率差=.10；S=1 时差=.25。差中差交互=.25−.10=.15（15个百分点），等权平均K差=.175。固定 K=0 时S差=.05；K=1 时S差=.20，同样交互=.15。这里是加性比例尺度上的教学估计，不是乘法尺度交互或统计显著性；真实数据需独立单位/分配、预设模型、相关性与区间。不把.80与.50之差.30全部归因于知识，因它同时改变两个因素。若只比较有知识一次给全与无知识分阶段，两个因素完全混杂。

## 3. 从分配到真实执行：阶段、污染与可比性

实验单位可以是隔离的任务执行实例，区组可按任务/初始项目；同一任务多个种子、同一项目多个缺陷或共享人员并不自动独立。选择适合的分层随机或区组设计，事前冻结分配算法、种子、重复次数、目标量、最小有意义效应、样本量依据、分析和停止规则；小样本只能做有限探索，不以一次小样本结果宣称功效充分。各条件独立会话与工作区，阻止读到其它条件产物、参考解及隐藏验收；评审可读取已冻结合同和必要制品，但不应按组别期待改变判据。无法隔离的共享服务、版本变动与执行者学习须记录，不能自称消除全部混杂。

阶段化输入示例：需求阶段提供适用的规则冲突/权威知识，架构阶段提供变化轴/约束/接口，实施阶段提供所需机制，验证阶段提供独立测试设计原则而非隐藏答案，维护阶段按同一新任务观察真实变化。所有组保留相同有权需求与验收事实；不剥夺对照组必须具备的业务合同或安全约束。记录计划输入及实际收到的知识ID/版本、公开可观察工具调用、失效/未发现知识、开始/停止与阶段产物；不得索取隐藏模型推理。仅在架构通过者中比较维护结果会条件化于干预后变量；对所有预分配完整轨迹报告联合合格结局，失败者保留原分母；若维护实际不可达，标未到达，不能伪造维护时长。成功轨迹的维护成本是条件性次要结果。

对公开历史任务，模型训练语料可能已含答案；新任务、私有保留题、隔离输入及独立测试可降低但无法绝对证明无污染。记录任务来源、时间、版本与选择方法，冻结隐藏评价材料及访问边界；不可用知识正文包含同题解或评价标签。模型供应商不披露具体版本/训练数据时，明确不可知；temperature=0或固定seed不等同完全可重现。报告实际模型/工具版本、日期、配置、外部可观测调用、输入及制品身份，保存可依法共享的原始证据或明确删节/限制；不搜集秘密、无权个人数据或内部推理。

## 4. 从资料到结论的效度与可复查链

| 关注点 | 反例与控制 |
|---|---|
| 构念效度 | 把LOC下降叫维护性改善：固定维护任务和独立变化成本/正确性证据，而非单一代理量 |
| 内部效度 | 知识组同时多预算或更简单任务：固定条件、随机/区组及差异记录；不可控时缩小因果表述 |
| 统计结论效度 | 把同一执行中100条日志当100次独立复制：按真实单位、相关结构、预定分析与效应不确定性 |
| 外部效度 | 只在一个语言/简单项目得到收益：明确总体、任务代表性、环境与未来复现边界 |

这些是定量比较常用的关注维度，定性研究还关心可信度、反思性与情境可迁移性，不机械套统计代表性。例：仓库有120个候选修复，自动筛选保留80，人工核查发现其中8为重复/非修复、40排除项抽查发现漏选；应保留采集日期、查询条件、原始ID、包含/排除依据、重复身份、误分类和修订版本；不能从72条确认记录推全部120条准确，也不能因40未读取就称非修复。若研究目标是用户修复成效，仅PR合并记录不够，须链接实际验收/部署/缺陷再现；多个PR可能对应同一任务，定义单位再统计。挖掘资料可用于发现机制和假设，不能在未解决混杂时当干预证据。

区分冻结的确认性分析与探索性发现；保留负结果、偏离方案、未运行、失败、缺失及不同解释，不事后更换主要指标。独立复算同一数据是分析复查；重新执行同一设计是另一轮复制；换任务、环境或方法验证边界是扩展证据，结论可能不同。保留原数据/制品/分析脚本及版本，无法披露则说明影响，不凭可复算纸面例声称真实复制。

## 5. 区分性 Oracle 与来源

| 教学反例（NOT_RUN） | 独立 Oracle |
|---|---|
| 四格只取.80−.50归因K | 按冻结设计/格分母计算各条件差与加性交互，不给未估计显著性 |
| 仅对通过架构者比较维护时长 | 原始分配表及阶段可达性，联合结局与条件描述分开 |
| A组可读B组答案或隐藏验收 | 实际访问边界、输入与制品身份，污染标记；不报无污染的因果结果 |
| 72条仓库修复被当作全集 | 独立复核采样框、筛选/重复、排除抽查与记录范围 |
| 替换模型版本或预算后宣称知识效用 | 独立配置、执行轨迹及差异账本，限制归因；失败全部保留 |
