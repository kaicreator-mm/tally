## 2. 同一个有权教学合同（D0）

教学系统供两个租户导入、规范化、发布文档供本租户搜索。当前只支持两种固定格式，文档有明确大小与资源预算上限，内容和版本元数据均存于同一个事务数据库（无外部对象写入、无付款）。输入格式适配不改变有权字段语义；只有权威验证通过才能发布。合法提交可在持久受理后提前返回任务身份；一旦受理，进程重启不应使其丢失，允许返回明确失败、待处理或已发布。请求超出有权容量时拒绝而非虚假受理。任务只能操作实际有权租户，查询/发布/重试均按当前执行/查询合同确认身份；本例明确撤销编辑权限后尚未提交的发布不得成功，已经发生的合法发布不会因撤权而自动删除。

Q1：同一 tenant/docId/baseVersion 的并发发布不得使两个互相冲突的新版本都从同一 base 成为当前版本；内容与当前指针、成功任务结果、供索引读取的持久变更记录在共同事务提交。重复同作用域、同操作ID和规范输入只读已有结果（仍须当前查询权）；同 ID 改输入拒绝。Q2：受理后重启，待办与最终状态可查询；中途准备内容不等于发布，失去响应需核权威记录；旧 worker 不能提交过期版本。Q3：搜索允许显示标明版本/陈旧的结果，但不能返回未获权内容；索引不得成为当前发布/授权的权威。Q4：增加一种合法格式不得改变旧格式与业务不变量；不同格式只有确有相同规范值语义才共享。Q5：处理/积压/内存有界；实际阈值、流量、恢复时间和分位数尚未给出，故不能宣称任何候选已满足性能 SLA。Q1–Q4 为本例必需合同，Q5 须在实际获权预算下证实。

权限、目标、失败行为是候选共同约束，不能把分布式候选改成“最终会一致”从而降低 Q1 或把简单候选删除重启要求。当前没有第三方插件作者、独立发布团队或不同地域的部署需求；后文变体改变前提时明确标记，而不是假定现状。

## 3. 用四个正交维度比较并组合架构

| 维度 | 当前最小候选 | 何时扩展及付出的代价 |
|---|---|---|
| 静态模块/依赖 | 入站适配、文档业务模块、持久任务执行、查询投影；模块化单体，可按业务职责包含内部层。简单模块直接调用；真实变更边界才用窄 port。 | 多入口/可替换存储需稳定合同与 adapter；接口/类型本身不隔离状态/授权，间接层有维护代价。 |
| 算法/控制流 | parse→normalize→validate→prepare→publish 的类型化顺序；中间纯阶段保持窄输入输出；publish 是一次获权业务动作，不是任意 stage。 | 多格式或合法依赖分支时可用明确 pipeline/graph；独立无共享写入且无因果依赖才并行。泛型 process(any) 会隐藏类型/错误与 Effect；DAG 不自动解决重复或撤销。 |
| 运行连接 | API 同步完成持久受理/查询，持久任务由有限 worker 处理；提交后索引 worker 消费变更记录，异步投影。 | 需要独立消费者或不同处理速率可采用持久消息；事件是已发生事实，命令是请求动作。消息交付与业务提交仍需各自保证，R4-B 补具体 broker。 |
| 部署/扩展 | 一个部署内 API 与 worker，共同 DB；固定两适配器静态选择，非动态插件。 | 独立伸缩/进程隔离可拆 worker 部署仍共 DB；不同团队/运行位置需要版本化扩展点时再考虑插件宿主/服务，新增通信、授权、生命周期、版本、恢复、容量与观测成本。 |

“模块化单体 + 内部分层 + pipeline + 事件投影”是一套可组合方案，不是四个互斥架构。插件也是扩展和绑定方式，既可在同进程亦可在另进程；能部署独立不代表应该拆业务状态所有权。MVC 可以是入站表示方式，不要求领域数据模型和数据库表一一对应。观察到所有文件按 controller/service/repository 放置也不证明依赖边界有效；必须查实际跨模块调用与写集。

教学静态依赖及运行视图（箭头含义分别标记）：
```text
[源码允许依赖]
HTTP/UI adapter ──> Publish/Query application boundary
Worker entry ────> Publish use case ──> domain rules
                        │
                        ├──> approved Format adapters via narrow contract
                        └──> publication store contract <── DB adapter
Index projector ──> read committed change contract + index writer
(Format adapter 不调用 publish 或持久化，Index 不拥有 Publish 权限)

[运行与数据通路；一个部署]
Client -> API -> DB: accepted Task + scoped source
                 ^             |
                 |         Worker read/claim -> parse -> normalize -> validate
                 |             |
                 +-- transaction: content + current version + Task outcome + change
                               |
Index projector <--- read committed change ----+
Search API -> authorized current scope + index result (version)
```
当前共同 DB 是共享故障域；进程崩溃与 DB 故障不同。发布写者由 domain use case 和受保护持久提交机制共同落实；Index 只写派生状态。实际 port 的依赖方向须按所选语言/装配核对，上图是约束候选而非真实代码图。接口可共享，但同一业务结果只能有有权的提交点。

## 4. 同一 D0 下的可反驳候选

| 候选 | 合同适配与拒绝理由 | 反转/复议条件 |
|---|---|---|
| A 直接同步函数，无持久待办 | 若只在完整提交后成功响应且不承诺提前受理，可简单；但 D0 已要求持久受理后可提前返回，未完成待办重启仍可查；A 原形不满足此受理路径 | 有权取消提前受理/待办要求，且单次处理有界，重新比较 |
| B 模块化单体，直接/窄接口+类型化 pipeline+持久任务+异步投影 | 候选基线，共同事务保护 Q1，持久记录满足 Q2 的机制前提，查询再核权限、当前范围，阶段纯机制可按格式变化；需实际证明并发、恢复、容量和版本 | 共享进程造成实际不满足响应/隔离或有独立伸缩需求，比较 C |
| C API/worker/索引 worker 独立部署，仍同一权威 DB | 可保护同一业务提交，限制处理资源并隔离部分进程故障；不同实例需真实 lease/版本约束和资源配额，DB 故障仍共同，网络与发布复杂度增加 | 实际故障域、维护独立性或测量支持；若 DB 为瓶颈，拆 worker 并不证明改进 |
| D 形式/发布/索引独立服务、各自 DB 和事件 | 索引本已派生，可以独立持有投影；但若把内容、当前版本、任务成功写入不同 DB 后逐个发事件，不再满足 D0 同一原子提交，暂拒。格式服务可计算但不能获得发布写权；超时/版本/负载需额外合同 | 有真实独立团队/资源需求，保留发布权威共同事务或取得新的明确业务合同并重新证明跨域一致性；不自动以 saga 替代原合同 |
| E 以动态插件机制替代固定格式适配 | 仅两种已知固定格式、无外部独立发布，动态扫描/任意 hook 增加不必要能力和风险；不能把 plugin 返回“valid”当权威校验 | 实际第三方发布、版本和运行位置需求出现，明确插件输入输出/版本/拒绝、能力最小化、真实隔离、终止与资源预算，核心仍验证及提交 |

不把候选 B 写成唯一正确设计：满足同一合同的其它实现可接受。这里选择 B 为待验证的最小教学基线；Q5 未知，无法排序实际吞吐/成本。两种架构若都未满足硬约束，不能因某种更容易测试而宣布其合格。B 现有文档适配也可以先用直接函数，只有第二种格式的独立变化合同明确才引入 port。真实部署演进参考 [T32a-1](T32a-1-maintenance-refactoring-replacement.md) 与 [T32b-1](T32b-1-data-migration-and-mixed-consumers.md)。

## 5. 处理链、提交与失败的实质推理

假定租户 A 文档当前 v7；两个已受理任务 X/Y 均携带 base v7。X 解析/规范化/验证后获得候选内容 cX，Y 获 cY；中间产物只允许作为任务局部准备数据，不能对外标已发布。最终事务内重新核当前授权、任务身份/合法执行许可、baseVersion 和数据约束；在同一受保护权威提交中生成 v8 内容、更新当前指针、任务成功结果及相应 change 记录。若 X 先成功，Y 不能再基于 v7 晋升 v9 或覆盖 v8；Y 按 D0 明确拒绝冲突或等待新的受权任务，不偷偷重新基于 v8。若授权在提交前撤销，旧许可不能授权写；具体保护提交时授权竞态需与权威状态一致（若授权在不同系统，需额外协议并重新评价 D0，不凭一次远端读取证明）。

提交之后产生 DocumentPublished(A,docId,v8,changeId) 这一已发生事实；将其与“请建立索引”命令区分。索引失败不得把已经合法发布回滚成未发布，亦不得报告“已搜索到全部最新版”。对同一文档的旧变更晚到，仅按实际版本合同及完整投影机制拒绝覆盖新版本；重放不得新增权威文档。若搜索权威许可已撤销，旧索引数据不能泄露，按当前受信权限范围及实际查询合同过滤，必要时拒绝/重建；不能仅在最终 UI 隐藏，若授权结果排名/截断受未授权数据影响还须按具体合同验证（复用 T06-C05）。本例未指定 broker 或投影协议，不声称全局 exactly-once；[T27c-2](T27c-2-distributed-consistency-coordination-recovery.md) 的实际 etcd 条件不外推到任意事件系统。

| 教学故障/变化 | 独立应有事实（NOT_RUN） |
|---|---|
| 持久受理前崩溃 vs 提交后 ACK 丢失 | 前者若权威证实未受理可重新请求；后者以同身份查询，不能靠新 ID 重复受理或假报失败 |
| parse 成功但 validate 拒绝/插件抛错 | 权威当前仍 v7；无成功任务与 change；记录真实失败/未决并清理临时资源；允许合法重试的范围依实际合同 |
| 两 worker 同时读取 v7 | 在共同原子提交下至多一个成功；核内容、当前指针、任务 outcome、change 一致；仅检查最终指针会漏双成功 |
| 业务提交后索引 worker 崩溃 | v8 与 change 仍在；索引标陈旧/未完成；按实际持久 checkpoint 恢复；不得因消费 ACK 推断已应用 |
| 旧索引/权限变化/跨租户有效文档ID | 合法范围结果正确且无禁止披露/修改；独立从当前权威身份与版本推导，不用目标索引生成 Expected |
| 新增固定格式或实际插件需求 | 原格式合法/非法值与行为不变；新格式越权/超预算/错误结果被核心拒绝；检查实际允许依赖、运行位置、已支持消费者；无插件需求不强制动态机制 |
| 独立部署重启、共享 DB 不可达 | 允许重启的待办恢复按事实；DB 不可达不能虚假受理或确认发布；分进程不等于独立数据库故障域 |

这些验证要求源、调用/运行视图、权威前后状态、实际消费者和受控失败证据；图或测试定义本身不是执行结果。只有随后真实维护任务、同一质量/环境/预算及完整分派结果才能评价架构变化的成本和效用（[T34b-1](T34b-1-empirical-research-design-causal-evidence.md)、[T34b-2](T34b-2-engineering-measurement-human-factors.md)）。具体消息协议、数据生命周期、部署、复杂产品专项由 R4-B/C/D 或 RE-04 继续，不在本章重复或晋升。
