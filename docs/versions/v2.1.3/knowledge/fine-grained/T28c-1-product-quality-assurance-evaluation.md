# T28c-1 · 产品质量目标、质量保证与评价范围

#604；K05 主责，K01 需求、K02 架构、K10 运营、K11 经济与测量。复用 [V&V](../../../v2.1.2/software-engineering-knowledge/K05/advanced-verification-validation-and-oracle-qualification.md)、[T26a-1](T26a-1-architecture-scenarios-views-variability.md)、[T24c](T24c-human-computer-interaction.md)、[T28a-1](T28a-1-test-design-stateful-isolation.md)、[T28a-2](T28a-2-consumer-contracts-installed-artifacts.md)、[T25d-1](T25d-1-probability-statistics-engineering-measurement.md)。本章为评价设计与质量保证的专业增量，例/Oracle NOT_RUN，不是认证方案。

## 1. 质量对象、需求与评价问题

产品质量不能以代码风格、测试数或单一用户评分代替。ISO/IEC 25010:2023 官方摘要说明其产品质量模型包含九项特性及子特性，可用于需求、设计、评价、验收及测量；适用对象含软件及 ICT 产品组件。这里只核摘要，不列举未经全文核实的特性/子特性或强制条款，不把2011版分类当2023版。实际工程可选以下评价问题（原创分类示例，非标准逐项转述）：
| 关注点 | 具体可观察问题 |
|---|---|
| 业务正确性 | 合法用户能否完成目标，非法操作是否被拒绝且无禁止效果 |
| 交互与可访问性 | 用户能否发现任务、理解状态、纠错及借助适用辅助技术完成 |
| 运行效率与可靠性 | 在指定负载和故障下达到何种延迟、完成/恢复与数据损失界限 |
| 维护与兼容 | 指定变更影响哪些消费者，能否独立替换/验证，不遗漏支持环境 |
| 安全及风险 | 数据归属、权限、故障后果和未决风险是否按有权合同处理 |

选定真实用户、使用环境、被测产品边界（含依赖、版本、数据和配置）、质量目标及阈值责任人。质量属性之间可能冲突：增加同步校验提高正确性证据却增加延迟；不能由一个属性评分推导全局最优。产品质量与实际使用成效相关但不同：功能正确的系统仍可能使用户任务失败，原因可以是术语、环境或组织流程；需实际观察，不能直接判根因。

## 2. 保证、控制和独立评价的分工

本章以工程职责区分：质量保证关注建立和保持可信过程与证据（例如需求追溯、独立 Oracle、制品身份、变更影响及发现机制）；质量控制关注指定对象实际满足判据与缺陷处置（例如真实测试、评审、测量及不合格处理）。二者并非互斥岗位或固定流程。V&V 的职责及测试层沿用原专业正文；过程检查通过不能代替产品行为验证，产品某项通过也不能证明过程完整。独立性按风险安排，例如作者可先检查；高风险或循环自证可能需非作者、外部权威数据或独立测量，不强制所有小改动采用同一审核形式。

教学例：桌面库存软件的用户希望首次启动即可配置，配置未完成不得执行无权预留。过程保证检查目标/角色/支持平台的规格和验收责任、包来源、测试发现及真实数据隔离；控制实际观察新用户启动、配置取消、错误恢复、直接调用业务入口和真实持久结果。测试套件绿但漏掉首次启动入口，属于证据缺口；完整流程记录也不能证明用户看得懂错误。

## 3. 从质量目标导出可执行评价合同

教学目标（假定有权批准，并非 Tally 当前规定）：
| ID | 场景、判据及观察方法 | 不能替代 |
|---|---|---|
| Q1 | 在空配置的新用户环境，未获权前预留请求不得产生持久预留；合法配置后可执行；独立查业务记录及直接 API 负例 | 仅按钮隐藏 |
| Q2 | 固定100项查询/指定设备、负载、网络，95%的全部尝试在500ms内成功返回正确结果；超时/错误保留分母；记录计时起止、原始每项结果 | 只统计成功项平均耗时 |
| Q3 | 指定支持平台的报错与恢复流程能仅用键盘完成，焦点顺序合理，错误可定位且合法输入不丢失；实际执行完整任务 | 自动扫描首页 |
| Q4 | 模拟指定断网及重启后，已确认的预留与独立权威记录对账一致，未确认显示未知；在规定恢复界限内核观察点 | 进程已启动或日志无异常 |

Q2 示例固定100次尝试：94次500ms内正确完成、4次较晚正确完成、2次超时，结果94/100=94%，不满足95%；若只看成功98次，则94/98≈95.92%会误判。此处指标是全尝试期限内正确完成比例，不是成功请求延迟的p95，另需实际代表性与不确定性；统计推断见 T25d-1。对Q4恢复界限未给具体阈值时，恢复时间目标仍待确认，不能填入任意值。每个判据需独立 Expected、实际观测、覆盖域与不适用理由。

## 4. 风险驱动抽样与可访问性完整过程

评价不必遍历所有同质页面，但必须先探索真实产品和不同模板、状态、组件、关键过程、设备及支持技术。W3C WCAG-EM 2.0 Group Note（2026-07）提供针对数字产品 WCAG 2 的方法：定义范围/目标级别/支持基线，探索产品，选择结构化与随机样本并覆盖完整过程，实际评价及报告。它是评价方法说明，不是替代 WCAG 的成功准则或自动认证。实际评价需要专业能力；本章未重读所有 WCAG 条款，不声称任何产品符合标准。

假设评价报销系统：入口、表单、凭据上传、校验错误、确认、提交、结果查询、取消恢复属于同一或相关完整任务，选择结构化样本覆盖各个相关步骤和独特状态，再按方法选额外随机样本用于发现遗漏；随机不等于代表所有高风险状态，也不能用平均分抵消不符合项。仅首页无自动检测错误，无法推出上传、焦点移动或提交后的错误可访问；自动扫描、键盘/辅助技术人工检查、代表用户任务观察回答不同问题。若选中某完整过程需评估其每个相关步骤与必要交互，不能跳过错误恢复再宣称过程合格。记录所用辅助技术、浏览器/平台、语言、用户任务、实际观察和限制。样本评价不自动覆盖未评状态、所有残障人群或所有产品版本。

## 5. 质量证据聚合和变更后的有效性

评价账本以每个目标和实际支持范围为行：PASS/FAIL/NOT_RUN/UNKNOWN/NOT_APPLICABLE（不适用须有依据），记录版本、环境、方法、样本与独立观察。区分观察失败、Oracle 不合格、环境不可达和产品缺陷根因未知。若授权合同要求 Q1..Q4 都通过，Q1失败、Q2/Q3通过、Q4未运行，不能给整体PASS；Q4未运行不是观测失败，也不能被忽略。评分只能在有权决策允许权衡的目标上应用，先处理强制门槛和风险，不能用高性能分抵消越权效果。风险接受必须由适当责任人基于影响、剩余风险、临时措施和时限决定；不是评价者自行批准发布。

变更后按影响判断证据复用：文字更正不改变被测行为时可限定复用；改变错误焦点、首次启动权限、包入口或真实支持平台时重验相关任务及边界；回归范围不能只看改动行数。缺陷关闭需区分修复提交、回归验证、独立证据和最终适用范围。正式发布仍按产品授权，不由质量模型自动授权。

## 6. 区分性反例与来源

| 教学反例（NOT_RUN） | 拟议 Oracle |
|---|---|
| 100个测试全绿但没发现新用户测试 | 实际发现/执行清单、干净环境真实启动及业务负例 |
| 只测成功请求使比例虚高 | 固定尝试集合及独立结果、超时保留分母、时间戳 |
| 首页自动扫描绿，错误对话框焦点陷入 | 完整任务键盘操作及可访问性检查，实际恢复 |
| 质量综合分优秀但禁止预留已发生 | 权威状态/Effect与获权硬约束对照，不晋升整体PASS |
| Q4恢复目标未定义或未执行 | ASK/UNKNOWN 或 NOT_RUN，保留其余独立结果 |
