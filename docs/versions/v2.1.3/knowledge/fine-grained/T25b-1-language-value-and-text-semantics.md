## 1. 名称、绑定、作用域和求值

语法描述合法程序，静态语义限制某些结构，动态语义描述执行时如何求值、改变状态、完成或失败；实现可优化而不改变规范要求的可观察行为。名称不是对象本身：环境将名称关联到绑定，绑定有作用域、初始化状态和可能的可变性；对象有身份及生命周期。词法作用域由程序嵌套结构决定，不是调用者任意提供同名变量。语言规范的抽象环境也不要求引擎实际分配同名对象。

ECMAScript 2025 §9.1 环境记录的外层链接、创建/初始化/取得绑定是不同动作。以下两段是独立教学反例：
```js
let limit = 10;
{
  // 内层绑定已存在但尚未初始化；不会回退到外层。
  console.log(limit); // ReferenceError
  let limit = 20;
}
```
```python
limit = 10
def configure():
    print(limit)  # UnboundLocalError
    limit = 20
```
Python 3.11 §4.2.2 对函数块中的名称绑定有整块局部分类；它不是 JS 的块级 let 规则。修复先明确本函数是否应读取外层值、持有自己的值或显式修改外层，不能通过任意改全局变量消除错误。

求值还涉及何时执行、是否短路、调用次数、异常传播。不要把带副作用的表达式当纯数学式任意交换或重复：例如读取一次可变配置并验证后使用，比先验证 getConfig() 再次 getConfig() 更容易建立同一值的合同；但若要求检测最新配置，缓存反而可能错误。具体求值顺序与运算符重载按目标语言规范，不能从本章两个例子推导所有语言规则。

## 2. 闭包、对象身份及共享

闭包使函数可使用定义时的词法环境，不意味着创建时把每个变量值复制一份。JS 教学例：
```js
let mode = "draft";
const getMode = () => mode;
mode = "ready";
// getMode() -> "ready"
```
若需要任务提交时的模式快照，应在提交点创建独立绑定或值，而非在执行时读取活配置。即使绑定不可重新赋值，若绑定值是可变对象，内部字段仍可能变化。
```js
const a = { items: [{ qty: 1 }] };
const b = { ...a };
b.items[0].qty = 2;
// a.items[0].qty 也是 2
```
复制顶层属性不等于深层隔离。函数传入对象后修改属性与重新赋值参数是不同动作；不要用“所有对象按引用传递”掩盖重新绑定不改变调用者绑定。Python 3.11 数据模型区分对象身份、类型和值，容器可含可变对象；不可变 tuple 内的 list 仍可修改。用身份判断同一对象、用明确相等关系判断领域值；哈希键必须与相等关系及其稳定性一致。表示泄漏、frame 与所有权的工程选择统一参见 T27a，不重复定义。

## 3. 类型与跨边界表示

类型是允许操作/值及推理约束的描述；静态检查、运行时表示、外部数据合同是三个层次。泛型参数描述相关类型之间的关系，不能仅通过泛型或类型断言证明网络数据合法。联合类型可帮助表达已知状态集合；对未来未知值需明确拒绝/兼容策略。null、undefined、缺失字段、空值、0 与 false 不是统一“没值”。例如 PATCH 约定字段缺失为保留、null 为清除、空字符串为实际值：解析要保留属性存在性，不能用 truthy 过滤。不同序列化格式可能无法无损表示全部语言值；先规定 wire domain，再决定拒绝或有权编码。业务身份、金额和时间等不能用显示字符串自动恢复真实原始值。

## 4. 数值表示和精度

| 表示 | 机制和风险 | 适用选择 |
|---|---|---|
| 固定宽整数 | 有界值域；超范围的截断/异常/未定义行为由具体语言及运算决定 | 已知范围、二进制协议、位运算 |
| 任意精度整数 | 可表达很大整数（仍受资源限制） | 大标识、精确计数；跨边界须保真 |
| 二进制浮点 | 有限有效位、指数及舍入；十进制分数可能无法精确表示 | 测量/数值计算，按误差合同验证 |
| 定点/十进制 | 明确比例、单位、舍入与范围 | 需要确定十进制精度的合同；并非所有金融/业务规则的唯一方案 |

ECMAScript 2025 §6.1.6.1 Number 基于 binary64（含 NaN、正负零、无穷），连续安全整数范围为 ±(2^53−1)，2^53 本身可表示但与 2^53+1 转成 Number 后无法区分。教学反例：两个 64 位设备标识以 JSON 数字传输，解析到 Number 后可能合并；若上游协议可选，以十进制字符串传递并作格式/范围校验，或明确支持任意精度端到端编码。BigInt 与 Number 不能无条件混算；不要先把丢精度的 Number 再转 BigInt 以为恢复原值。

二进制浮点相加可能舍入；例如 0.1+0.2 不等于 Number 表示的 0.3。测量值可按实际绝对/相对误差设计比较，绝对误差适于接近零的范围；身份或财务确切金额不能随意用 epsilon 判等。累积计算须分析运算顺序及误差传播。定点教学：单位为 0.01，存 105 代表 1.05；乘除后必须规定何时舍入，逐项舍入与汇总舍入可能不同（两笔 0.005，按假定 half-up 分别成 0.01+0.01；汇总 0.010 只成 0.01）。这是差异证明，不授权采用该舍入政策。还需校验单位换算、范围、负值、NaN/Infinity 输入和输出表示。

## 5. 文本：字节、代码单位、标量、用户感知字符

UTF-8 编码字节、UTF-16 代码单位、Unicode 代码点、extended grapheme cluster（EGC）不能互换；Unicode scalar value 不包含代理码点。JS String 是 16 位代码单位序列（允许未配对代理），length 不是代码点数；Python str 的长度/索引以代码点计，不等于 EGC。以下是合法文本在 UTF-8/UTF-16 下的纸面计数，UAX29 rev47 默认 EGC：

| 文本 | UTF-8 字节 | UTF-16 单位 | 代码点 | EGC |
|---|---:|---:|---:|---:|
| A | 1 | 1 | 1 | 1 |
| U+1F600 | 4 | 2 | 1 | 1 |
| e + U+0301 | 3 | 2 | 2 | 1 |
| U+00E9 | 2 | 1 | 1 | 1 |

限制文件/协议大小用字节，限制 UI 可见输入可用与目标用户一致的分段合同；数据库字段容量、索引长度另核引擎。不能把 JS substring 任意截断当合法 Unicode 截断。流解码时字节可在多字节编码中间断开，需要保留增量状态（见 T27b-2）。错误编码选择显式拒绝或允许替换并记录信息损失；禁止静默转换身份。

UAX15 rev57 区分 canonical equivalence 与 compatibility equivalence；NFC/NFD 是规范等价方向的两种形式，NFKC/NFKD 引入兼容分解，可能丢失业务意义。例：e+组合符与预组合 é 可 NFC 归一；全角字母与普通字母的兼容映射并非天然业务同一身份。规范化、大小写折叠、locale 排序、视觉渲染/BiDi 是不同操作。先确定域身份是否允许等价再决定保存原始值和规范键；变更规范化/排序版本可能使旧唯一键发生冲突，需迁移评估。此处不宣称所有 locale 或运行时分段一致。HCI 的错误呈现复用 T24c。

## 6. 典型问题与独立反例

| 问题 | 具体判断 / 教学 Oracle（NOT_RUN） |
|---|---|
| 异步任务读到修改后的配置 | 验证提交快照 vs 执行时读取；两者不同设计，按业务合同 |
| const/readonly 后仍修改内部数组 | 别名和可变对象边界，构造后及返回后的修改反例 |
| 大整数 ID 碰撞 | 2^53 与 2^53+1 比较 wire→parse→key 的精确性 |
| 金额合计不一致 | 明确单位、舍入阶段；以独立整数/十进制推导为预期 |
| 多语言名字长度及搜索冲突 | 测四种文本计数与规范等价/兼容等价，明确目标版本及域政策 |
| 跨语言迁移 | 使用旧/新具体语言语义，检查作用域、异常、溢出、空值与 wire 兼容；不以同名 API 证明行为 |
