# T40-R1 · 从操作合同组合推导职责、状态及提交边界

#650 / #563；K01 业务约束、K02 结构与所有权、K03 合同及实现、K05 独立评价。基线 42332eeb00bc0c1869172a667944e9c02abbc0a7。原创条件推理 DOCUMENT_CANDIDATE，所有目标执行 NOT_RUN；不是新业务政策、形式化工具验证或产品设计。复用 T24a §2/5、T24b-1 §4、T27a §1–4、T26a-2 §2–3、T35-1/2、K03 R19 粒度选择、K01 REQ 与 K02 边界；此处补“已知多个局部合同，如何系统检查其组合并得出责任边界”，不重复基础定义。

## 1. 由目标得到状态与行为，而非从功能名得到类

先写出获权可观察目标、合法输入域、状态与历史事实、外部依赖、失败及不改变的事实。以数学状态 s 表示相关抽象事实，I(s) 表示当前共同不变量；对每个操作 A，定义前置 P_A、允许的状态转移关系 Q_A(s,s',result)、读依赖 R_A、允许修改 W_A、权限及外部效果。这里集合是抽象事实/资源身份而非简单字段名；例如“当前可售”依赖所有活动预留，即使实现中没有可售字段。读取的范围/谓词、版本、权限及不存在的记录也可能是依赖；写入集合含间接变化的派生事实，不能只抄 SQL 列。失败/UNKNOWN 要另描述观察和义务，而不假定无变化。一个读请求可能产生有权审计或实际外部效果，纯函数才有明确无写合同。

对每个获权状态及所有允许结果，若成功且 I(s)∧P_A(s) 成立，应使 I(s') 成立并满足 Q_A；拒绝、异常及部分结果亦按各自合同评价状态和效果。若 I 只在一次受保护的组合结束时成立，组合中间状态须不可被合同外观察、提交或逃逸（包括异常及回调）；否则该中间态本身需要合法合同。操作内部字段完整不等于全局不变量成立。

## 2. 顺序可组合性与失败边界

对 A 后接 B，要验证 A 成功所允许的全部后态满足 B 的所需前置（包括有效权限、时效及版本），或明确存在分支/重新判断。形式上 I(s)∧P_A(s)∧Q_A(s,s1,success) ⇒ P_B(s1) 是无条件继续的充分前提之一，仍须核 B 合同、失败和整体目标；不从名称“prepare”推出“commit 必可执行”。若外部可在两步之间改变状态，须把其获权转移纳入允许历史或用实际事务/版本保护。B 的拒绝是否要求回滚 A，是整体需求而非技术默认。

教学：一份报名必须同时获得名额与设备。A 获取名额，B 获取设备；若名额剩1、设备剩0，A 成功后 B 不满足前置。若要求全有全无，则同权威下将 A/B 的检查、状态、结果共同提交，失败保持两者原状态；不能通过公共 A 成功后调用 B 来承诺全有全无。若获权合同允许暂占名额待设备分配，则 A 后态可成为显式 HELD，保留期限及释放责任；B 失败不等于全局失败，用户应看真实待办或释放结果。不同权威下不能假设同事务，需获权暂态、失败义务或拒绝不可实现的强承诺。补偿是新动作，可能失败，不等于历史未发生。

## 3. 共享约束导致的职责归属

教学目标：项目 P 的活动任务每个占一个配额；每台设备至多一个活动任务；任务只能绑定已启用的设备。任务状态、设备启用、项目配额分别是抽象事实。初始配额2、设备 X/Y 启用、无活动任务。操作 Start(t,d) 需要配额、设备可用及当前权限，成功新增活动绑定；Disable(d) 要求该设备无活动绑定才禁用；ReduceQuota(q) 要求活动数≤q。三动作分别有不同业务资格及写集，但共享不变量 I = activeCount≤quota ∧ 每设备活动数≤1 ∧ 每活动绑定设备启用。

反例 A：Start 与 Disable 都读取 X 空闲/启用，各自检查通过；Start 写任务绑定，Disable 写 enabled=false，二者若按旧读独立提交则得到活动任务绑定禁用设备。即使两动作写不同表、各自字段均合法、各自串行测试通过也失败。反例 B：两个 Start 分别绑定 X/Y，初始 quota=1，两者读 count=0，各自写不同任务，合计2违反 I。反例 C：初始 quota=2、已有一活动任务，Start(Y) 与 ReduceQuota(1) 都各读旧状态，合计2且 quota=1。联合约束不是调用者可以选择略过的校验 helper。

在同一权威 DB 内，最小候选可为一个保护项目配额和设备状态的应用提交边界，内部仍保留不同操作及局部领域模块；按实际竞争域使用合适约束、锁共同记录或可串行化事务与整体重试。若设备可跨项目共享，项目锁单独不足，必须保护真实共享设备竞争域；多个锁需稳定获取协议和错误处理。任务表、设备表及项目表不是自然的三个独立写权威。若所有设备状态变化与任务写入都不经过保护，任何新入口可绕过共同 I。共享不变量要求共同权威/协调机制，并不强制一个类或一个巨大模块；把所有只读查询、渲染、通知也塞进同一事务没有由本例推出的理由。

## 4. 干扰与可安全组合的充分条件

候选静态检查：A 写 B 所读或写的抽象事实，或 B 写 A 所读或写的事实，则存在潜在干扰；要用实际合同判定能否交换、重试或并行。无交集不自动证明安全：R/W 若漏掉全局配额谓词、资源别名、外部限额、权限撤销或提交次序，推理无效。一个保守充分条件是完整且独立的状态分区、读写/效果与授权依赖均独立、局部转移只改变本分区并保持各自不变量，整体不变量确实是局部不变量的合取，且整体目标不要求额外顺序/原子承诺；则单步交错保持合取（按任意有限交错的步数归纳）。这不证明公平性、进展或期限；也不排斥有交集但可交换的数学操作，例如在无溢出、无上限/外部顺序依赖的抽象计数中加法交换，但实际并发写仍需原子机制。

明确两个不同概念：两个转移在同一初态都可执行且两种顺序均合法、最终抽象观察等价，才可在这个合同下称可交换；只比较最终字段而漏掉外部通知顺序或操作返回值不能证明。若操作一方取消另一方的前置，必须选择实际顺序、重新检查，不能并行后再用最后写胜出掩盖失败。状态维度正交（任务、付款、资源）只是表达独立事实，不代表所有转移独立；仅允许的组合及跨维度不变量仍由领域合同定义。

## 5. 从推导结果选择抽象层级

| 已证事实 | 最小选择 | 不应推出 |
|---|---|---|
| 单一操作内部短逻辑，独立无变化 | 内联/局部 helper | 每个步骤一个公共接口 |
| 多入口共享同一纯谓词，真实合同相同 | 共用窄领域谓词 | 纯判断结果等同获权提交 |
| 多操作维护同一跨对象不变量 | 共同提交权威及明确不同操作；内部可再分解 | 每张表独立服务，或所有模块合成一个类 |
| 资源、合同、变化与故障域确实独立 | 分模块/可按证明并行 | 自动引入消息 broker 或微服务 |
| 获权独立部署使权威分裂 | 显式协调、可接受暂态/额度/恢复，再比较结构 | 保留原子承诺而无证明 |

合法变化：若 Disable 政策变为“允许禁用后活动任务继续到期，但禁止新启动”，原 I 的第三项不再成立，须区分设备准入与已有绑定允许继续，变更具体状态/查询/启动合同，不把旧 invariant 继续强制；此时 Start 与 Disable 的实际先后仍决定新任务是否可启动。若配额不再约束已存在任务而只限同时新增速率，需另定义时间窗口和权威计数，不套活动数约束。反向变化若加全局共享设备，重新核跨项目边界，而非只增参数。共享资源身份与政策变化会影响职责分配；仅新增 UI 布局不自动要求变更事务边界。

## 6. 推导检查与停止条件（纸面 NOT_RUN）

从独立有权合同列初态、操作与允许历史；对反例 A/B/C 写出各自读到的状态和两次提交后的 I；再核候选机制能否排除反例而不排除合法操作。若历史先 Disable 后 Start，应拒绝 Start；若先 Start 后 Disable，应拒绝 Disable（原政策）。若只有一个合法候选，记录不可替代的必要能力而非生造模式；若多个候选均满足约束，以实际成本、变化隔离、运维和可逆性比较，不编造性能。状态空间有限时可纸面枚举，较复杂才考虑明确抽象/模型检查，仍不能用模型证明其未建模的实际执行。真实并发/DB/外部效果 NOT_RUN。不是对全部程序的形式化证明。
