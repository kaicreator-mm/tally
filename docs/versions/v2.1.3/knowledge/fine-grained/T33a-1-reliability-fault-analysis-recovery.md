# T33a-1 · 可靠性模型、故障分析与业务恢复目标

## 1. 先定义服务失败，再选择模型

故障来源（fault）、内部错误状态（error）与可观察服务失败（failure）是不同层次：错误配置可能长期未激活；某副本异常但其余副本满足合同，未必发生系统服务失败；返回200却丢失已确认订单是业务失败。某组件的失败可能成为上层的故障来源。以用户操作、必要结果、容忍延迟、禁止效果、观察位置及时间窗定义服务，不以进程活着定义成功。可恢复、可降级与允许拒绝必须由具体业务目标决定。

可靠度 R(t)=P(T>t)，T 是从约定初始状态至首次规定失败的时间，给定任务/环境及观察条件。可用性回答在时刻或时间窗内能否提供规定服务，允许修复后重新可用。教学系统在100小时内故障一次、停1小时后恢复：观察时间可用比例99/100=99%，但此次100小时任务无故障成功指标为0；不能从单次观测估总体可靠度或稳态可用性。若合同按请求统计，必须另有全部有效请求分母；无请求时间不能凭空生成成功。若在长期交替正常/停机的更新模型下，周期均值有限且存在长期平均，则时间可用性可写 E[正常时长]/(E[正常时长]+E[停机时长])；停机包含检测/等待/修复/验证等合同指定时间，不把任意 MTTF/MTTR 口径混入公式。可用性高不能自动证明安全或数据正确。

## 2. 串并联系统、共同原因与假设

NIST e-Handbook 的串联首次失败模型：所有组件必须工作、寿命独立，R_s(t)=∏R_i(t)。并联模型：至少一个工作即可满足完整合同、各组件独立运行至失败，则 F_s(t)=∏F_i(t)，R_s=1−F_s。两者是固定任务时长、不修复的教学概率模型，不能直接用于软件重复请求失败率、复杂切换或活跃主备的稳态可用性。独立性须由依赖/故障域或证据支持，不由部署数决定。

教学：固定任务时长，两个独立节点各 R=.99。若两者均需正常，则 R_s=.9801；若任一足够且无切换故障，则 R_s=.9999。若共享电源/数据库/控制面事件 C 以 .01 概率使两者均失败，C 未发生时各有独立 .01 失败概率，则 P(系统失败)=.01+.99×.01×.01=.010099，可靠度=.989901。这里节点边际失败率变为 .0199，并非仍为 .01；比较的是条件故障与额外共同原因模型。不能把各节点边际概率相乘来消除共享故障。共享发布缺陷、同一凭据失效、相同错误输入、单一网络入口也可能形成共同故障；冗余消除某一单点不代表消除所有相关失败。

## 3. 自底向上与自顶向下分析

FMEA 从组件/功能的失败方式出发，记录功能、模式、原因候选、局部及上层效应、探测、现有控制、行动/责任和剩余未知；不以故障发生频率取代后果，也不把未经定义的严重度×频率×可探测性分数当概率或安全保证。FTA 从明确顶事件反向分解充分原因组合，用 OR/AND 表示逻辑条件；需定义时间窗、状态与事件含义，静态布尔树不能直接表达任意顺序依赖、修复动态或相关概率。

教学顶事件 T：“在约定任务窗内无法按规定期限完成一次获权查询”；C=共享权威数据不可用，A/B=各服务路径失效，G=共同路由失效。假定在固定需求及其他条件正常时，T=C∨G∨(A∧B)，且任一路径正常足以完成。最小割集为 {C}、{G}、{A,B}（每个集合足以导致顶事件，移除其任一成员则不再保证该集合足够；这里是单调静态布尔模型）。并非“最少数量的一个集合”。若 C∧A 也出现在展开式，它被 C 吸收，不是新的最小割集。概率 P(T) 是这些事件的并集，重叠不可直接求和；无独立假设不能随意乘概率。若 C、G、A、B 相互独立且事件定义不重叠于同一原因描述，则 P(T)=1−(1−p_C)(1−p_G)(1−p_Ap_B)。这只是模型推导，不是所有真实故障已枚举的证明。

| 模式教学 FMEA | 可见效应与区分性控制 |
|---|---|
| 主路径 A 停止响应 | 只有 B 在期限内接管并返回正确值才可称服务未失败；验证实际路由和负载 |
| C 权威存储不可读或数据损坏 | 两服务共享 C，副本数量不足以保证；需真实独立恢复点及校验 |
| B 备用路径配置旧凭据 | 正常流量看似无问题，切换时才失败；演练备用路径和版本权限 |
| G 路由错误把请求发给错误租户 | 即使查询响应成功仍可能违反授权；另建“越权结果”顶事件，不能用上面的可用性树覆盖 |

失效模式可反馈 FTA，割集可反向确定故障注入优先级；未发现的路径不因模型图完整就不存在。需要故障检测、隔离、恢复后再进入服务的状态条件；对不可接受错误可按获权合同拒绝/降级而非返回伪成功。

## 4. RTO、RPO 与真正的恢复完成

NIST CSRC 术语以组织业务后果定义恢复时间目标 RTO、以中断后必须恢复的数据时点定义 RPO。工程合同须明确开始事件（例如服务中断，而非运维发现）、恢复结束条件、适用数据范围、认可的持久提交/时间基准、外部效果及例外。RTO/RPO 是目标，不是备份周期、实际恢复时长或数据丢失量的实测。若假设中断10:00、RTO30分钟、RPO5分钟，即要求10:30前满足约定恢复合同、数据可恢复到不早于09:55的合格一致恢复点。若10:12进程启动、10:34才完成获权用户路径及必需对账，则实际34分钟，未满足该RTO；恢复09:53一致快照则时间差7分钟，未满足RPO（若有可验证日志能恢复到09:58，另按实际最终点判断）。两者独立，不能用快速启动抵消数据遗失。只知道最近记录的时间戳不代表从前缀中无空洞；时间差也不等于丢失记录数。若必要外部付款结果 UNKNOWN，保留未知并按获权程序核对，不由快照回退外部资金。

备份设计：确定数据/配置/密钥（按安全授权）/schema/依赖版本的恢复集合；一致快照、增量日志链、完整性校验、隔离及读取权限；验证在隔离环境使用实际恢复制品能够重建并解密，核业务约束、恢复点与日志连续性，检测已确认数据/未知效果。备份作业显示成功不等于可还原；复制可能同步传播误删。旧版本应用读新格式的风险沿用 [T32b-1](T32b-1-data-migration-and-mixed-consumers.md)。切回生产前需有权控制写入与隔离旧写者，不以回滚任意覆盖后来合法数据。

## 5. 区分性反例及资料

| 教学故障（NOT_RUN） | 独立 Oracle |
|---|---|
| A/B 分别停止，再同时失败 | 记录固定期限、真实用户路径、独立正确结果及所有请求；区分单路径故障与顶事件 |
| 注入 C 或 G 单点故障 | 权威记录/网络隔离证据及顶事件；反驳副本独立假设 |
| 切换到旧 B 版本/错误租户 | 实际身份、权限及业务正确性；禁止效果不由HTTP状态代替 |
| 还原备份缺密钥/日志中段 | 实际恢复字节/版本、独立提交序列及数据完整性；不能仅查最新时间戳 |
| 10:12启动、10:34恢复、09:53恢复点 | 独立事件时钟、完成条件及恢复序列；分别裁定RTO/RPO，未知外部Effect保持未决 |
