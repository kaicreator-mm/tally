## 1. 先确定操作合同及工作负荷

| 结构 | 典型操作成本（条件见下） | 主要边界 |
|---|---|---|
| 动态数组 | 下标 O(1)，尾增摊还 O(1)，中间移位 O(n) | 单次扩容可 O(n)，引用/迭代器失效 |
| 链表 | 已持节点及所需前驱时局部插删 O(1)，查找 O(n) | 额外指针、分配、局部性 |
| 有序数组 | 二分查找 O(log n)，插删 O(n) | 保持排序、比较成本 |
| 链式 hash table | 良好分布及受控负载下期望查找 O(1)，最坏 O(n) | 键稳定、碰撞、扩容 |
| 平衡搜索树 | 查找、插删 O(log n)（维持平衡） | 顺序/区间查询、比较合同 |
| 二叉堆 | peek O(1)，插入/取最小 O(log n)（不含扩容，或单独摊还） | 无完整排序、任意查找 O(n) |
| Trie | 长度 L 的键按字符/单位 O(L)（子边访问 O(1)假设） | 字符单位、内存、稀疏分支 |
| B-tree 家族 | 高扇出下减少页层数；理想页模型约 O(log_B n) 查找 | 页大小、缓存、实际键/写放大 |

先明确值身份、顺序、重复、更新频率、范围查询、遍历顺序、持久性及并发，不只看查找复杂度。n 是元素数而非字节；若键为长字符串，哈希/比较也有代价；外存按块访问计，不能简单套 CPU 单位操作。Big-O 是增长上界，Theta 才是同阶上下界；平均/期望来自明确输入或随机机制，摊还是对一串操作的总成本约束，不等同概率平均。真实延迟/内存未测。

## 2. 动态数组：摊还证明与空间代价

教学从容量1、空数组开始，满时容量翻倍，复制已有元素，append 写一次。若恰好插入 n=2^k 个元素，扩容复制总量 1+2+...+2^(k−1)=n−1，加上 n 次新写，总计2n−1。对任意 n≥1，最终容量 C 为不小于 n 的最小2的幂且 C<2n，扩容复制 C−1，总写入成本 <3n（忽略分配初始化等其它成本；若其与容量线性仍同阶）。因此从空开始 n 次尾增的平均摊还成本有常数上界，即使某次 append 复制 Θ(n) 个元素。不能承诺每次延迟 O(1)。容量在增长阶段有闲置，若缩容也在接近满容量阈值进行，交替插删可反复扩/缩；应采用分离阈值或明确不缩容及内存回收策略。具体容器的增长因子/迭代器合同按目标库，不宣称 JS Array 或 Python list 必用2倍。

## 3. 哈希与有序索引

教学哈希 h(k)=k mod 4，键1、5、9 均进入同一个桶；必须以域相等关系区分，不用相同 hash 当身份。若大量键集中同一桶且链式查找，最坏线性；受控负载 α=n/m 和合适随机/分布假设下期望桶查找 O(1+α)（忽略键长度），不是确定的安全性能保证。相等键须有相同 hash，非等键可碰撞。可变键若参与 hash/equality，插入后修改可能使查找失效，见 T25b-1/T27a。建立一次 Map O(n) 期望成本且增加内存；一次小列表查询未必值得。高频范围查询不能用 hash 的点查找复杂度推导；有序结构允许从下界开始枚举 k 个元素（适当平衡树及后继遍历 O(log n+k)），保留比较顺序。数据库索引及实际选择率参见 T27b-1。排序稳定性与业务顺序是合同，不由某个算法名字保证。

## 4. 堆、优先队列与双索引不变量

min-heap 的 RI：完全二叉树且父键≤子键；数组0起始，i 的子节点 2i+1、2i+2（在 n 内），i>0 的父节点 floor((i−1)/2)。根为最小键但兄弟未全序。教学数组 [2,5,4,9,6] 是合法堆，插入1置末尾 index5，与父 index2 的4交换，再与根2交换，得 [1,5,2,9,6,4]。取最小后以末元素移至根，再与较小子节点下沉，维持 RI。堆高度 O(log n)，上浮/下沉单次沿一条路径。相同优先级 FIFO 若为业务要求，需使用定义好的稳定次键，不能假定堆天然稳定。

实际调度器需要 cancel(id)、changePriority(id) 时，普通堆无法 O(log n) 直接定位任意 ID；可额外 Map id→index，交换时同步更新两个映射项，删除后移除对应 ID，所有修改路径维护双索引 RI；或使用带版本的惰性条目，取出时拒绝过期身份并限制积压/清理。两种选择都不能将已出队任务的取消当未出队；任务生命周期见 T27c-1。双索引 O(log n) 更新只在 map 查询/更新期望常数且同步维护、忽略扩容或单列摊还时成立。

### 4.1 任意位置删除及双索引修复（FG12）

教学合同：活动 ID 唯一，重复 ID 插入拒绝（更新是独立操作）；每个活动索引 i 满足 pos[heap[i].id]=i，反向每个 pos 项均指向合法索引且 ID 相等，pos 的定义域恰为活动 ID 集合，基数等于堆长度。交换两元素必须同步更新两项。删除不存在 ID 返回 NOT_FOUND 且不变；删除末项只移除该元素和对应映射；其余删除先将末元素移入空位、缩短数组、删除原 ID 并更新迁入 ID 位置，再按键与父/子的比较决定修复方向。若非根且新键小于父键则上浮，否则下沉到不大于任一子键；每次交换同时维护 pos。相同优先级按实际完整比较合同，不能用优先级充当 ID。changePriority 也在相同不变量下根据新键选择方向。

纸面反例：合法 min-heap [1,5,2,8,9,3,4]，数字是键而非 ID。删除 index3 的8，以末4填入得 [1,5,2,4,9,3]；该叶无子，仅下沉不动却违反父5≤4，必须上浮得 [1,4,2,5,9,3]。反向删除原堆 index2 的2，末4替入得 [1,5,4,8,9,3]，与子3交换得 [1,5,3,8,9,4]，必须下沉。修复前只有迁入位置与邻接边可能失序；若小于父键，则原父键不大于原被删键及原子键，新键不会同时大于子键；否则只需检查向下。上述证明依原堆合法、比较传递及完整树表示。

拟议 Oracle（NOT_RUN）：每一步以独立 ID→键模型核域/基数、所有 pos/heap 双向对应、父子顺序、根及后续取最小序列（相同键按明确次键）；分别注入上浮/下沉、删根/末项、不存在 ID、重复 ID 拒绝与优先级增减；不得以最终排序正确掩盖中间陈旧索引。忽略缩容/Map 成本或单列摊还，沿一条路径 O(log n)；不承诺并发原子性，调用方需按 T27c-1 确保外部观察不到半更新。

## 5. 图表示、遍历与外存

邻接矩阵 Θ(V²) 空间，边存在检查 O(1)；邻接列表 Θ(V+E) 空间（简单有向图，枚举实际边），检查某边通常 O(outdegree) 若列表未索引，枚举邻居按实际度。BFS 使用队列，从起点入队即标记 visited，按距离层扩展；在无权/同权边图中首次发现的距离是最少边数，不能用于任意加权最短路。DFS 使用栈/递归，递归深度可能 V，真实栈容量需考虑。两者访问全部节点/边在邻接列表和常数标记假设下 O(V+E)；从单起点未必访问不连通部分。依赖拓扑与环定位不同，见 T25a-1。外存大规模排序/搜索可能由随机 IO 主导；采用连续块、B-tree 高扇出或外部归并前要核可用内存、页大小、访问分布及写放大，不能用 RAM 复杂度直接报磁盘耗时。
