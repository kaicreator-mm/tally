## 1. 明确模型及独立可行性

教学假定整数时间槽0..6，任务 i 非抢占，持续 d_i>0，开始 s_i、结束 e_i=s_i+d_i，区间 [s_i,e_i)。每任务选恰一合法模式 m_i（模式含可用设备、时长和所有必要资源需求）；模式固定后每种资源 r 的需求 q_ir 在区间内恒定，容量 C_r(t) 由实际时间表给定。可行要求 release_i≤s_i、e_i≤deadline_i（若期限为硬约束）、每个前置 u→v 有 e_u≤s_v、合法模式及授权、每个资源及每时槽总需求≤C_r(t)，且所有已承诺不可移动的时间/模式被固定。未安排若允许需有显式变量及独立服务目标。单任务可行、无环、设备容量足够、各资源单独足够均不证明联合可行。真实连续时间、可抢占、异步等待、setup/切换成本或不确定工期时模型改变，不能套固定槽位结论。

可以用二值 x_(i,m,s) 表达每个合法开始选择，按任务求和=1，按资源/时槽累加覆盖该槽的选择及需求≤容量；结束和开始由选项加权求和，施加前置约束。任何真实合法安排在固定离散模型可编码为满足约束的 x，任一满足约束的 x 给出每任务唯一合法模式/开始及受检查的联合容量，故在给定完整输入和规则时二者对应。不合法选择从变量域排除，不能靠大惩罚。变量数随任务×模式×可选开始增长；也可用区间变量或专用算法，选择取决于实际结构及预算，不声称任一求解器实现。独立 checker 应从解码出的实际区间、资源身份、容量表、依赖和固定承诺重新计算可行性，而非检查求解器输出字符串；未知的实际资源资格不得当合法模式。

## 2. 关键路径、资源下界和可达到计划

有限算例：X/Y 两台独立设备，各容量1；共享技术员 S 容量1；初始全部空闲。A=(X,2)，B=(Y,2)，C=(X+S,2) 依赖 A，D=(Y+S,1) 依赖 A 与 B。全部 release0，工期确定，C、D 均需完整持续占用所列资源，先求最小总完工时刻。
- 忽略资源冲突的最长依赖路径 A→C 长4，A/B→D 长3，故 makespan≥4。这是下界而非可行计划。
- C/D 最早均不能在2之前开始，二者共需3单位 S 时间且容量1，所以它们全部结束不早于5。由此 makespan≥5。
- 候选 A,B=[0,2)，C=[2,4)，D=[4,5) 符合所有资源和依赖，总完工5；等于上述有效下界，故这个固定模型中最优。
- 若再加入硬约束 D 必须在3结束，则上述最优完工计划非法。另一个 A,B=[0,2)，D=[2,3)，C=[3,5) 满足约束且仍达下界5。因此同一 makespan 不表示同一业务结果，贪心优先长任务 C 并不能保证所有期限。

一般在无额外释放/固定承诺的简化模型，可按拓扑序计算最早起点 max(前驱最早结束、release)，最长依赖路径给出忽略资源冲突的完工下界（实际模式工期未知时使用获权的适当下界）。固定资源容量 c>0，总必需资源工量 W=Σ q_i d_i，在起点0且无其它占用的模型中工期至少 W/c，整数时间向上取整；容量随时间变化或固定已有占用时，应核可用容量积分/分段及各任务窗口，不能直接用平均值宣称可行。本例 S 的全部工作均在2之后，因而强化下界为2+3=5。多资源下界取最大，不无依据相加；相互重叠的工作可能同时占多种资源。下界与可行上界在同一冻结合同和目标时才可比较。

## 3. 动态到达、不可移动承诺与合法重规划

在时刻2出现获权新任务 E=(X,1)，release2、hard deadline3，不需 S。A/B 已真实结束，原剩余 D,C 的计划分别 [2,3)、[3,5)。若 C 尚未准入且 D 已合法承诺 [2,3)，新计划 E=[2,3)、D=[2,3)、C=[3,5) 可行，E 与 D 使用不同设备且只有 D 用 S。若现实是 C 已在2开始占 X/S 至4、不可抢占且不可撤销，E 在 [2,3) 无可用 X，本模型无合法安排；不能因另一历史中可行而将已运行 C 移到3。若要求 D deadline3 也保持，则 C 的这一已运行历史本身已违反 D 的可行性，应明确冲突，而不是把它当同时满足所有旧合同的合法输入。可另在不含 D 硬期限的旧合同下比较同样的固定 C 与新 E 不可行；新增期限、资源故障或发现错误不自动授权违背承诺。实际需要抢占/替代设备、调整期限、部分服务时须有新的获权政策及真实效果记录。

重规划时区分已完成、不可移动承诺、允许调整的草案、运行中与未知效果；新计划版本保护实际准入/提交。若在 solver 计算时 X 被第三方占用，候选即使数学最优也不能提交，必须重新核实际资源。一个可行计划的延迟、变更成本、预计完成率与真实执行结果分别记录。不能在输入不完整、结果未获权时标模型不可行或宣称优化达标。

## 4. 多目标、变动成本及局部算法选择

当任务允许延后且计划尚未承诺，若同一可行集合中有多个候选，可以按有权词典序比较：先全部硬约束，再最小完工时刻，再最少变动，最后明确稳定次键；若业务优先服务数量或关键期限，则改变目标顺序且显式表达未服务结果。示例两合法候选 P/Q：完工5/6，改动未承诺任务3/0。若主目标最短完工，则 P 胜；若要求完工≤6且首选最少改动，则 Q 胜。不能自动把二者相加为同一单位。若真实业务已承诺不可改，变动是硬禁止不是惩罚项；允许变动的成本可包含通知、重新验证和资源切换，不能只数节点。多目标无确定权重时保留合法的非支配候选与取舍（P/Q 各有优势），不伪造唯一最优。

问题只有一个独占资源、给定预约，使用 T35-5 区间检查；固定单槽选择用 T40-R3 匹配；只有真实多资源/前置/时间窗才需联合模型。小规模可枚举有限合法模式/时间验证反例；规模变大，按实际图结构、独立分区、约束传播、搜索预算等选择算法。分解的充分条件须涵盖所有共享资源、跨组前置、目标和固定承诺，不能仅因不同项目独立求解；若总目标是最大完工而分区真正独立，各自最小完工的最大值可达全局最小最大完工，但有共享约束或不同目标时此推导不适用。求解超时若有可行解仅报实际解及同模型界；无解未证明则 UNKNOWN。实际执行仍要验证节点前后义务，参 R1。
