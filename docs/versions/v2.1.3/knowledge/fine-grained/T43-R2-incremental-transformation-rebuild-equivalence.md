## 1. 明确要保持的数学关系

固定获权的源状态 S_v（版本 v、完整范围）、转换定义 F_t（版本 t）、合法输出观察 O。派生结果 P_v=F_t(S_v)，实际增量过程 G_t(P_v,Δ,S辅助) 只有在已知前态确实对应 S_v、Δ 完整描述 v→v' 的合法变化、所需辅助状态充分、且满足 G_t(...)=F_t(S_v') 的指定观察合同下才可替代重算。若 F 依赖当前时间/外部查询/随机数等，先把合法观察输入纳入版本与语义；不能从代码表面相同推断确定性。输出可仅保留合同需要的表示，但不得弱化观察精确性。归纳证明：可信初始结果与 F 一致，每次合法变更维持关系，则有限已接受变更序列后仍一致；不证明源传输完整或分布式实现正确。

教学固定同币种/同租户已确认金额，源每行 stableId→(group,amount)，输出每组 (sum,count)。v1: a=(P,100), b=(P,50), c=(Q,80)。P=(150,2), Q=(80,1)。v2 将 b 变为 (Q,70)：先撤销旧贡献 (P,50,1)，再加新 (Q,70,1)，结果 P=(100,1),Q=(150,2)，与按新源 a/b/c 全量分组相同。若只按 b 新值加70，P 仍150且 Q150，重复计旧贡献；若只减/加70−50到 Q，Q=100且P150，同样错误。v3 删除 a：P count0，按合同移除该组（若维度全集仍应显示0，则明确另一种观察）；Q 保持150/2。新/旧身份与版本要有真实来源；缺 before image 时必须可从可信已应用状态取得，不能凭 after 推测。

同一 v2 重放不能重复撤加，按源/代际/变更ID及内容核实际已应用事实。若 v3 先到而 v2 缺失，本例 delta 依赖连续版本；保留缺口并获权补齐，或从有权一致全量 v3 重建。禁止用最新序号标记进度，却漏掉 b 的跨组更新。

## 2. 聚合和连接为什么需要辅助状态

sum/count 的撤销在明确精确数域、实际旧贡献和合法非负计数下可计算；浮点舍入及非结合的算术不能默认逐步结果与全量位级一致，需有权数值合同与稳定计算。均值保存 sum/count，不只保留平均；max/min 在删除极值时需知道次值或重查真实源。H1=[10,7]、H2=[10,3]，均 max=10,count=2，删除同身份值10后分别 max7和3，单独 max/count 不足（T40-R2 的表示碰撞）。distinct 需集合/引用计数等充分信息：两个不同记录均用户 U，删一个后仍有 U；只保留 distinct=1 不能判断另一个是否存在。一个候选为每个值维护 multiplicity，最后一个合法引用消失才去除；实际存储/查询成本与允许近似误差另行决定。

连接增量：在袋语义（重复记录计数）下，设 A'=A+ΔA，B'=B+ΔB，Δ 允许带符号的增删，连接对带符号多重集可双线性扩展。则 A'⋈B'−A⋈B=ΔA⋈B + A⋈ΔB + ΔA⋈ΔB。最后交叉项不可漏。教学同键、无其它过滤：旧 A 有1行、B 有1行，旧连接1；各新增1行（不同身份），新连接4；两项独立旧态贡献各1，少交叉项只能得到3，正确增量3。可改用顺序更新 ΔA⋈B + A'⋈ΔB，效果相同，不能再加交叉项。此为内连接袋语义，不直接推广外连接、去重、LIMIT、排序、非单调过滤或任意 SQL；外连接还需维护是否存在匹配，第一条匹配出现时撤销旧 null 扩展、最后一条移除时补回。真实计划需考虑高扇出与中间状态。

## 3. 版本、发布及恢复边界

小量或允许周期刷新：权威查询直接计算 F，或周期物化结果，以简单机制换可接受滞后。PostgreSQL18 REFRESH MATERIALIZED VIEW 重新取得定义查询结果，非通用增量视图维护接口；CONCURRENTLY 允许并发读，但要求已填充且存在满足条件的全行普通列 UNIQUE 索引，同一物化视图一次只能一项 refresh；WITH NO DATA 后不可扫描且不能和 CONCURRENTLY 同时用。刷新不保证维持定义查询排序，不意味着最新业务数据或外部源统一快照。实际 MAINTAIN 权限也不替代数据披露合同。增量候选须对照其具体源和目标能力，不据名称判定更省。

多文件教学：快照 v7 要求数据分区 A7、B7 及 schema t2；v8 更换为 A8、B8。若逐文件改当前路径，读者可能观察 A8+B7 混代结果，即使两个文件单独有效。候选为不可变对象、完整版本清单、真实原子 current 指针 CAS、读者绑定同一清单；发布前独立核覆盖、摘要及实际源版本，旧版本按合法读租约/保留政策清理。对象写入先成功不代表快照已发布；CAS 丢 ACK 必须核当前/历史提交收据，不能直接发布另一版本或删掉可能可读对象。若存储没有所需原子指针/持久性或生命周期机制，不能承诺该合同，采用受保护权威记录或明确弱化需求。Parquet 布局只定义文件列数据与元数据，不给多对象快照原子性。

增量执行真实提交边界必须将受保护的贡献状态、派生值和已处理变更身份/必要进度一致提交，或用可证明重放/幂等发布替代；源进度先过而目标未保存会丢失，目标先保存而进度未确认须安全重放（T27c-3）。若转换 t2 改为 t3（新分组/修订单位/过滤），旧 P_t2 不能直接加 t3 增量当完整 t3；从有权源重算，或证明状态迁移等价且冻结并衔接变化日志。教学重建读 S_v，期间 v+1/v+2 已提交：先绑定 v 和变更连续前缀，再应用后续记录，当前指针按已获权允许版本 CAS，不让 v 重建覆盖更高已发布版本。切换期间真实读合同与权限仍控制；重放输出不重复触发通知等外部动作。

## 4. 何时增量值得引入（NOT_RUN）

教学规模 N=10000，变更2行；若分组汇总已具充分旧值、各行影响有界，更新受影响组可避免扫描全部。但若一条分类变更影响9999个关联事实，或新规则作用全部源，增量工作可能接近全量甚至额外付状态维护成本。不能用 changedRows 小直接推出计算量小；看实际依赖扇出、跨组变更、读写放大、完整性及恢复预算。对少量周期报表优先简单全量查询；频繁重复大扫描且可证明增量等价与恢复时才引入；复杂非单调操作可选择受影响分区重算，不必全增量。保留获权完整重算/核对路径以识别漂移（若源保留/查询预算不允许，明确可验证边界）。

独立纸面 Oracle：v1→v2→v3 的逐组和全量等价、重复/缺口/跨组修订；max 删除与 distinct 引用反例；连接1→4、交叉项和顺序更新；旧新 schema、混代文件及指针丢回执、重建期间新版本；不以相同总额替代逐键结果。真实 DB/Parquet/CDC/并发/性能均 NOT_RUN，不额外执行产品、LLM 或 Package。
