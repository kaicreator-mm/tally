## C1 · 资源责任的生命周期与所有权转移（K03.F4.2 / K02.F3.1）

在需要真实资源（文件、连接、订阅、锁、临时文件）时，区分尚未取得、已取得并由某方负责、借用、已转移、释放中、已释放或释放结果未知。取得成功后调用者立即登记清理；获取器内部部分成功但未交付时由获取器清理已获得资源，或按明确合同交付部分句柄及责任。借用 Conn/Rows 的 Close/归还按各自合同执行，不等于关闭共享 DB pool。部分取得失败仅释放实际已获得且仍拥有的资源。借用方不得默认关闭共享资源；转移后应移交释放义务。释放依赖顺序来自真实资源关系，不由目录层级推断；逆序退出是嵌套资源的常见方案，并非所有资源的固定全局排序。

检查主失败与清理失败的传播合同：需要保留首次失败与附加失败，或依据具体语言/资源规定允许退出回调改变异常；禁止笼统 catch 后宣称释放成功。重复初始化/退出是否允许取决于具体产品和资源合同，不因通用机制出现 Once 而强制去重。依据 [T05-C09/C10](T05-common-function-abstractions.md)、[T08-C05](T08-platform-functions.md)、[T09-C08](T09-code-abstraction-cases.md) 的不同源机制。

原创反例：先打开文件 A，打开 B 失败；初始化框架仅在全组成功时登记 Exit，A 被泄漏。另一个反例是释放者关闭仍被其他消费者使用的共享连接。对照一个固定资源语言作用域、动态清理栈和共享资源独立 Owner；根据实际获取失败、转移、重复 close、清理错误检查。没有资源时不添加空生命周期框架。

## C2 · 并发协调的安全性、可见性与进展（K03.F3.1 / K03.F3.3 / K10.F3.2）

原子更新只保护所声明的状态/操作范围；其他线程观察到标记不等于此前工作和外部副作用已经完成。锁、CAS、条件等待、消息与单一 Owner 均有不同语义。先明确共享可变数据、合法观察、竞争对象、线性化候选点、需要的可见性、等待/取消和失败后进展；选择最小机制。一个完整的操作往往有多个可见阶段；只在具体合同允许时将其视为单一原子事件。T09-C08 的 Once 原作者给出 CAS-only 反例，T05-C08 的取消信号不等待完成；它们共同说明信号和完成需要不同保证。

原创对照：线程 A 把状态标 RUNNING 后启动实际资源；B 观察 RUNNING 便调用尚未初始化资源。安全性质是未完成不开放消费者，进展性质是在满足条件且任务能够终止时最终开放/拒绝。另一情形取消仅停止排队，不撤销已提交外部操作。检查两并发调用、旧版本写入、取消/完成竞态、锁排序、超时、阻塞工作；不使用 sleep 时长证明线程安全。若无需共享可变状态，优先直接调用/不可变数据或消息所有权转移。

## C3 · 事务、外部副作用与恢复的可观察时间线（K02.F3.1 / K10.F3.1 / K10.F3.2 / K06.F3.2）

将操作拆为有权意图、执行尝试、实际提交/外部效果、可观察结果、记录与接管。提交点取决于资源合同；本地数据库 Tx 不会自动回滚 HTTP 调用、文件系统或第三方消息。T04-C05/C06 的事务与 WAL 文档、T06-C03 的连接绑定、R6 的证据冲突均说明记录与事实不可混用。恢复前确认操作身份、原承诺的范围与可查询真值；不把未知 ACK 当失败。确认已生效则读回并核对，不重复写；确认未生效、无遗留在途操作且仍获权时可开始新 attempt，即使远端没有去重接口。对未知/在途的外部写效果，只有经核实的幂等/条件提交等机制能在原操作身份、目标版本、payload、去重范围与有效期、并发和授权条件下避免重复效果时才可重放；否则先对账、受权人工处置或停止。纯读按其合同另行判断。预算是停止条件，不是安全证明；补偿是新的受权效果，不保证恢复原世界。

故障矩阵（原创教学，未执行）：

| 中断点 | 可知事实与合理下一步 | 禁止推断 |
|---|---|---|
| 有权意图前 | 无已接受操作记录；先确认是否已发出外部请求 | 任意重放一定安全 |
| 请求发送、无结果 | 外部可能未执行/执行中/已提交；查询受权效果 | timeout 等于无效果 |
| 本地提交后、响应前 | 读回相同操作身份与版本 | 客户端未收到就重新写 |
| 恢复接管 | 确认旧执行者是否仍能写，重新取得受权资源 | 进程退出意味着所有远端效果撤销 |
| 补偿中断 | 查询原效果及补偿效果，分别保留不确定性 | 发出补偿就必然恢复 |

若不能核实且后果不可逆，停止受影响动作；独立安全工作仍可继续。纯函数/本地单原子更新不需要分布式恢复协议。

## C4 · 有界工作、背压与终止（K03.F3.3 / K10.F3.3）

预算必须绑定实际资源/工作单位，例如每轮扫描对象数、实际返回项、字节、队列容量、并发连接或计算 token。拒绝、排队、截断、取消与部分成功是不同业务结果；耗尽预算不等于已完成，也不等于不存在目标。T04-C01 的计算调度预算、T04-C03 的搜索许可、T05-C09 的连接池与 T06-C06 的流资源支持不同约束下的设计参考。资源预算不能仅靠计数：某项可能无限等待或产生过多数据，因此同时确定时间/阻塞/单项限制及何时报告真实进展。队列稳定性和吞吐/尾延迟仍按原 K10 容量知识测量，未测不推定改善。

教学对照：一轮处理最多 100 项但第 1 项等待远端无限期，计数有界不代表时间有界；扫描 100 项没有匹配且实际全集更大，不能报告全域没有匹配。可选直接有限列表、带取消的工作清单、持久队列或流式背压。分别检验满队列、下游停滞、取消和资源释放、部分结果与剩余范围；无实际长运行/资源竞争时不预建调度平台。

## D1 · 演进的兼容集合与切换边界（K09.F2.1 / K09.F3.1 / K09.F4.1 / K08.F4.1）

对有权保留的行为分别标出源码/API、数据格式及历史数据、运行中旧消费者、部署/制品、外部效果。迁移策略从真实支持窗口与不可逆风险得出：停止并整体切换、兼容窗口/扩展迁移收缩、替代后逐步退役。没有要求兼容的旧合同不强制保留；已支持消费者未切换时不能仅因旧代码碍眼就删除。持久迁移记录与实际 schema/数据一致性、真实应用可运行性须分别核对；T08-C07 的 fake 分支是实际记录不必对应执行的例子。旧记录不证明新产物已经加载。

教学对照：本地临时工具完全重写且无旧数据，直接替换通常更简单；滚动升级多人服务需保留新旧读写交集；不可逆数据转换必须有真实映射、恢复方案、读回及失败边界。检查旧客户端连接新服务、旧数据载入新程序、混合版本写入、失败接管和回滚可恢复性。仅在原要求明确且证据足以覆盖时关闭兼容义务。

## D2 · 变化影响集合与工程投资阈值（K09.F5.2 / K11.F1.2 / K11.F4.1）

比较两个抽象候选先固定必须保留的合同、真实变化场景与必要职责集合；再估计导航、修改、接口迁移、测试、资源和长期维护。必要变化涉及多个 Owner 不一定坏，偶然跨 Owner 泄漏才需解释。没有真实后续变化，不宣称实际维护收益。保留成本证据类别：已观察事实、工程估计、未知和有权质量下限；不汇总成无依据通用分数。原 K09 的陌生维护者/真实变化方法保留，但当前知识整理不启动新 Agent 实验。

定性阈值：若方案 A 的初始改造成本高于 B，而 A 预期仅在若干真实后续变更中节省重复工作，则只有在合法风险/质量约束同时满足且合理情景下累计节省能覆盖初始、验证和迁移成本时才值得优先。缺次数/成本事实时以区间或条件表达；若任何合理情景都不会改变选择，停止继续研究。不可逆或严重正确性问题先满足质量下限，不用经济优势抵消。例：一处稳定转换可保留 inline；多个消费者已反复修同一不变量则考虑提取最小 helper；如果分离会破坏旧公共行为，先限定迁移合同。以真实变更、旧/新 Oracle、读者定位和返工为反证，未运行不报告百分比。
