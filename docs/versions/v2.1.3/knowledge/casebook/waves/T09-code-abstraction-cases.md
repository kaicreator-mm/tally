# T09 · 细粒度代码抽象与正反例

[#567](https://github.com/kaicreator-mm/tally/issues/567)。10 个新案例、10 个新来源文件（Go 与 CPython 两个既有项目），覆盖函数、泛型、算法、对象、动态多态、数据结构、接口/适配器、状态机、组合/继承、错误及机制/策略分离。实际源码观察与原创正反例区分；所有新检查 NOT_RUN。不是实现任务，不照抄源码，不将标准库特定合同变成通用 Rule。以 [T01](T01-theory-ab.md) 的语义替换、边界及表示/别名条件为前置。

## T09-C01 · 函数抽象：分离查找机制与选择谓词

**分类：** 函数/泛型 / L5。**知识：** K03.F2.1 K03.F1.1。**来源：** T09-S01。

- **实际观察：** IndexFunc 遍历 slice，首次谓词为 true 即返回索引，否则 -1；Contains 由 Index 结果转换为 bool。
- **抽象合同与变化轴（分析）：** 复用的是遍历与停止合同，谓词描述实际选择条件。若调用者还需全部结果、错误传播或遍历副作用，不能用首次匹配接口偷换合同。
- **采用/不采用条件：** 一处简单比较可直接循环；多处同合同的首匹配用 helper；真实变化只有元素类型/谓词时用泛型/参数，勿引入对象工厂。
- **原创正反例与验证意图：** 正例：两种无副作用的筛选条件共用首匹配；反例：把需要扫描全部权限规则的裁定改成首匹配。检查空集合、首/末匹配、谓词调用次数；NOT_RUN。

## T09-C02 · 泛型原地变换：保留别名与内存语义

**分类：** 泛型/数据结构 / L5。**知识：** K03.F4.2 K03.F2.1 K03.F1.2。**来源：** T09-S01。

- **实际观察：** DeleteFunc 先找首个删除元素，再将保留元素向前移，clear 尾部并返回缩短 slice。
- **抽象合同与变化轴（分析）：** 泛型可共享元素操作，不隐藏 backing storage 变更；返回新 slice header 不等于获得独立副本。清零尾部有资源/引用语义。
- **采用/不采用条件：** 原地压缩适合明确可变输入且允许别名看到变化；不可变数据合同应分配独立输出，局部一次变换无需泛型公开 API。
- **原创正反例与验证意图：** 正例：临时 buffer 内删除无用项；反例：给需要独立快照的调用者原地删除共享列表。验证保序、全部/无删除、尾部引用、别名；NOT_RUN。

## T09-C03 · 算法与策略：排序接口的语义前提

**分类：** 接口/算法 / L5。**知识：** K03.F1.1 K03.F2.1 K03.F5.1。**来源：** T09-S02。

- **实际观察：** sort.Interface 要求 Len/Less/Swap；Less 的排序关系需满足传递性等条件；注释明确 Sort 不保证稳定，Stable 保持相等元素原相对次序。
- **抽象合同与变化轴（分析）：** 算法负责排列，调用者提供有效比较与交换语义；同签名的 comparator 未必满足排序合同。稳定性是可观察性质，不是内部优化选择。
- **采用/不采用条件：** 固定内置类型直接标准排序；确有多个比较策略用参数/接口；稳定要求必须显式确定，不统一成一个含糊 sort。
- **原创正反例与验证意图：** 正例：按有序数值字段排列；反例：不传递的循环比较或相等项必须保序却使用不稳定排序。检查重复键、NaN/缺失政策、传递性、原顺序；NOT_RUN。

## T09-C04 · 对象与职责：游标状态与位置无关读取

**分类：** 对象/状态 / L5。**知识：** K03.F2.1 K02.F3.1 K03.F4.2。**来源：** T09-S03。

- **实际观察：** strings.Reader 持有 string、读取索引及 prevRune；Read 改变游标，ReadAt 注释禁止改变状态且检查负偏移；零值等价空字符串读取器。
- **抽象合同与变化轴（分析）：** 把共享的字节访问与独占游标状态分开；对象拥有真正持久于调用间的状态。随机访问接口不应修改顺序游标。
- **采用/不采用条件：** 单次切片/索引可用普通函数；需要连续读取才有 reader 对象；无游标状态的读取不必强行构造 stateful 对象。
- **原创正反例与验证意图：** 正例：连续读取器保有当前位置；反例：并发 ReadAt 隐式改变 Read 的位置。检验 EOF、负 offset、交错 Read/ReadAt、零值；NOT_RUN。

## T09-C05 · 动态分派：类型扩展与真实变化轴

**分类：** 多态/策略 / L5。**知识：** K02.F2.3 K03.F2.1 K09.F3.1。**来源：** T09-S04。

- **实际观察：** singledispatch 文档定义按第一参数类型选择注册实现，原函数为默认；实现持有 registry 和 dispatch cache，注释说明延迟导入的启动取舍。
- **抽象合同与变化轴（分析）：** 变化轴是真实类型分派；注册、默认及缓存属于分派机制。不能将业务状态、授权动作或协议版本未经确认压缩成类型分派。
- **采用/不采用条件：** 固定两种局部类型可直接分支；独立作者可添加实现时考虑注册机制；仅类型参数统一且无行为差异时使用泛型而非动态分派。
- **原创正反例与验证意图：** 正例：真实多种文档表示有独立格式化；反例：为同类型不同退款政策按类型选择。检查未知类型、默认、扩展注册与缓存失效；实际失效路径未审查，NOT_RUN。

## T09-C06 · 数据结构：堆不变量与操作选择

**分类：** 数据结构/算法 / L5。**知识：** K03.F1.1 K03.F1.2 K03.F2.1。**来源：** T09-S05。

- **实际观察：** heapq Python 源 heappush append 后 sift；heappop 删除最小值并恢复堆；heapreplace 注释说明返回项可大于新 item，与单纯 push/pop 组合的适用取舍。
- **抽象合同与变化轴（分析）：** 维护优先队列不变量而非全列表排序；相同元素比较与业务公平/时限政策分离。
- **采用/不采用条件：** 小集合且查询偶发可扫描；频繁取最小用 heap；需任意按 ID 删除/更新时额外索引或不同结构。固定大小 top-k 要按真实比较条件选操作。
- **原创正反例与验证意图：** 正例：持续到期任务取最早项；反例：将 heap 内部数组当完整排序结果、把 heapreplace 当任意 top-k 合同。检查空、重复、替换顺序、并列策略；NOT_RUN。

## T09-C07 · 窄接口与适配器：函数无需额外服务类

**分类：** 接口/组合 / L5。**知识：** K02.F2.2 K03.F2.1 K03.F5.1。**来源：** T09-S06。

- **实际观察：** HTTP Handler 仅声明 ServeHTTP；HandlerFunc 把符合签名的普通函数适配为 Handler，调用直接转发；ResponseWriter 不得在 ServeHTTP 返回后使用。
- **抽象合同与变化轴（分析）：** 共同调用合同不要求每个消费者都创建状态类或继承基类；适配器只处理形式差异，保留请求/响应及资源使用期限。
- **采用/不采用条件：** 单一函数直接调用；真实框架消费者要求接口时用小 adapter；只有实际状态或多个协同方法才建对象。
- **原创正反例与验证意图：** 正例：无状态端点用函数适配；反例：包装后延迟异步写已结束的响应，或为每个函数引入 service factory。检查错误、短路和资源期限；NOT_RUN。

## T09-C08 · 状态机：开始执行不等于完成屏障

**分类：** 状态机/并发 / L5。**知识：** K03.F3.1 K03.F3.3 K10.F3.2。**来源：** T09-S07。

- **实际观察：** sync.Once 文档要求正常返回时首次函数已完成；注释明确仅用 CAS 标记会使其他并发调用过早返回；慢路径使用锁并在函数返回后设置 done。panic 后视为已返回，未来不重试。
- **抽象合同与变化轴（分析）：** 区分未开始、执行中、结束；抽象需定义等待/可见性和失败政策。Once 的完成屏障不是业务成功，也不是可重试初始化器。
- **采用/不采用条件：** 单线程一次调用可直接执行；并发一次性动作且符合 panic/重入合同用 Once；需失败重试/释放/重启用显式状态机。
- **原创正反例与验证意图：** 正例：初始化不可变查找表；反例：网络连接失败后必须允许重新激活却用 Once 永久阻止。检验并发、panic、重入（源明确死锁）；不泛化为所有 Package 强制去重，NOT_RUN。

## T09-C09 · 组合与继承：读取视图和写入责任不对称

**分类：** 组合/继承/数据视图 / L5。**知识：** K02.F3.1 K03.F2.1 K03.F4.2。**来源：** T09-S08。

- **实际观察：** ChainMap 继承 MutableMapping 接口实现，并组合多映射；查找按顺序找第一个 key，文档明确写/更新/删除只作用第一层。
- **抽象合同与变化轴（分析）：** 复用公共映射合同的同时暴露具体写入政策；读取范围不等于写权限。共享视图与 flatten/copy 有不同实时性和状态所有权。
- **采用/不采用条件：** 固定配置可合并成不可变快照；需动态覆盖和父级读取时采用分层视图；禁止因继承 mapping 就假设删除可修改任意下层。
- **原创正反例与验证意图：** 正例：局部作用域覆盖父作用域；反例：删除本层不存在的 key 时未经授权删除全局配置。检查遮蔽、下层变更、删除/更新及别名；NOT_RUN。

## T09-C10 · 部分成功与组合错误：不伪造原子性

**分类：** 错误/组合/副作用 / L5。**知识：** K03.F5.1 K03.F4.2 K02.F2.2。**来源：** T09-S09、T09-S10。

- **实际观察：** hex.Decode 文档允许非法输入返回已解码字节数及错误，循环逐字节写入；io.MultiWriter 逐个 Writer 写入，错误或短写立即返回，构造时可扁平化嵌套 MultiWriter。
- **抽象合同与变化轴（分析）：** 输出 buffer、多个 sink 的可见副作用及失败原因必须保留真实合同；组合共用迭代机制，但不自动获得事务原子性。
- **采用/不采用条件：** 纯小数据若要求全有或全无可先验证/暂存再发布；明确允许部分结果时返回进度与错误；多 sink 独立投递需要单独重试/状态。
- **原创正反例与验证意图：** 正例：调用者明确消费合法前缀；反例：第二 sink 失败就断言第一 sink 未写入，或通用 catch 丢弃进度。检查非法末尾、第二 writer 失败/短写、重复尝试；NOT_RUN。
