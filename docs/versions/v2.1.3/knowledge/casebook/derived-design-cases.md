# 原创工程设计与反例案例 · 第一期

所有 DE 案例均为 SYNTHETIC_DERIVED / DESIGN_REFERENCE / NOT_RUN，由本库根据公开项目机制及既有 Kxx 原理生成。不是相应项目的真实代码/架构，不包含隐藏实验题或已执行测试，不作为项目必用模板。每个案例提供情境、参考设计、坏抽象、改变结论的条件与可执行验证意图；用于 Agent 迁移专业判断，而非照抄实现。

## DE-001 · 文件下载器：多协议与断点续传

**分类：** 下载管理/CLI/桌面 · L2–L5。**参考案例：** AB-008/009/010（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K02.F2.2。**关系：** 条件启发；不同协议续传能力。验证意图另见正文，NOT_RUN。

- **需求与事实：** 单任务支持 HTTP 与 SFTP；用户希望暂停、续传、校验完整性。远端可能变化，部分协议不支持范围续传。
- **参考设计及职责：** DownloadJob 保存目标身份、已验证分片和临时输出；协议适配器仅实现真实能力；调度/限速共享，校验与提交归文件任务。简单单协议无恢复需求时可直接流式下载。
- **错误抽象/反例：** 把所有协议强制实现 resume(offset)，将远端变更后的旧分片直接拼接；同名文件不等于同一版本。
- **适用条件与反转：** 两个协议都支持且语义相同的范围读取才共享；不支持则从头下载或拒绝；取消保留/清除临时文件由产品合同决定。
- **验证意图（NOT_RUN）：** 远端版本变化、部分块损坏、断网重启、取消、目标已存在；验证最终长度/摘要，错误后无误晋升完成。

## DE-002 · 跨存储备份：共同接口与能力差异

**分类：** 备份/同步/存储 · L2–L5。**参考案例：** AB-001/009（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K02.F2.2。**关系：** 条件启发；存储能力差异。验证意图另见正文，NOT_RUN。

- **需求与事实：** 本地目录与对象存储需要备份；源数据可能并发变化，目标仅部分支持原子重命名。
- **参考设计及职责：** Snapshot/Manifest 负责版本与成员；历史版本保留不证明并发源的同一时点一致性，后者依赖实际快照/冻结/验证合同，Store 负责明确能力，Transfer 负责数据移动，Publish 负责可见版本。对单机备份可采用已有文件系统快照或成熟工具。
- **错误抽象/反例：** 统一 FileSystem 接口假设所有后端支持目录事务、原子 rename 或 POSIX 权限；上传失败即删除远端对象。ACK 未知先读回同一操作/对象身份；确认未生效、无遗留在途且仍获权才新尝试；未知写效果须证实去重或条件提交合同，否则对账或停止；预算不是安全证明。
- **适用条件与反转：** 能力有共同合同则共享，否则分策略并保留 UNKNOWN；恢复目标不要求历史则减少快照复杂度。
- **验证意图（NOT_RUN）：** 上传中断、对象写成但 ACK 丢失、源变更、旧快照恢复；验证可读回内容及 manifest 完整，不只传输成功数。

## DE-003 · 批量导入：同步与可恢复任务

**分类：** 企业管理/数据处理 · L2–L4。**参考案例：** AR-009/012 AB-005/014（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K03.F4.1。**关系：** 条件启发；批量事务范围。验证意图另见正文，NOT_RUN。

- **需求与事实：** 导入 100 万条数据，需要进度与重启恢复；有重复提交和局部失败；用户尚未授权全批次原子性。
- **参考设计及职责：** 解析/规范化纯机制、业务校验、分批写入、持久任务进度分开；每批身份与已提交数据绑定；错误记录保留来源行。小数据直接事务导入。
- **错误抽象/反例：** 一个 import() 同时读取 UI 文件、验证、写库、更新进度和发布成功；仅内存进度或每行启动一个分布式任务。
- **适用条件与反转：** 数据量、恢复、全批原子性、拒绝/部分成功由用户确定；若必须全批原子，不以分批提交偷换合同。
- **验证意图（NOT_RUN）：** 同一批次重投、进程在提交后进度前中断、非法行、取消；核对已提交行与进度，不从最后 ACK 推断全部成功。

## DE-004 · 订单与退货：共享计算而非共同业务状态

**分类：** ERP/电商 · L3–L5。**参考案例：** AB-011/014（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K01.F3.3。**关系：** 条件启发；订单和退货不变量。验证意图另见正文，NOT_RUN。

- **需求与事实：** 销售订单和退货单都有商品、数量、税额、库存变化，但授权、时点、财务方向与合法数量不同。
- **参考设计及职责：** 可共享带精确舍入合同的纯金额计算、标识验证或单位换算；订单与退货保留各自状态机、权限、库存/会计操作。
- **错误抽象/反例：** 通用 DocumentService(mode) 用 flag 正负数量共用状态与写权限；允许已完成订单按退货路径直接重写历史。
- **适用条件与反转：** 若某计算在两个领域确有同输入域/单位/舍入，适合纯 helper；各政策独立变化时不要共享业务对象。
- **验证意图（NOT_RUN）：** 半分舍入、重复退货、超过已交付量、不同角色、库存/会计失败；测试两个业务旧合同分别成立。

## DE-005 · 权限：动作与资源上下文

**分类：** SaaS/后台管理 · L2–L5。**参考案例：** AR-005/008 AB-003（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K02.F4.3。**关系：** 条件启发；主体资源授权威胁。验证意图另见正文，NOT_RUN。

- **需求与事实：** 多租户后台，用户可编辑自己租户订单，审计角色只读；后台任务也可访问数据。
- **参考设计及职责：** 身份认证、资源归属、授权政策、执行点分开；每个敏感入口从受信上下文确认实际资源，复用共同判定机制。
- **错误抽象/反例：** 只用角色字符串或 UI 按钮隐藏代替执行端授权；把认证成功当所有动作获权；共享缓存跨租户。
- **适用条件与反转：** 简单单用户离线程序不需通用 RBAC/ABAC 引擎；多主体复杂规则时比较角色、属性和直接能力授权。
- **验证意图（NOT_RUN）：** 跨租户 ID、过期授权、角色变更、后台任务、批量接口；未授权不得产生写副作用。

## DE-006 · 配置：首次启动、验证、应用与回滚

**分类：** 桌面/服务器/CLI · L2–L5。**参考案例：** AR-008 AB-007/016（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K08.F4.3 K10.F5.1。**关系：** 条件启发；首次启动允许设置且未授权业务禁止；CLI/headless 配置形态另按合同。验证意图另见正文，NOT_RUN。

- **需求与事实：** 交互式软件可以先启动再由用户设置连接；后台服务的合法启动条件可能不同；运行中配置变更可能失败。
- **参考设计及职责：** 默认可启动外壳、配置存储、校验与应用、资源切换独立；未配置时阻止受保护操作。将静态启动依赖和可变配置区分。
- **错误抽象/反例：** 单一全局 config object 被任意模块写；保存配置即宣称连接成功；应用失败后用新值覆盖旧可用状态。
- **适用条件与反转：** 只读常量可简单模块导出；真正热更新需要明确资源所有者与切换语义，不强制所有服务用 UI。
- **验证意图（NOT_RUN）：** 首次空配置、无效凭证、连接失败、应用一半、重启、并发修改；验证实际生效版本及合法回退。

## DE-007 · 本地搜索：索引与结果合同

**分类：** 搜索/知识检索 · L2–L5。**参考案例：** AR-001/002 AB-015（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K02.F2.2。**关系：** 条件启发；结果范围合同。验证意图另见正文，NOT_RUN。

- **需求与事实：** 搜索文档内容、文件名及元数据；支持增量索引、取消和限制返回，数据在扫描期间可能变化。
- **参考设计及职责：** SourceReader、索引/查询、结果排序和范围/版本收据分开；只在确有负载时新增索引。查询截断不是没有命中。
- **错误抽象/反例：** 统一 find() 返回数组却隐藏扫描预算/部分结果；以旧索引上的无命中断言当前文件不存在。
- **适用条件与反转：** 小集合直接扫描；全文查询与语义搜索目标不同，向量不是所有搜索任务的必需依赖。
- **验证意图（NOT_RUN）：** 新增/删除文档、索引中断、扫描限额、排序并列、旧版本结果；报告完整性和范围。

## DE-008 · 消息通知与审计：用途不同

**分类：** 企业系统/日志/通知 · L3–L5。**参考案例：** AB-006/012（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K03.F5.2。**关系：** 条件启发；日志与审计用途分离。验证意图另见正文，NOT_RUN。

- **需求与事实：** 订单状态需向用户发送消息并形成审计记录；渠道可能失败，审计要求不可随通知重试丢失。
- **参考设计及职责：** 领域事件表达已发生事实；审计归有权记录，通知有独立投递策略；共享格式化/序列化而非交付政策。
- **错误抽象/反例：** 把审计、调试日志、短信、邮件都包装成 fire-and-forget event，失败统一忽略。
- **适用条件与反转：** 若只用于本地诊断可普通 logger；持久审计有独立授权及保留要求才引入可靠存储。
- **验证意图（NOT_RUN）：** 渠道不可达、重复通知、审计写入失败、敏感数据；证明业务状态、审计和发送结果各自可追溯。

## DE-009 · 插件：可扩展性不等于任意动态执行

**分类：** IDE/工具平台/CMS · L2–L5。**参考案例：** AR-005/011 AB-012/016（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K02.F2.3。**关系：** 条件启发；稳定扩展点。验证意图另见正文，NOT_RUN。

- **需求与事实：** 第三方提供文件格式解析，部分插件只需纯计算，另一些需系统资源；需支持不同版本。
- **参考设计及职责：** 最小公开输入/输出合同与声明能力，明确加载/停止和资源 Owner；对高风险/异构运行时可用独立进程；进程不是安全沙箱保证，另须实际 OS 权限、IPC 授权、资源限制和可信边界。固定内部组件先静态组合。
- **错误抽象/反例：** 为两种固定解析器先建全局发现、动态注册与依赖注入平台；允许插件继承宿主全部权限。
- **适用条件与反转：** 真实外部作者、版本独立发布、动态替换、隔离需求决定是否扩大扩展点；否则直接函数或窄接口足够。
- **验证意图（NOT_RUN）：** 版本不兼容、插件异常、资源释放、未声明能力、重入；不能仅验证加载成功。

## DE-010 · 设备控制：期望状态与反馈

**分类：** IoT/机器人/控制应用 · L2–L4。**参考案例：** AR-003 AB-013（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K03.F3.1。**关系：** 条件启发；期望与实际反馈状态。验证意图另见正文，NOT_RUN。

- **需求与事实：** 多设备期望状态由 UI 设置，网络断开或设备重启；传感器反馈可能迟到，外部物理状态不能从发送成功推断。
- **参考设计及职责：** 目标设定、命令执行、实际反馈、状态协调与安全保护分开；版本/时间/设备身份明确，硬件保护不依赖上层重试。
- **错误抽象/反例：** 发送命令立即标已完成；旧反馈覆盖当前目标；通用无限重试忽略实际设备安全边界。
- **适用条件与反转：** 无反馈能力时保留 UNKNOWN，不能宣称闭环；实时/安全关键控制须按实际专业规范单独设计。
- **验证意图（NOT_RUN）：** 旧反馈、设备失联、断电重启、重复命令；验证观察状态，不涉及具体危险物理操作。

## DE-011 · 交互式应用与 CLI 共享核心

**分类：** 桌面/CLI/服务 · L1–L5。**参考案例：** AR-006/008 AB-008（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K02.F2.1。**关系：** 条件启发；交互入口与核心职责。验证意图另见正文，NOT_RUN。

- **需求与事实：** 同一文件转换能力有 CLI 和 GUI，GUI 需要取消与进度，CLI 需要明确退出码；第三种服务入口尚未授权。
- **参考设计及职责：** 领域核心保持纯转换与资源协议，GUI/CLI adapter 翻译输入、进度、取消和错误表现；只共享真实合同。项目多子模块可用单 monorepo，但不把代码库结构等同进程架构。
- **错误抽象/反例：** 为所有入口强制共享 UI 状态或统一 success 字符串，CLI 不能可靠退出；为未来服务建立多余网络层。
- **适用条件与反转：** 真实多入口共享领域语义时适用；若 GUI 与 CLI 输入政策不同，分别验证适配。
- **验证意图（NOT_RUN）：** 相同文件结果一致、取消清理、非法参数与退出码、GUI 错误显示；证明真实消费者调用核心。

## DE-012 · 重构重复代码：选择正确粒度

**分类：** 跨领域代码维护 · L5（演进教学，非真实历史）。**参考案例：** AB-011/014 与 R6 evidence-boundary-case（见 [架构](architecture-cases.md)、[抽象](abstraction-cases.md)、[R6](../evidence-boundary-case-r6.md)）。**知识：** K09.F2.1。**关系：** 条件启发；原行为反例。验证意图另见正文，NOT_RUN。

- **需求与事实：** 两个函数均解析输入文本：一个必须保留前导空格，另一方必须去空格；两者使用相同数字校验且有独立消费者。
- **参考设计及职责：** 先比较合同；只共享已证实相同的数字校验纯函数，分别保留文本策略。若未来策略共同变化且合同重新授权，再评估模块或接口。
- **错误抽象/反例：** 为去重统一 normalize()，让两方都 trim；测试只覆盖无空格输入。另一个错误是给两段局部代码建立抽象工厂。
- **适用条件与反转：** 共同不变量、变更频率、消费者稳定性与实际成本决定提取范围；没有真实重复维护问题时保留内联。
- **验证意图（NOT_RUN）：** 前导空格、空串、数字边界、两消费者旧行为；新增第三种策略仅在真实任务授权后观察修改成本。
