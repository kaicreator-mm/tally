## 3. 提炼可独立于 SDK 的知识（补充候选，仍归原 Kxx）

以下是从精确案例与既有学科内容推得的通用候选机制，非新增外部已合格 Source Claim、强制 Rule 或针对特定 API 的修复说明。

### A. 共享机制不等于共享政策 — K02.F2.1/F2.2/F3.1 → K03.F2.1/F5.1

- 原理：不同领域对象可复用一个输入/输出与不变量完全一致的纯机制，同时保留不同权威集合、决策政策、错误与状态语义。
- 适用条件：确认共享机制本身不依赖调用者业务状态、权限/提交点、资源所有权及互不相容的合同；未来共同变化只限同一机制。
- 反例：内容比较一致不意味着集合完整性一致；统一裁定时删除某一方需要的权威集合，即使 helper 局部完全正确也会导致业务误判。
- 判断方法：分别比较机制级与业务级前置、结果、不变量、错误、资源与变化轴；先考虑保留已存在的共享机制，不自动增加更大的类/框架。使用替换同 ID 内容和保留差异两类反例。知识来源 [K02 DP](../../v2.1.2/software-engineering-knowledge/K02/advanced-engineering-abstraction-boundaries-and-variation-r19.md)、[K03 DP](../../v2.1.2/software-engineering-knowledge/K03/advanced-abstraction-level-selection-and-semantic-reuse-r19.md)。

### B. 权威事实集合和请求视图必须分开 — K01.F2.2/F3.3/F5.1、K02.F3.1、K05.F1.2

- 原理：单条记录具备资格，不代表请求中可见的集合完整。普通请求是一个视图，不能代替权威全集。对材料性事实的省略、替换和过滤不应消除已确认的冲突/失败。
- 适用：存在外部权威事实或完整义务集合、部分记录可由调用方选择，且遗漏会改变结论。纯本地算法的输入本身就是全部授权数据时不需要新确认服务。
- 可检验性质：固定权威事实、对象、版本和范围，改变普通视图的遗漏/替换；材料冲突不能因此变成支持；独立不相关候选仍可成立。证据不足要区分未知与已证明否定。若权威集合本身未确认完整，保留 UNKNOWN，不伪造全集。
- P1-01 对应实际反例。原始概念仍归各 Kxx，不另建通用“证据引擎”。

### C. 局部冲突先于跨范围聚合 — K05.F1.1/F1.2/F2.2/F5.3、K06.F1.2/F2.2

- 原理：汇总之前先确定可比较的主体、版本、执行身份、目标/环境、覆盖域及事实类型。矛盾发生在某个具体判断单元，不能仅以全局“发现失败优先”或“发现冲突优先”替代局部资格判断。
- 适用：多条执行证据、局部覆盖、重复/并发或相互矛盾报告。区分同次执行的执行/未执行冲突与独立执行的真实不同结果；不同条件下的不同结果未必矛盾。
- 决策：先判定每个单元的资格和未决冲突；排除受矛盾阻断的证据，保留其他适用范围独立反例；再汇总 PASS/FAIL/UNKNOWN/未执行/过期，保留原因。反例：同次同范围 FAIL+NOT_RUN 不能直接 FAIL；其他独立范围确有合格 FAIL 也不应被无关冲突抹去。后者是后续适用验证建议，不能冒称此次已重放。
- P1-02 说明状态集合与优先级本身不足以保证正确性，还须明确判断粒度。与 [K05 Oracle 校准](../../v2.1.2/software-engineering-knowledge/K05/advanced-quality-reviewer-calibration-r18.md) 衔接。

### D. 知识/合同身份与成本证据不能用字符串或数值代理 — K01.F4.2/F5.3、K08.F1.1/F3.3、K09.F3.1/F5.2、K11.F1.2/F2.2/F4.1

- 版本：源代码 SHA、合同 revision、制品、执行环境是不同身份。精确源码相同也不表示 Oracle 合同仍有效。只有已确认旧版本/不适用时标过期；未知来源或版本关系仍 UNKNOWN。保持原记录，不能按版本字符串字典顺序猜测历史。
- 取舍：多候选可行只证明存在选择，不证明已经比较真实成本。需说明具体变化场景、修改的职责集合、调用跳转/依赖、保留合同的验证成本、迁移与可逆性。无法量化时如实记录定性证据或 UNKNOWN；不要创建普遍评分或根据文件数、支持数宣布最优。真实后续变更和有效 Oracle 才能观察维护收益（K09 DP）。
- P2-01/P2-02 分别提示身份/分类与比较证据缺口。
