## 1. 同一任务随阶段改变选择：抽象与维护

公开任务 W36-A（非真实授权）：既有应用有两个读取入口 ReportPreview 与 FinalReport，已确认同一 K01 Owner、同一整数单位及确定性的列计算。Preview 接受缺少可选备注并显示空值；Final 必须拒绝缺少必填签署字段，生成制品需另有发布许可。初始仅两个同模块调用者，不存在独立插件/发布需求。以下是教学指定事实，不替代真实项目的源码/合同。纯 computeColumns 对已验证输入具有相同前后置、值域/错误、无副作用和共同变化；其它完整行为不同。若事实没有实际确认，保持候选待证。

| 当前阶段及获得的事实 | 实际选择的 pilot key（引用其源范围） | 结论、排除和下游输入 |
|---|---|---|
| L1 仅知道两个入口都生成报表，尚未确定签署要求/是否有写效果 | P36-POLICY，必要时由原 K01/T24a 定向查有权合同 | ASK 两个入口合法输入、错误、权限/效果及版本；不因同名 report 设计统一 save。若用户已明确仅预览可查，可先研究其局部合同 |
| L2 收到上述明确区别及共同纯计算事实 | DP-K02-R19-01、P36-POLICY | 拒绝把两种完整行为变为一个有统一权限/错误的命令；同一模块各入口保持独立，纯机制可共享；单库本地路径无跨系统需求，排除 P36-EFFECT/OFFSET |
| L3 实际候选：inline 两份计算 vs 私有 computeColumns vs 公共 Strategy | DP-K03-R19-01，承接 L2 的 Owner/真实差异 | 纯计算已同义、真实两个维护位置时私有 helper 为可行建议；无真实替换/外部消费者，不建议公开 Strategy。若仅一个维护位置或共享语义未证，保留 inline/NEEDS_EVIDENCE；不声称唯一最优 |
| 实施 | DP-K03-R19-01 所选范围与当前合法源码/工具链 | 仅交付有权代码变化，保留两个入口的校验/授权和原错误；须实际测试才有执行事实，本例未写代码 |
| QA/Review | K05.ORACLE，实际独立合同和观察（不是 Builder 的选择收据作为 Oracle） | Preview 无备注仍可预览；Final 缺签署字段拒绝且无发布；同合法输入计算一致；无发布许可不得交付。有效签署及许可的 Final 正例应成功。NOT_RUN；不知道真实合同/执行则 UNKNOWN/NOT_RUN |
| 维护 | P36-MAINT、DP-K03-R19-01；新增仅 Final 的签署要求 | 合法政策变更只影响 Final 资格/交付，不改变 Preview 及纯计算；新字段若改变共同计算，重新核共享合同。旧源码缺陷不是合法基线；真实变更与回归成本仍未知 |

具体纸面区分：输入两行金额 120、80，共同计算合计200；Preview 缺备注合法，Final 缺签署非法。不允许将 Final 的错误变成返回200并发布，也不允许共享规则使 Preview 必须有签署。候选仅共享纯函数时仍可输出200，调用者的合法动作不同。若后续 Owner 变为两套独立计费政策，且数值舍入/变化轴未证同义，则重新比较私有 helper；只共同整数加法不证明完整计费机制可共享。现有九维及 K02/K03 DP 保持原义，不创造一个新的共同“报表 Rule”。

## 2. 第二个任务：恢复合同改变知识组合

W36-B 公开教学：小型单租户工具导入有界本地数据，同 DB 的全批原子更新，不支持跨重启恢复，也没有外部效果。已确认当前输入域、合法权威与事务。只需查 P36-POLICY、原 [T35-1 G1](../fine-grained/T35-1-general-function-knowledge-composition.md) 与 [T27b-1](../fine-grained/T27b-1-relational-data-and-transactions.md) 的适用范围（不因 pilot 没有直接 DB 基础记录认为缺失）；短本地路径不选 P36-RANGE、OFFSET 或 Kafka，不强制持久下载任务。

合法变更 B'：来源变为 HTTP，用户要求中断后续传、跨重启、整批不可见直到发布。实际服务器身份和表示验证器尚未知，不能直接承诺续传。L1 选 P36-POLICY 与 P36-RANGE 查是否存在固定源验证合同；L2 选 P36-STAGING/P36-COMMIT 研究权威可见性；L3 只有在确认实际 HTTP/表示条件后选 P36-RANGE 和 P36-DURABILITY，另核真实 parser/DB/平台。假定测试输入源 bytes "abcdefghij"，可信块清单已确认前4字节 "abcd"、总10字节、强 ETag "s1"，合法 identity coding；请求 bytes=4-9。实际返回200且 ETag "s2"：旧块不能拼接，固定旧源合同下停止/待授权。若收到合法匹配206、bytes4-9/10、完整性和实际持久化通过，才可确认剩余6字节。没有可信源身份时保留旧片段未决，不虚构可安全重用。

QA 独立核前后字节/真实持久状态、已验证 checkpoint 和当前 DB pointer、旧 Worker 及源变化负例；若未运行则 NOT_RUN。维护新增 parser version 时不复用原 checkpoint。若之后有真实外部索引 consumer 需求，才重新查 P36-EFFECT，确认选用 Kafka4.1/Java4.1.2 后才查 P36-OFFSET；若仍同 DB 直接读取变更记录，则不需要 broker。知识选择由实际目标和变化触发，不由关系闭包。

## 3. 第三个任务：权限与外部效果不可混成同一种失败

W36-C 公开教学：某导出 Job 在授权 epoch12 下生成不可公开制品，合法快照包含两个已批准对象。当前收到 epoch13 撤权事件且有权证据确认不能继续交付旧制品；同时一个独立邮件通知发送的远端 ACK 丢失，邮件 Provider 当前是否支持稳定意图去重尚未知。选择 P36-POLICY、P36-EXPORT/P36-CACHE 处理当前披露，选择 P36-EFFECT 处理通知未知；不能因通知 UNKNOWN 而重新发一封或授权导出，也不能因导出 SUCCESS 推断通知送达。披露门保护真实授权顺序；已合法准入的字节不可远程追回。查真实 Provider 合同与收据后再判断重试，未得证据不调用外部效果。K05.ORACLE 区分三类实际事实：制品已完成、合法交付、邮件真实效果。若只改变 UI 请求顺序而未改变权限，旧响应也不能覆盖新 view，但不能声称权限已撤销。若 Provider 版本/权威读回明确同一意图已成功，输出限定 confirmed，不继续一律 UNKNOWN。

## 4. 对上述公开推演的可区分变形

| 变形 | 预期选择变化及可反驳结果（纸面，非运行） |
|---|---|
| A 删除决定性签署/写权限合同，保留相同函数体 | 不能确认完整语义可合并；P36-POLICY/DP 查证或 ASK，纯计算有证据的子判断可保留。无条件合并失败 |
| A 改 Owner/合法变化轴为两套独立政策 | 不用同名作为共享依据；保持各业务行为，重新证明纯机制；不强制拒绝所有共享 |
| B 从本地短输入改为获权 HTTP 跨重启，或删除实际验证器 | 选择与排除机制改变；验证器缺失时不能给安全续传结论；不把从未访问的 locator 记为不存在 |
| B 提供正确定位但只提供其它 Kafka/HTTP 或 parser 版本的真实合同 | 决定性版本适用性未确认，标 STALE/UNKNOWN/另查；旧文档字节正确并不消除版本风险 |
| C 同一意图存在两个同范围相冲突的权威收据 | 保留冲突，禁止合并成最新一条或自行宣布 success；不相关的导出拒绝仍成立 |
| 任一题删除必要读取范围、关系访问预算不足 | 记录具体未访问和材料缺口，必要部分 UNKNOWN；不能把“无命中”当不存在或完整候选集 |
| 任一题加入同名但无关的 framework/benchmark 文档或错误候选关系 | 排除无关/不具真实前提材料；不得改变已证实合法判断，也不得借噪声生成未授权工具动作 |
| C 收到真实当前且同主体成功收据（不冲突） | 限定已确认效果，不能永远 ASK；仍不从收据推断独立权限或其它效果 |

这些正反轨迹是作者设计的可证伪目标，不是系统执行结果。独审应从源与明确假设独立推导并挑战，不照抄这些预期。公开 W36 及此前 G/B/R10 练习不能作为隐藏题或宣称模型未见过的泛化证据。

## 5. 下一阶段的评价单位、证据和准入

复用 [R10评价协议](../../../v2.1.2/software-engineering-knowledge/professional-knowledge-evaluation-protocol-r10.md)、[T34b-1](../fine-grained/T34b-1-empirical-research-design-causal-evidence.md)、[T34b-2](../fine-grained/T34b-2-engineering-measurement-human-factors.md) 及原 #561 R20 归档结论，不重复历史 Agent 实验或改变原结果。下表为未来有权任务的独立观测层，不把上一级通过推为下一层。

| 评价层 | 分母/观测 | 能否据此声称工程效用 |
|---|---|---|
| 内容存在 | 独立指定的有限问题和真正必要机制；实际定位及正文是否回答目标 | 否；未读不等于不存在 |
| 可发现 | 全部预先分配查询；访问范围、必要引用召回/遗漏、无关材料、版本正确性、预算/不完整 | 否；候选命中不证明适用 |
| 选用与决策 | 全部被分配决定，独立审核必要/可选知识集合（允许等价途径）、采用/拒绝原因、正反变形、错误放行/过度拒绝 | 否；结构合理不证明代码 |
| 真实工程行为 | 有权真实仓库/任务、初始/结果SHA、实际构建/执行、权威前后状态及真实消费者；所有 Attempt 包括失败 | 仅限定行为证据 |
| 独立验证 | 冻结有权义务全集、独立 Oracle 与真实结果/覆盖；缺执行/陈旧/矛盾/未核查分开；不靠 Builder 自评 | 仅相应验证范围 |
| 维护与成本 | 同一合法后续变化、真实制品、回归、端到端资源、返工/Reviewer/人工介入；全部原分配，缺失另报 | 有可比研究设计才评价限定效用/因果 |

**先做设计验证，再决定是否需要新真实任务**：独审 T36 合同、真实定位/身份、关系条件、纸面轨迹及评价可区分性。通过后可另行准入有限专业投影扩展（按真实任务选择更多 Kxx，不强制全量切分）与 #563 原抽象决策产品方案的重新核对；#565 原 R5 2P1/2P2 未修复，A24/T4 仍 HOLD，不能借 T36 自动 dispatch。若真实 SDK/Consumer 未获权或不足，保留 BLOCKED/NOT_RUN，先处理原问题，不能模拟生产接入。

如未来 Owner 重新授权研究，先独立冻结真实任务/初始制品、合法维护要求、隐藏 Oracle/评分、模型/预算/工具、分配方法、实际对照和停止条件。优先有限真实新代码消费验证实际决策/行为，不因此宣称因果；需要因果才考虑 T34b-1 的 K（相关知识）×S（阶段化交付）或受控匹配设计，基础权限/任务资料不因分组而缺失。记录实际分配、送达、阅读/引用、真正采用、最终结果及维护，而不是只比较成功者。隐藏评价由独立非作者在隔离位置保存，避免公开近重复和跨组泄漏，真实交付及维护全部 Attempt 纳入分母。样本量、任务集、阈值和运行预算尚未确定，无新 Agent 授权；不虚构统计功效、准确率、节约或因果收益。T36 不产生任何生产 Rule、SDK新ABI 或发布资格。
