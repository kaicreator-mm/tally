## 2. 公开选择推演与反转（NOT_RUN）

这些是作者给定的纸面材料，不是独立实验、实际代码或隐藏题。下面每一组均以明确合同选择，而非要求固定引用组合；独立reviewer应从来源重推预期，实际执行时另获权冻结任务和Oracle。

### A. 数据模型、查询与精度不是同一个决定

教学：项目p、设备d、设备型号m，登记关系键(p,d)，FD为p→pn、d→m、m→mn、(p,d)→role。RELATIONAL 给出原关系三次无损分解及依赖保持的独立依据；更广模型增加厂商/序列号不是原关系列。另一个L(city,street,zipcode) 满足(city,street)→zipcode、zipcode→city，两个候选键均含street。拆Z(zipcode,city)和S(street,zipcode)无损，但 Z={(z1,c),(z2,c)}、S={(s,z1),(s,z2)} 各自满足投影FD，连接违反原(city,street)→zipcode；不能只因BCNF更强就批准本地约束不足的设计。若真实订单保存成交时商品名称/价格，属于历史合同，不以范式教条改成读取当前商品名。

CONSTRAINT针对真实数据库写入：同厂商重复serial拒绝，不同厂商相同serial允许；代理键本身不能保证业务唯一。PG18 CHECK(q>0) 对null不拒绝，要求存在才另用NOT NULL。FK也不能授权跨租户登记。若角色允许多个或需保存历史登记，重新确认键而非沿用(p,d)。QUERY针对真实读合同：项目A有reader d1、operator d2，B无设备。LEFT JOIN在ON过滤reader得(A,d1),(B,NULL)，在WHERE过滤会丢B；COUNT(*)对B=1而COUNT(device_id)=0。索引变化须先保持真实结果，再核实际计划/负载；不能以EXPLAIN估算或语法等价代替。

实际涉及金额才追加PRECISION数值部分：三个0.335逐笔half-even=1.02、先求精确和后half-even=1.00，必须由有权政策确定舍入点；decimal从float构造并非恢复原字符串。若只涉及locale排序分页，不必读金额合同：id101/102的规范等价Å名称排序相等不等于身份相同，(collationKey,id)稳定次键保留两条（按本题ID合同和同一数据/排序版本），仅按key>last会漏102。若真实业务以NFC名称为唯一键，冲突由Owner裁定。独立预期用真实合法关系、记录粒度、金额政策或身份集及实际结果，不以SQL实现自身作为唯一Oracle。

### B. 数据库事务、内存同步与外部效果的边界

教学：X、Y两台设备均enabled，权威合同至少一台enabled。PG18两个独立事务分别读取两台，然后分别只关闭X或Y；普通各自行锁不保护共同谓词，稳定快照仍可能写偏斜。TRANSACTION比较真实Serializable（所有相关写路径遵守合同，至少需处理序列化失败并获权重试整个事务）与锁共同项目权威行再按真实隔离合同读取/判断。独立两连接控制交错并读回，最终不得零台enabled；不能只检查某次更新返回成功。若仅单行余量扣减，原子条件UPDATE及真实受影响行可能已足够，不强制所有事务Serializable。若状态权威改为仅进程内内存，则按SYNC保护检查及修改全路径；单线程两个await间共享一个名额也可能竞争，race detector干净不证明业务不变量。

Go限定例：写value=42后close(ready)，接收因关闭返回后读取，在仅原写者及无额外写条件下有同步关系；close后无同步写不能维持原证明。选择实际语言/内存模型而非统一锁抽象。若写入需要真实当前授权/任务许可，另选P36-COMMIT；若跨独立付款或邮件，另选P36-EFFECT并核真实稳定意图/权威结果。数据库事务提交与远端ACK不同。一次DB序列化失败可获权重试完整数据库操作，不因而许可重发任意外部Effect；提交ACK丢失必须读回权威状态，不直接当失败。独立观察提交、业务谓词、外部结果与许可分别成立。

### C. 任务、数据结构、超时和容量

有真实控制器C=4执行许可、Q=16待办，所有已受理任务仅在这两互斥集合且超额准入前拒绝，则本控制器最多持有20；若入口先产生无界producer或另有重试队列，不能说全系统20。选 LIFETIME；真实需按ID取消/改优先级且选择堆时才选HEAP/REPRESENTATION。原合法堆键[1,5,2,8,9,3,4]删除index3键8，末4移入后[1,5,2,4,9,3]必须上浮得[1,4,2,5,9,3]；删除原index2键2，末4填入[1,5,4,8,9,3]需下沉得[1,5,3,8,9,4]。ID另有独立身份，不是数字键；每次交换同步更新pos，独立ID→键模型核域/基数、双向映射、父子顺序和根/稳定次键。最终排序正确不能掩盖中间错误。若已出队获许可，即使用户函数尚未进入也不属于仍排队项；堆删除不能撤回其运行许可。取消、settlement、join和外部效果另按真实合同，简单FIFO无任意删除需求时不引入双索引。

DEADLINE：同一时钟域5秒预算，第1阶段消耗3秒，第2阶段最多剩2秒，若耗尽不得启动下一工作或正时长backoff。墙钟向后校时不应延长经过时间预算；Linux suspend是否计入按实际合同选clock，monotonic绝对数不跨重启使用。等待超时若实际工作仍运行，不声称已取消。真实完成迟于deadline可保留结果但不能算按期。独立观察实际准入、许可、调用、资源释放、时间域和远端UNKNOWN。

CAPACITY：同一窗口初始10、接纳100、完成80、确认取消5→在途25；另外10客户端超时但远端未确认结束不能减成15。M/M/1仅给定稳态泊松、指数、单服务台无限队列等条件；μ100/s、λ80/s，W=50ms、Wq=40ms均值，不是P95或真实容量。单CPU需求8ms/任务与独占DB20ms，理论吞吐上界125/s与50/s，增worker不突破共享DB。开放负载1000计划/900发起/810按期，服务已发起任务按期90%、生成实现90%、计划按期81%，未发起100不是已观察的服务器失败。若实际目标仅闭环固定并发则按其不同模型验证，不将所有闭环试验称错误。无真实测量不报告性能提高。所有这些教学算例只用于独立纸面复算，不能作运行证据。

### D. 分布式权威、投影、租约和删除

CONSISTENCY：W(x=7)响应后才开始R，且无其它写，R=6不满足线性化；重叠时可有合法次序。单键读各自正确不保证跨键快照。5固定成员多数3，3+2仅3侧具多数、2+2+1均无；假定可互通及正常协议/持久化，多数交集最少1，不证明任意Raft提交或给定时间进展。若本地DB足够不加载多数协议；分区若同一名额不可冲突，必须等待/拒绝或设计获权可独立额度，不让两侧无通信均报成功。

WATCH仅实际etcd v3.6投影：r10快照，r11同改A/B。created ACK header14不代表11..14已应用，半组后断线不得记11，必须从持久10+1重放；完整组、投影及checkpoint原子持久化。实际分页固定r10且cluster_id不变，r10第一页A，r11新增B并改C，第二页仍读r10的C旧值（header即使11也不改r），随后watch从11。实际fragment须禁用或完整重组，DELETE使用删除revision；压缩/换集群重建相应身份。只有监听部分scope不能把revision间隔当遗漏；进度通知同watch身份及完整持久应用后才可推进。当前业务权威读仍选实际合适线性化读/事务，不从watch的最近接收判断。P37-RECOVERY用于确有恢复及一致点目标时，非每次watch必读。

FENCE与P36-COMMIT联合但不等价：A41暂停租约失效，B42已在同一资源原子建立42并写入，A41随后应拒绝；若B尚未在资源建立42，仅高水位41仍可能接受A41，故不能承诺失效即刻撤权，严格当前授权需实际保护提交合同。另核同token重复、可信发放、资源/epoch与灾难恢复切换；不可验token的外部API不能借此保证。合法既有提交不因撤权自动删除。独立验证实际高水位、写入和授权先后而非只看协调服务owner。

LINEAGE：中心授权离线补丁例generation1 v7 (N,100)，D1改名先提交v8，D2改价120若不同字段且无联合约束冲突、当前获权才合并v9(N1,120)，同字段冲突或关联数量/单位不能仅按到达时间自动合并。权威删除v10后旧v7不能复活，获权重建用gen2；恢复备份v9隔离读历史，重新开放当前目录前核实际删除/权威状态。源A R2 11=10接受+1拒绝+0未读，不能说目录恰10商品，也不能由CouchDB确定性winner推断已解决业务冲突或OpenLineage图证明质量。墓碑退休只有旧事件/离线重入/恢复合同实际可拒绝旧写才批准；未证保持UNKNOWN，保留期/清除须授权。独立比对实际源版本、变换、映射身份、授权、删除持久事实及派生应用，发送ACK不是所有副本已删。
