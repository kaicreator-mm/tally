## 1. 发现与选择是两件事

目标不是取最相关的文档，而是找足以改变当前工程判断的专业机制。先核有权目标/合同、当前真实对象和阶段、材料风险与环境；区分证实事实、否定事实、假设、缺失、冲突、旧证据。检索不能充当业务授权。面对未给出的材料事实，可先给条件化方案、明确询问或 UNKNOWN，不将缺失当否定；无关不确定不阻塞其它独立子判断。

发现入口优先复用原 Kxx 课程/Topic/深度地图、[T22案例反向索引入口](../casebook/waves/T22-current-knowledge-entry.md)、[56组及阅读路径](../T23-reading-paths-and-waves.md) 与 [细粒度46篇入口](../fine-grained/README.md)。问题同义词/术语/领域对象/功能族/质量风险可帮助召回；阶段只是辅助过滤。多个可能 Owner 并列查询，查不到应扩大有界搜索或保留 UNKNOWN；pilot 没有命中不证明全库没有知识。向量或全文只是以后可选的发现方式，不能决定事实、当前性、必要条件和真值。没有新增索引服务或检索算法。

候选来源从实际精确文档读取，不仅看标题和摘要；核条件、版本、反例、原资格、跨域邻接。先验证本候选能回答什么，以及若采用它会改变哪个可观察选择。仅引用足以解释结论的正文范围，保留必要反例和限定。来源 locator 的 commit/blob/范围不一致，或实际适用的 API/消费者版本不同，则查新来源或返回 UNKNOWN；同一引用的文本完整性并不替代任务来源的当前性。已有 #564 投影仍是原抽象切片参考，本批 [pilot](pilot-references.json) 是其旁路设计资料，不是替代运行输入，不把两种 JSON 自动合并。

## 2. 以决定为中心的消费收据

每次选择可用自然语言/表格记录以下字段（不是强制表单或新机器 ABI）：

| 项目 | 说明 |
|---|---|
| 当前决定与输入身份 | repo/Issue、实际基线/制品、合同版本/Owner、阶段、具体候选/对象、目标与允许操作 |
| 材料事实 | 每项有来源、范围、版本、真实确认者；事实缺失/冲突/过期与不适用分别标识；不可把待评价者自报当可信上下文 |
| 候选及选择 | 需要回答的问题、精确知识引用及实际阅读范围，为什么适用；排除哪些近似但不适用的知识/案例，哪些只是条件启发 |
| 结论与未决 | 有条件建议、KEEP/TRADEOFF/EXCLUDED/ASK/UNKNOWN（沿用原业务含义，不新造 Runtime enum）；明确实际结论范围、备选与反转条件 |
| 验证与交接 | 独立合同/Oracle、输入及预期、真实执行状态与未完成项；下一阶段能使用哪些结论、还需核实哪些 |
| 完整性与预算 | 访问范围、已读/未读、停止原因；如果必要材料遗漏/预算耗尽，受影响结论 UNKNOWN，非完整结果 |

最小充分意味着每一项已选择材料具有具体用途，且所有决定性事实/约束都有证据和适用机制；不能以最少 token 为单独目标，不能为了减少阅读而删反例或权限。没有通用的最小唯一知识集合。重复等义片段可择原 Owner 的准确解释；实际版本、正反例或补充机制独立必要时都保留。首次读取的知识不要直接当已消费；实际使用须在决定理由中对应它改变/约束了什么，并在后续真实观察记录里验证。只有完成检索不等于完成决定。

## 3. 分阶段，不重复全量注入

下表的阶段是实际工程问题的视图，不定义 ADS 新流程；任务很小且无独立风险时合并阶段，复杂任务可回访上游。工作计划与任务权威仍由 ADS/Tally 既有合同决定。

| 实际问题 | 优先选择的专业责任与例示入口 | 交接而非复制全文 |
|---|---|---|
| 需求/L1 | K01、必要 K02/K05：权威、业务合同、质量目标、当前/未知；T24a/T24b-1 | 合同/Owner/事实/禁止行为、独立验收目标；缺权限则 ASK |
| 架构/L2 | K02、必要 K03/K10/K11：职责/事务/失败域、真正变化及替代；DP-K02-R19-01、T26a-2 | 候选比较、必要不变量、拒绝原因、真实消费者、待证前提 |
| 详细设计/L3 | K03、K01/K02：具体算法、接口、精确语义、资源与并发；DP-K03-R19-01、T27a/b/c | 最小实现合同、受影响代码与数据边界、真实协议/语言版本 |
| 实施 | 已授权的工作范围；只读所选专业机制、实际代码/库合同；K04/K08 在真实任务/制品需要时加入 | 实际变更、执行命令和失败、当前 SHA/制品；计划不是执行收据 |
| QA/Review | K05、K06、K08：独立 Oracle、验证范围、真实执行身份、故障探针 | 独立结论及未执行项、反例、准确 HEAD；不使用 Builder 自报当验收 |
| 维护/运行 | K09/K10/K11：已支持消费者、版本、现状/历史、恢复、变化成本 | 原合法行为与合法新增变更、回归/真实成本和失败；反馈候选待审 |

阶段只携带当前必要输入、上游已确认事实、结论及其证据引用；同一源可以再读取，只有当前阶段需要其具体内容时才注入。若 L2 发现业务合同冲突，应回到 L1 的实际权威，不强行按流程继续；新版本事实导致旧决定不可用，重新选择受影响部分，不将整个旧报告直接当新事实。隐藏评估 Oracle 不向 Builder 注入；公开专业反例与测试方法可供正常学习。QA 独立从实际合同获得预期，不能以 Builder 选用的知识清单推导所有必需义务。

## 4. 实际有限投影如何使用

pilot 的13条导航记录分为三个相关但不强制互相加载的路径：
- 抽象与维护：两个原DP、K05.ORACLE、P36-POLICY、P36-MAINT。真实共享的机制与不同业务政策分开；确认源合同和候选语义再比较，不预设答案。
- 下载/导入：P36-RANGE、P36-DURABILITY、P36-STAGING、P36-COMMIT；只在实际跨重启、HTTP 续传、持久 staging 等条件成立时选择。若只有短本地输入，无需 Kafka、HTTP range、持久下载。
- 外部效果/权限：P36-EFFECT 仅为本地 Outbox/Inbox 与外部 UNKNOWN，普通邮件/付款不要求 Kafka。实际采用 Kafka 消费进度才选 P36-OFFSET；若比较 Kafka 内事务与独立 SQL/HTTP，另读 [T27c-3 §4 完整限定范围](https://github.com/kaicreator-mm/tally/blob/7f5160b3ec4b29138d4f21e9bcc6ff21459090a3/docs/versions/v2.1.3/knowledge/fine-grained/T27c-3-reliable-messaging-outbox-offsets.md#L48-L58)（原 blob 973fb2b186a5e76b5fe08dfa15e8c6b2544bcac8），不是普通外部 UNKNOWN 的必读。P36-CACHE 核实际查询缓存/异步 UI 条件，并包含 L45–72 的受保护披露合同；纯长导出可以直接选择 P36-POLICY/P36-EXPORT，不要求加载缓存、UI 或 Kafka。P36-COMMIT 仅在真实写侧提交条件有关时选择。不能因为全是异步任务就共享政策、事务或安全重试。

每个路径仅提供现有正文定位和候选判断提示；导航边 CONTEXT_FOR/SUPPORTS 不必遍历到闭包。公共问题先使用覆盖已有专业知识的入口，再按具体风险深入；领域专项 HC-04、DA-08、RE-04 和未选变体仍可触发有界新研究，RE-05 暂缓、RE-06 排除维持；最低授权、隔离、保密和完整性仍有效。遇到未知协议/平台，不能套用 pilot 的具体结论或把 U 转为 S。

## 5. 停止、失败与演进

建议按任务实际风险在开始前确定有界阅读/决策范围：最大源读取/关系访问、可返回候选、上下文及时间。具体数值由真实消费任务的模型和环境确定，本文不冻结任意通用上限。达到预算时，报告已验证部分、未访问范围、必要缺口及恢复入口；禁止截断后把必要材料当不存在。对于小任务已有明确可观察合同、适用机制、反例及最小可行候选，停止扩张；没有材料证据支持更复杂方案不能把未知未来当需求。多方案均符合合同则保持权衡，不伪造唯一最优。

每次实际使用发生失误、源版本变化或有权维护需求时，回指知识引用及失败事实；区分定位失败、选择失败、错误推理、工程执行失败、Oracle 不充分、真正知识内容缺口。先修最小责任层，保持历史原始结果，新增知识/关系需原 Owner 核实及适用范围独审。自动采纳新 Rule、执行 Tool、生成 Package 或发布均不在本批；#565 R5 未修复，不能以文档设计替代它。公开演算和未来评价见 [T36-D](evaluation-and-worked-traces.md)。
