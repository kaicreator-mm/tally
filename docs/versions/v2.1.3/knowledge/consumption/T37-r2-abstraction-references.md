## 2. 公开工程选择推演（NOT_RUN）

这些是作者合成的材料事实与期望，只验证引用设计是否有区分性，不是实际模型执行、真实代码或隐藏题。独立 reviewer 应从有权合同及实际原文推导，不以固定键或候选选择作为唯一答案。

### A. 抽象粒度与状态所有权是不同决定

教学：同一模块两入口的纯格式化前后置、错误及合法变化已经确认为相同，维护者已有两处必须同步的修复，业务发布动作分别有不同授权。选原两个 DP、COHESION/SMELL 比较 inline、私有helper 与公共接口。可以共享纯格式化，不把发布命令合并为 mode 并抹去权限；没有真实外部消费者不强制公共Strategy。若修改只是两个不同业务的同形正则且一方保留空格，则不能共享完整格式语义。若实际只有一处且没有变化隔离收益，直接实现也合理。

另一个明确合同：构造输入可变数组 x=[1,2]，模块承诺独立快照，之后调用者合法修改 x[0]=9。选择 INPUT-OWNERSHIP（原研究反馈候选）与已有 REPRESENTATION；当前可观察结果必须仍为[1,2]，调用者原对象可依法修改，不能因为模块是唯一内部写Owner就保留别名。独立观察输入、内部抽象值和 frame，不要求所有语言都深复制。若获权合同实际改成共享可变视图或有效不可变借用，原快照预期不适用；未声明不擅自创造义务。数字运算错误若未能证明与边界/共享/表示选择有关，不自动标为抽象缺陷；实际判定沿用原DP和R19-F2限定。

### B. 组合、资源与权限不可被统一接口掩盖

教学：当前 A 直接声明 B，B 声明 C，实际项目明确要求直接依赖才可调用。A 通过解析路径直接调用 C，即使编译成功也违反当前静态合同；可合法声明 C 或通过 B 受约束公开接口。C 的外部写动作仍需独立授权，声明成功不授予 Host 业务权。选 BOUNDARIES，若实际 npm v11 再选 DEPENDENCY/INSTALLED，分别核声明、解析、加载和真实包，拒绝以 workspace hoist 掩盖缺 codec。有限 host ^2.0.0 和插件A peer ^2.1.0 的可选2.2.0；若插件B要求^3.0.0 且必须共享同宿主实例则无共同解。独立安装3.1.0不能满足该实例合同；若工具真正独立、无共享实例要求可重新比较，不要求 monorepo 所有版本一致。

封装候选 acquire A 后 acquire B 失败：选 ERROR-RESOURCE 与 TESTMODEL，独立核只释放已取得的 A，不释放未取得的 B，保留主失败和实际清理故障；真实语言机制另查。合法 patch 缺失字段保持原值，显式 null 清空，不能用统一 default 混同。取消返回不证明远端效果未发生。若只有纯值计算、无资源和错误语义变化，不引入通用资源管理层。真实组合必须保护跨对象不变量和 frame，不能以同签名替代行为兼容。

### C. 实际变化决定架构与扩展能力

依据原 D0（STYLE）：同一DB四权威事实、持久受理后可提前返回且跨重启恢复，两固定输入格式、无独立插件作者。候选直接同步无持久待办不满足当前合同；模块化单体+内部层+pipeline+异步投影是组合而非互斥模式，可作最小待验证基线。独立服务各DB若破坏四事实共同提交，则拒绝；动态插件若没有真实扩展消费者不默认增加。Q5容量/SLA未知，不宣布性能优胜。选 SCENARIO、STYLE、原 COMMIT（实际保护提交时），VARIATION 仅有真实合法变体时选，ADR 记录条件反例与复议。
- 变化为真实第三方格式作者及独立发布，才比较窄扩展合同、版本和能力、资源及终止；不把插件当发布授权或沙箱保证。
- 教学格式2种×审批2种×存储2种共8；manual需要DB、file仅CSV，合法组合5个，禁止其它3个；仍未证明5个产品的完整恢复/权限合同。若后来实测file不满足必需持久受理，则该变体不可批准。独立验证组合约束及业务实际行为，不因默认产品绿而全通过。
- T17三例为已有真实局部对照：Oscar可跳过不合格订单行，与新 all-or-nothing 合同冲突；Saleor取消资格谓词与命令分开，前置查询后状态变化需实际提交保护；Odoo确有销售基类及库存模块 override 扩展关系，不证明所有业务需要插件或真实事务/ACL。读取 BUSINESS-CASES 及原来源登记，当前授权和合法业务规则仍来自真实Owner。

### D. 维护时可能删除抽象，也可能必须补充

HISTORY-CASES 的已登记真实历史局部观察：pytest删除仅服务内部控制流的 getnextitem helper；HTTPX先弃用后移除公共 app shortcut（0.27 warning 为 truthy app 条件），调用者迁移成本未知；p-limit 给 limitFunction wrapper 补 clearQueue 委托已有队列能力，仍排队项才清除，不撤回已出队获许可但尚未运行用户函数的项。不是越少方法越好；内聚/粒度/维护各自核真实合同。

教学维护任务：某真实系统要求两个受支持消费者逐步从 O 到 N，选择 MAINT、REPLACEMENT，实际需要时读 ADR、MIGRATION、INSTALLED。先捕捉有权窄边界，迁移实际消费者，验证同合同；同一真实写意图只交获权一方，不以生产双写做对照；新状态不兼容则关闭开关不代表可回退。退役须有实际消费者与状态证据、授权和支持期限；静态零引用不足。若有权明确无旧运行时支持且无需共存，可直接替换，不能用模式教条强制兼容shim；合法历史数据合同另核。成本结论需真实同类维护变更、独立回归及耗时等证据，不能凭删LOC/新增委托或历史提交接受推断经济收益。

## 3. 停止、独立验证与交接
