# Tally v1.4.1 Target Architecture

The Final PRD and Decision Locks are authoritative.

## Product loop

```text
AI Runtime PlanningResult
        ↓
Intent / Dynamic Clarification
        ↓
FrozenIntent + TaskContract + VerificationContract
        ↓
Contract Compiler
        ↓
EngineeringPolicy / Risk / Assurance
        ↓
Tally-owned disposable workspace
        ↓
agentruntime.Runtime
        ├── Codex Runtime Adapter → external Codex process
        └── DSH Runtime Adapter   → external DSH process/bridge
        ↓
Tally freezes immutable ChangeSet
        ↓
Tally Verification
        ↓
Repair / Escalation
        ↓
Acceptance
        ↓
controlled local Git integration
        ↓
Outcome
        ↓
Rule Proposal / Replay / EngineeringPolicy evolution
```

## Runtime boundary

There is no new generic ExecutionBackend.

The single core protocol remains:
- `agentruntime.Runtime`
- `agentruntime.Session`

Harness implementations are external processes.

If DeepSeek Harness needs an SDK, a subprocess bridge is allowed, but Tally Go still communicates across a process boundary.

## UI boundary

Navigation is a projection:
- Work
- Runs
- Reviews
- Rules

It does not replace the existing lifecycle state machine.

Dynamic Forms are bounded presentation objects and cannot create domain schema or executable UI.

## Rule boundary

EngineeringPolicy remains the runtime rule schema and Git snapshot remains runtime authority.

Governance adds:
proposal → evidence → replay → human approval → GitWriter activation.

## Git boundary

v1.4.1 release scope:
- L0 read
- L1 workspace
- L2 commit
- L3 controlled local integration

Remote push/PR/MR is not a release blocker.
