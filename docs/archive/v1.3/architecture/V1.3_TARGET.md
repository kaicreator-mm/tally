# Tally v1.3 Target Architecture

This is a navigation summary. The PRD remains authoritative.

## Product hierarchy

```text
Human Idea
  → Product/Engineering Intent
  → TaskContract
  → VerificationContract
  → CodegenRun
  → immutable ChangeSet
  → VerificationRun / Evidence
  → Patch Review
  → HumanApprovalEvidence
  → derived lifecycle state
```

Tally is the lifecycle control plane. Codex/OpenCode/Pi are execution runtimes, not the product core.

## Authority model

```text
LLM output      = Proposal
Agent result    = Claim
Validator output= Evidence / Fact
Lifecycle state = Derived
Human           = decision authority where policy requires
```

Implementation Authority cannot redefine Verification Authority.

## P0/P1 architecture locks

- Go remains the authoritative control-plane language.
- PostgreSQL + sqlc + goose remain the persistence stack.
- Brownfield Core Replacement; no greenfield rewrite.
- Production Git writes converge on `internal/gitwriter`.
- Executable commands use structured argv/cwd/env/timeout and deny implicit shell semantics.
- Agent execution uses disposable Git worktrees; the owner primary worktree is not an execution sandbox.
- ChangeSet is immutable; supersession is append-only fact.
- Desired contracts and observed execution/evidence remain separately traceable.
- Acceptance owns `independence_required: none | source | information`.
- Functional Coverage and Independence Coverage are separate gates.
- P1 held-out scope is minimal isolation/final execution/exposure accounting, not full automated recovery.
- P1 workflow is a single-Task vertical kernel, not a generic workflow engine.

## Phase boundary

P1 proves the Vertical Trust Loop. It does not implement full Triage, Task DAG autopilot, Pi/OpenCode production adapters, delivery/incident redesign, or AdaptiveKit evolution. See `docs/tasks/v1.3/DEFERRED_ROADMAP.md`.
