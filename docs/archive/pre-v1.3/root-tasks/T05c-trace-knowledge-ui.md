# T05c 追溯 + 知识 Wiki UI + 算出状态

## 前置
T06 T07 T08(知识、需求、追溯数据就位);T05a(Web 地基)

## 目标
补上平台最后一块:已验证修复库浏览、诊断状态、视图 A/B、条款覆盖率,以及**任务算出状态**的展示。**知识 Wiki 两层在此彻底分开。**

## 交付物

```
internal/web/handlers/
  knowledge.go      已验证修复库浏览(按指纹;只读,无编辑入口)
  diagnose.go       诊断状态(第几轮/五分类)+ 触发重诊断(入队)
  views.go          视图 A(条款累计失败)/ 视图 B(指纹影响面,LEFT JOIN 条款)
  coverage.go       条款覆盖率、依据已变更标记
  taskstatus.go     任务算出状态展示(从执行链算,无勾选框)
web/templates/      对应页面模板
```

## 验收标准

### 知识 Wiki 双层(核心)
- [ ] **已验证修复库页面无任何编辑/新增入口**(只能经失败处理流程入库,INV-2)
- [ ] 验证库条目用 `--verified` 绿 + 「已验证」标;Wiki 笔记层(T05a)用 `--stale` 赭石 + 「笔记·未验证」标;**两层视觉上明确可分**
- [ ] 修复条目展示:指纹条、复现命令、修复内容、验证时版本组合、是否漂移(stale)

### 视图与状态
- [ ] 视图 B「关联条款」列用 **LEFT JOIN**:无需求层时该列空,页面其余照常
- [ ] 视图 A 展示:实现提交数、构建/部署失败数、同一指纹次数、条款年龄与变更次数
- [ ] 任务「完成」从执行链(合并/构建/测试/部署/稳定)**算出展示,无手动状态控件**(INV-3)
- [ ] 触发重诊断走 jobs,**三轮上限由后端守**,界面只显示「已达上限,不再诊断」

### 通用
- [ ] 所有写路由过登录 + CSRF(INV-9);关 JS 仍可用;空状态是行动提示

## 不要做
- 不给验证库加编辑功能(哪怕「只改个备注」)
- 不做手动挂钩界面(挂钩来自 commit trailer 与测试注解,不来自人点)
- 不做条款全文编辑器(条款在 git,界面渲染 + 链接)
