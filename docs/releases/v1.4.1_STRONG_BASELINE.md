## Closure repair changes

- Fixed Safe Export self-triggering on its own private-key marker fixtures/source.
- Raw tar paths are validated before normalization; non-canonical/traversal spellings are denied.
- Default `HEAD` export rejects a dirty worktree so working-copy changes cannot be mistaken for the archived candidate.
- Outcome replay idempotency moved from check-then-insert to DB unique constraints + `ON CONFLICT DO NOTHING`.
- Codex/DSH failure summaries are redacted before they cross the durable claim/log/UI boundary.
- DSH live validation uses the same `TALLY_DSH_BIN` configuration face as production and cannot silently SKIP after live validation is explicitly requested.
- Three duplicated legacy LLM→AI Runtime adapters were replaced by one composition-root adapter and an architecture guard.
- GitHub CI now covers source quality, architecture/runtime/tool tests, build, repository hygiene, Safe Export and PostgreSQL integration separately.

## Validation semantics

Use exactly these meanings in reports:

- `PASS`: the command actually executed successfully against the candidate.
- `FAIL`: the command executed and found a defect.
- `SKIP/NOT_RUN(environment)`: the command could not execute because the required external environment was unavailable (network dependency download, PostgreSQL/Docker, real DSH launcher/key, external Hidden Validation pack, etc.).

An environment SKIP does not block creation of a **development baseline**, but it remains open evidence for **release qualification** when the skipped gate is release-required.
