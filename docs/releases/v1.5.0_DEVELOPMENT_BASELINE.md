# Tally v1.5.0 Development Baseline

**Status: DEVELOPMENT BASELINE — NOT RELEASE QUALIFIED**  
**Base:** v1.4.1 brownfield implementation  
**Scope:** Engineering Control Plane Foundation

This document describes what is implemented in the v1.5.0 development candidate. It is deliberately not a release declaration. Required full visible validation, real Critical Journeys and external Hidden Validation still need to execute against one frozen candidate.

## Implemented foundation

### Engineering lifecycle domain

- `RequirementsBaseline` with explicit acceptance criteria, artifacts and provenance.
- immutable-style `PlanningRevision` / `ProjectPlan`.
- `ArchitectureRevision` with typed architecture constraints.
- validated `TaskDAGProposal → ActiveTaskDAG`.
- deterministic dependency/readiness and parallel-ready derivation.
- `Active TaskDAG = Project Flow`; no second project-flow state authority.
- append-only Action/Audit records.
- deterministic `CompletionContract` over required state, artifacts, PASS evidence, PASS checks, action records, authority and Git-operation records.
- human participation/authority values including `AUTO`, `SUPERVISED`, `AUTHORITY_REQUIRED`.

### Intelligence boundary

- common typed `IntelligenceProvider` contract for Direct and AI Runtime adapters.
- provider result contains Proposal / Assessment / Recommendation + provenance.
- provider output is advisory; it cannot own Project/DAG state or bypass deterministic gates.

### Execution contracts

- thin `AgentExecutor` above the existing `internal/agentruntime` protocol.
- orthogonal `ExecutionEnvironment`, `ExecutionTarget` and environment-aware `WorkspaceRef`.
- Local compatibility implementation for v1.5.0.
- explicit cancellation/interruption and bounded resume/fresh-fallback semantics.
- task correctness does not depend on Agent-session resume.

### Engineering Control Plane

- project lifecycle accepts Requirements → Plan → Architecture → Active TaskDAG in order.
- restartable file-snapshot compatibility repository for v1.5.0 project/DAG/audit state.
- ready task dispatch, governed block/interruption and DAG advancement.
- Authority decisions remain project facts and participate in CompletionContract rather than Agent output.
- protected JSON API under `/api/v15/...`.
- minimal protected browser console at `/v15/control-plane` reading the same snapshots and writing only through the existing API.

### Brownfield execution bridge

Production v1.5.0 task execution reuses, rather than replaces, the v1.4 authorities:

```text
Engineering Control Plane
        ↓
Brownfield TaskHarness
        ↓
load pinned Git execution bundle
        ↓
CompileAuthority
        ↓
existing closedloop.WorkspaceExecutor
        ↓
AgentExecutor
        ↓
existing agentruntime.Runtime × Local Environment
        ↓
Agent Claim
        ↓
immutable ChangeSet freeze
        ↓
durable CodegenRun + ChangeSet lineage
        ↓
existing candidateverify
        ↓
existing closedloop repair / accept / escalate
        ↓
Accepted Basis → CompletionFacts
        ↓
CompletionContract → Active TaskDAG advance/block
```

Safety properties include:

- executable changes run only in Tally-owned disposable linked worktrees;
- owner primary checkout is rejected at candidate-freeze boundary;
- completed Agent claim with no code change is not a candidate;
- unsupported deletion representation fails closed;
- immutable ChangeSet is durably associated with a real CodegenRun before independent verification records facts;
- repair attempts receive only the existing allowlisted safe RepairFeedback projection;
- held-out execution remains fail-closed without independently verified session isolation;
- Codex/DSH remain behind one `agentruntime.Runtime` protocol.
