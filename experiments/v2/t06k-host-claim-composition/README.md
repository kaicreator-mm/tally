# T06k — integrated native GitHub transport/Host CAS controller smoke test

This targeted Node24 test runs **existing**, previously source-reviewed Tally v2 components together: #160 native GitHub Task/dependency/no-claim source preflight; #161 one-shot GitHub ADS `DISPATCH_CLAIMED` POST+GET; #159/#163 exact native event/comment publication witness and Host after-state readback; and pre-existing #132 Host single-writer controller. It uses the ordinary native-C Woodpecker test profile.

**Test trust boundary (critical):** the in-process Octokit object and Map CAS store are explicitly **simulators**. Its `source.readAdmissionFacts` constructs the privileged Host admission projection **only inside tests**, after real C-style source validation. This is deliberately **NOT** a production Host admission authority and MUST NOT be copied into a deployed adapter or exposed through B/Agent/UI. Unlike the separate #132 `single-writer.test.mjs`, it does **not** use the real public DomainHarness SQLite CAS. It tests composition/contract interoperation and negative behavior, not a real GitHub write or physical exclusive Host deployment.

Claims verified by test: one source-qualified simulated Task can pass through existing CAS callback interfaces to one bounded ADS GitHub event and exact readback with a **non-authorizing** persisted Host receipt; competing simultaneous dispatches lose at the CAS boundary; actual blocked_by/non-ready Task cannot POST; lost ACK and tampered readback preserve PENDING, never retry blindly. **Not verified**: real GitHub CAS/accepted Start Record, `state:claimed → state:implementing`, real Host exclusive writer identity/credential isolation, installed DomainHarness K Permit, external Agent→PR/Review/CI, or two real Builder effects. Their explicit negative markers remain until local Host integration and authority audit.
