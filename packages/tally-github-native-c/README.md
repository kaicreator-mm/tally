# Tally v2 T03b — native GitHub ADS v5 read-only transport (R1 repair)

ADS **formal wire**: first-line `<!-- ads:github -->`, exactly one fenced `yaml` mapping with `schema/kind/data`, optional human Markdown. Reader uses mature `yaml@2.8.1` strict parse and rejects duplicate keys, anchors, aliases, tags and invalid schema via the pinned Ajv schema. Bare JSON is NOT a published report. `data_digest` is **lowercase SHA256(RFC8785_JCS(validated data))**, with no prefix and no envelope fields. This exact digest is solely derived from provider-retrieved YAML.

**Publisher provenance:** the trusted Host supplies `publisherBindings: { [namespace]: string[] // allowed GitHub transport logins }` at the native read boundary. Every candidate must originate from one of those provider-attested logins and match its own `publisher_namespace`. Unknown login comments do not become reports or poison an entire Issue; a missing allowlist yields UNKNOWN. This mapping authenticates the GitHub *transport account*, **not** the logical builder/reviewer or any approved Task Claim. Source `expectedSourceSha` must actually exist in the repository, but that alone doesn't prove branch-tip/Claim/Release currentness.

All source observations retain `authorized=false/taskPass=false/releasePass=false`. Octokit `issues.get`, `repos.getCommit`, complete `listComments` pagination are read-only. Exact source SHA, native comment ID, link/Issue, edit times and schema are checked. Partial/403/404/corrections produce UNKNOWN or PARTIAL. Real GitHub REST provider-token **read-only smoke PASS** in Node24 Actions; no conformant v5 publication exists on the smoke Issue and no authenticated publisher/Claim/Task acceptance was exercised. Selected DH Capability and approval gates remain separately owned. No special HTTP/TLS stack or private task-meta integration.

**ADS canonical wire:** Reports use exactly one first-line `<!-- ads:github -->` marker and a fenced `yaml` mapping with exactly `schema/kind/data`; the parser supports LF, CRLF/CR and blank lines between marker/fence. Unmarked JSON is discussion, not a report. The strict YAML loader refuses duplicate keys/aliases/anchors/tags and bad schema; a misplaced canonical marker from a bound publisher is a report anomaly, never silently ignored as discussion (including REVOKE). The digest is **lowercase SHA256(JCS(envelope.data))**, not the envelope and no ad-hoc prefix. External comments/fields do not confer Claim or engineering authority. Transport account login is bound to `publisher_namespace` by Host-supplied configuration, not by the body itself. `publication.classification` remains a data field, not independent clearance evidence.
