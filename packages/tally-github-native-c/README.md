# Tally v2 T03b — real native GitHub read-only C

Owner [#111](https://github.com/kaicreator-mm/tally/issues/111), parent #106. This package connects merged T01 report-projection + T03a exact ADS v4.18 schema validator to **mature Octokit REST** native Issue comment pagination and independently recomputed **RFC8785 JCS SHA256** (`canonicalize@5.1.0`). No private task-meta access, GitHub mutation, K admission, Release authority or homemade HTTP/TLS/retry engine.

**Semantics:** `readGitHubIssueReports({token,owner,repo,issueNumber,expectedSourceSha})` performs REST `issues.get`, `repos.getCommit` for pinned immutable Git source and **ALL pages** `issues.listComments`. Native Issue/commit match, comment ID/URL, GitHub update timestamp, ADS subject repository+Issue+source SHA, publication classification and the exact validator must all pass before forwarding a derived observation to T01. Missing page/403/404/unsupported dialect/partial scan/edited comments → UNKNOWN/PARTIAL, never CURRENT. A correction (REVOKE/REDACT/DISPUTE) blocks aggregate CURRENT pending later T03c reconciliation.

**Deliberate minimal on-wire rule:** Only comments whose entire body is raw RFC8785 canonical `ads/github/v5` JSON are recognized as reports. We intentionally reject pretty-printed or fenced reports rather than use an ambiguous duplicate-key JSON parse. If the real publisher uses another text wrapper, introduce an independently reviewed transport extraction in a separate delta rather than silently weakening this boundary. Ordinary unrelated discussions are skipped. The immutable source SHA is **caller pinned and provider existence checked**, not claimed to be the live branch tip or an accepted Task Claim. `publication.classification` is checked as a data field, **not independent clearance proof**.

**Current qualification:** CI Node24 synthetic GitHub pagination fixtures cover incomplete/edited/403/404/invalid sources/duplicate keys/corrections. Runtime authenticated private-repository GitHub E2E remains `NOT_RUN` without a legitimately scoped external token; tests must not print a token. No token → `GITHUB_PROVIDER_TOKEN_UNAVAILABLE`. Every return is `authorized=false/taskPass=false/releasePass=false`.

For rollout, the user-provided token is restricted to read-only Issue+commit access; Client is scoped per real project, never placed in the Builder subprocess or in GitHub issue comments. A selected Capability wrapper under sealed DomainHarness K is a separate integration concern: **this package is not an independently registered K/C yet**. Legacy Go CI remains explicitly FAIL/BASELINE_PREEXISTING. No early main merge.

Version-stage dependency P2: install uses exact direct package versions but lacks checked-in transitive lock; add a clean `package-lock.json` and `npm ci` when promoting to selected App/Release. Do not treat source CI as a reproducible packaged build or live token authorization test.
